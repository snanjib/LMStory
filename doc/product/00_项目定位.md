# LMStory 项目定位

> 本文是 LMStory 的项目定位与能力边界说明：README（中英）、贡献者文档与其他对外表述都应与本文保持一致，避免各处讲成不同的产品。
> 本文不写技术架构；技术事实以代码与 `doc/README.md` 文档地图为准。当本文与代码现实冲突时，先修代码事实再修本文（判定顺序见 `doc/README.md` 权威顺序）。

## 1. LMStory 是什么

**LMStory 是一个世界叙事引擎。**

不是情感陪伴，不为创作小说，也不只是角色扮演——LMStory 是一个由你推进、由 AI 回应、在经历中持续成形的互动世界。

- 你不必先写好角色卡、世界书或剧情大纲，从一句话就可以开始。
- 你推进事件，AI 回应世界；相遇的人、做出的选择、发生过的改变，都会沉淀为这个世界的知识、关系与历史。
- 后续发展继承已经形成的世界：一个临时命名的港口、一段结下的友谊、一条被打破的规则，都会在之后的回合里持续起作用。
- 世界可以从零开始，也可以从导入的角色卡/世界书出发——**它们是种子，不是门票**。

一句话节奏：**你推进，AI 回应，世界生长。**

## 2. LMStory 不是什么

| 产品形态 | 核心对象 | 主要目标 | LMStory 与它的区别 |
|---|---|---|---|
| 情感陪伴产品 | 一个预设角色 | 与角色建立持续关系 | LMStory 的核心对象是**世界**而非某个角色；角色是世界的一部分，会因经历改变关系与立场 |
| AI 酒馆/角色扮演前端 | 配置好的角色与世界 | 扮演预设场景 | LMStory 不要求先完成配置；预设是可选种子。**尊重酒馆生态，未来持续兼容其资产格式**，竞争的是"配置之后世界能否自己生长" |
| 小说生成器/写作助手 | 大纲与章节 | 生产一份故事文本 | LMStory 重要的是**探索的过程**；可以不设大纲，发展由用户推进。导出小说是旅程的记录与纪念（规划中），不是主要目的 |

## 3. 核心体验公式

```text
用户推进
   ↓
AI 回应世界
   ↓
事实、关系与经历被沉淀
   ↓
后续发展继承已经形成的世界
```

三句话概括：

- **角色卡和世界书是种子，不是门票。**
- **记忆不是聊天记录，而是世界的过去。**
- **小说不是目标，而是旅程留下的纪念。**

一段对比：

> 不是围绕一个角色陪聊，也不是让 AI 替你完成一本小说。你是在亲自探索一个还没有被写完的世界。

## 4. 用户、AI、世界三者关系

- **用户 = 推进者与探索者。** 用户决定事件往哪走、给什么命名、与谁结盟或交恶；世界因用户的推进而具体化。用户不是配置员，也不必是作者。
- **AI = 回应者与世界运转的执行者。** AI 不替用户写完故事，不主导大纲；它负责让世界对用户的行动给出合理回应——NPC 有记忆与立场，事件有后果，既成事实不被无故遗忘。在导演模式中，AI 还是幕后执行者：按项目规则运转世界，把正文作为唯一成果产出。
- **世界 = 核心对象与积累的载体。** 世界的知识不是预先写完的说明书，而是"被写下的设定 + 亲自发生过的历史"的总和。用户在意的是"这个世界因为我经历过的事情，成为现在的样子"。

关键纠偏：卖点**不是"世界记得我"**（那偏情感陪伴），而是**"你构造的世界观是积累的"**——强调因果、历史与世界演化。

## 5. 错误定位与慎用表述

- ❌ "AI 记忆力好"/"记得发生过什么"作为顶层卖点——记忆是机制不是产品（低层级表述，仅作机制解释）。
- ❌ "世界记得你"——偏情感陪伴，违背第 4 节纠偏。
- ❌ "另一个 AI 聊天客户端"/"Chatbox 替代品"——品类错误，内核深度表达不出来。
- ❌ "长期记忆叙事引擎"类技术性口号——描述技术机制，不描述用户获得什么（工程文档内可用）。注意区分：**"世界叙事引擎"是品类身份词，对外可用**（见第 1 节）。
- ❌ 贬低 SillyTavern/RisuAI 等生态或其创作者社区的任何措辞。
- ❌ 把 Session 机械改名为 World——在 World 一级领域对象存在之前（见第 7 节），UI/文档不得伪装这一模型。
- ⚠️ 单独使用"世界观"一词有歧义，对外优先用"世界"/"世界设定"。

## 6. 当前能力与未来方向的分界（2026-10-03 基线）

> 对外声明能力时以本节为准；任何"规划中"能力都必须显式标注，不得让读者误以为已交付。本节随版本演进同步更新。

### 已实现

- **三种产品模式**：对话模式（`chat`）、故事模式（`intermediate`，六步管线：生成→提取→检索→…→固化，记忆自动沉淀；入口默认隐藏，可在 设置 → 故事模式设置 开启）、**导演模式**（`advanced`，产品名"导演模式"，默认开启、可在设置关闭——AI 作为幕后执行者按"项目规则"运转世界，具备过程可观测、请示/审批、监督模式（未设置时默认不启用；审批可拒绝并附工作指导留言）、事件日志与重启恢复等能力）。
- **故事会话创作与阅读工具**（故事模式）：重生成/编辑重发不再覆盖旧稿——旧版自动存为变体，可查看、复制、切换或删除，切换即改变后续走向；生成中断或手动停止不丢正文——未完成稿件保留显示且可复制，可「以此收稿」或「续写」，失败轮也可直接发送新消息（自动清理失败残留）；会话稿件可导出 Markdown（全部轮次/仅最新轮 × 纯正文/含生成过程）；会话内搜索（命中跳转与高亮）；离开会话记住阅读位置，再次进入自动恢复。
- **外观体系 v2**（设置 → 通用 → 外观）：三根轴自由组合——主题结构（经典/琉璃/印刻/漫游）× 配色族（经典/波尔多）× 主题模式（深色/浅色/跟随系统），外加 12-22 档字体大小（三模式消息正文统一缩放）。结构由界面职责接口与各结构实现装配；无障碍面（减弱动态、键盘焦点环、纯图标可读名）与大屏版心（宽窗口内容列收窄居中、叙事阅读列限宽）、桌面快捷键（Ctrl+N/Ctrl+Shift+N/Ctrl+,/Ctrl+K/Ctrl+F）随外观体系单源管理。
- **配置双模式**（设置 → 通用 →「配置显示模式」，默认简单）：全部配置选项区分泛用户模式（简单）与技术用户模式（进阶，类开发者选项）。简单模式只保留供应商、选模型、模板/资源、剧情节奏等白话高频项与思考预算成本旋钮、向量化（嵌入）模型；进阶模式显示全部配置。切换即时生效；过滤只动展示层，被隐藏项的已有值继续生效。
- **新用户配置引导**：三模式会话页在模型未配置时显示引导横幅（直达对应设置，配置完成自动消失）；简单模式下含进阶配置的设置页与会话面板尾部显示「更多配置」指路行。
- **会话输入草稿跨重启保留**：未发送的文字随会话持久化（切换会话、退出应用、重启后自动恢复；发送后清空；随备份导出）。
- **世界书/角色卡资源库**（设置页入口）：导入 SillyTavern 兼容 PNG 角色卡（V1/V2 `chara` / V3 `ccv3`，V3 优先）、纯 JSON 角色卡（V2/V3）、世界书 JSON（顶层 `entries`）；导入后作为"种子"应用到会话，经投影进入世界运转，与记忆层（事实/经历）协同。导入内容为**属性级只读基线**：永不改写，AI 剧情演变以独立"演变"条目与基线并存（记忆库有基线/演变行级标识）。
- **AI 建卡/建书**（资源库页入口）：与 agent 对话式共创角色卡与世界书——你说想法，AI 逐字段起草并按需改稿，草稿确认后落库；也可对既有资源发起 AI 编辑（改稿保留未知字段，覆盖前可另存）。
- **数据维护与内容查看**：自动/手动备份与「从备份恢复」入口（备份与覆盖前快照双分区；导入全程有进度反馈，「打开方式」进入的备份 JSON 自动分流到数据导入；备份目录在应用私有存储、文件管理器看不到属正常现象有醒目提示）、导出可选是否包含世界资产、诊断页（日志/失败历史，开发者暗门需版本行连点解锁）；资源库内置内容查看器（角色卡富字段图形化展示——身份/场景/开场白/替代开场白/标签等，长文折叠、大书限流、不出原始 JSON）；记忆库归档/恢复通路（实体与经历双面）。
- **本地优先**：数据（会话、记忆、事实、事件日志）存于本地 SQLite；自带 API 接入多家供应商模板（OpenAI/DeepSeek/OpenRouter/Anthropic Claude/Google Gemini/NVIDIA NIM/Agnes AI），三种协议（OpenAI 兼容/Anthropic/Gemini）。
- **界面语言**（zh-CN / en-US 双语，设置可切换即时生效并保留选择；「跟随系统」暂未开放）。

## 7. 远期方向：World 一级对象（仅讨论，未立项）

长期理想模型：一个世界容纳初始种子（角色卡/世界书）、作者设定、已形成的世界事实、历史经历、角色与关系、多条旅程/时间线。届时"开启新世界""世界档案""旅程与时间线"等语言才有真实模型支撑。**在此之前不改名、不伪装**——领域模型升级与世界书深化一起讨论。

## 8. 品牌人格与设计原则（设计工作流参考）

> 本节承载**设计侧**的产品级约束：品牌人格、目标设备、设计原则、反例、可访问性口径。
> 设计工作流以本节为准。

### 8.1 品牌人格

**沉浸 · 匠心 · 有生命感**（Immersive · Crafted · Alive）

- **沉浸**：界面应当像「走进一个故事」——有氛围、专注、没有 UI 噪音。暗色是会呼吸的空间，亮色像清晨的稿纸。
- **匠心**：每个细节都是有意的——为阅读调校的排版、造出节奏的间距、像实物一样有重量的过渡。没有什么是默认值。
- **有生命感**：界面会回应。流式文本轻轻脉动；生成内容与记忆上下文保持可见的关联。应用像在听。

### 8.2 视觉身份（现行口径）

现行视觉身份是 **双轴外观体系**（v0.4.0）：**结构轴 × 配色轴**，八组合全部正式
支持，两条轴**不得合并**。

| 轴 | 取值（显示名 / id） | 决定什么 |
|---|---|---|
| 结构轴 | 经典 / 琉璃 / 印刻 / 漫游（`classic` / `glass` / `brutal` / `wonder`） | 界面长什么样 |
| 配色轴 | 经典 / 波尔多（`classic` / `bordeaux`） | 用什么配色 |
| 明暗档 | 日 / 夜 | 每个组合各有两档 |

- 装配入口：`ThemeCatalog.assemble`。
- 长期默认组合：**经典结构 + 经典配色**（Classic）。
- **已退役，不得再作现行口径**：早期 indigo「Daylight/Twilight」工具感皮肤、
  amber「夜航」主题；以及**未落地**的 Stagecraft（剧场）/ Ink（墨白）方案——其
  「台上/台下」语义在 v0.4.0 外观体系 v2 中被评估吸收，但方案
  本身不是现行视觉身份。「晚场/日场」「墨白」等一律视为**曾用名**。
- **平台口径以 `README.md` 的平台表为准**（Android 为主要目标平台；iOS / macOS /
  Windows / Linux 平台工程已就绪、未做发布验证）。本节不重复维护平台口径，避免
  又造一处会漂移的副本。

### 8.3 设计原则

1. **叙事优先，界面其次**：每一个界面决策都要回答「这是否帮用户留在故事里」。不服务沉浸的元素就不存在。
2. **熟悉的惯性，而非发明的可供性**：用成熟范式（列表、输入、导航），但用品牌自己的语气去塑造它们。不要为风味重造标准控件；为身份重造它的外观。
3. **克制的氛围**：最深的沉浸来自缺席的东西。最少的外壳、充裕的留白、会呼吸的排版。装饰是被赢得的，不是默认的。
4. **双世界一致性**：明与暗是同一栋房子里的两个房间——同样的家具，不同的光。组件、间距、层级完全一致，只有颜色值变化。
5. **记忆即连续性**：事实记忆与过往经历的存在意义是让故事保持连贯。呈现给用户时应像一本故事圣经，而不是一份数据库导出。

### 8.4 反例（明确不要长成的样子）

- **SaaS 暗色模板**：不要霓虹压深蓝、不要发光描边、不要「监控大屏」审美。这是故事工具，不是监控台。
- **游戏化 / 过度装饰**：不要经验条、不要成就徽章、不要装饰性粒子。叙事本身就是游戏，界面服务于它。
- **Material 默认外观**：不要未经刻意重塑的默认 Material 组件——不要默认 elevation 阴影、不要通用水波纹、不要 Material 配色方案。视觉身份必须可辨识。
- **通用 AI 聊天克隆**：不能长得像 ChatGPT 套壳。布局、排版、颜色与交互模式应当属于叙事，而不是客服。

### 8.5 可访问性口径

- WCAG 2.1 AA：正文对比度 4.5:1、大字 3:1。
- 屏幕阅读器语义标注。
- 所有动效都提供「减弱动态」替代（遵从系统设置）。
- 触控目标 ≥ 44×44dp。
- 支持动态字号缩放。
- **颜色永不作为状态的唯一指示**——始终与图标、文字或图案配对。
