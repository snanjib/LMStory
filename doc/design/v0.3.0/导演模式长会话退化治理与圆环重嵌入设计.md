# 导演模式长会话退化治理与上下文圆环重嵌入设计

- 状态：已实施（2026-09-02，S1-S6 全部交付，全量测试绿；思考深度问题经评审不在本任务范围）
- 调研依据：2026-09-01 四路调研（LMStory agent loop / skill 与 lint / 圆环 UI / opencode+deepseek-harness 对照），根因均已在源码逐条证实
- 关联文档：`导演模式上下文用量指示设计.md`（本文件 S6 修改其 §4.1 落位）、`导演模式正文交付契约设计.md`（六锚点，S2/S5 会触及锚点回归测试）

## 1. 症状与根因

用户报告三个退化（第四点为 UI 问题）：

1. **工具主动性衰减**：前几轮积极查/更新记忆，几十轮后基本"想一下就直写正文"。
2. **skill 遗忘**：几十轮后强模型输出无标点长段；去AI味越来越差，写作方法 skill 偶尔还会查。
3. **圆环突兀**：上下文用量环形指示器不对齐、不与其他元素同列、无嵌入感。

根因（详见调研记录，此处只留结论与锚点）：

- **R1 跨轮历史零工具痕迹**：persist 只落 1 条 user + 1 条 assistant 正文（`advanced_chat_controller_persist.dart`），下一轮 surface 重建只有 user/assistant 两类消息（`director_round_runner.dart` 历史映射）。模型看到的 in-context 示范永远是"输入→成品"，越长"直写"先验越强。**这是与"几十轮后衰减"时间特征最吻合的结构。**
- **R2 尾部 recency 位被"催写"独占**：每轮固定注入只有节奏指令（`agent_pacing.dart`），penReminder 是文风+催交稿；工具指引只活在位置 0 冻结前缀（`agent_system_prompt.dart` 工具索引），长会话 lost-in-the-middle。08-18 自主性重构刻意去流程化后无兜底。
- **R3 penReminder 双门槛失效**：触发条件 `steps >= 3 && !finishAttempted`（`agent_runner.dart` ~:384）——模型成熟后 1-2 步直接 finish_round，**尾部文风重述整轮不触发**。这是"越到后面越差"的直接机制。
- **R4 lint 对无标点长段全盲**：sentenceVariance 按 `[。！？]` 分句需 ≥6 句才判、paragraphLength 需 >400 字，无标点长段两条都不命中（`agent_style_lint.dart`）；且每轮只定向重写一次。
- **R5 闸门教绕过**：记忆闸首次拦截后明示"直接再次 finish_round 放行"且每轮只拦一次，忽略工具的代价≈0（`agent_session_tools.dart` gate B）。
- **R6 Anthropic 上提架空尾部注入**：适配器把所有 `role:"system"` 抽到顶层 system 字段（`anthropic_adapter.dart` `_extractSystemMessage`），轮尾 system 消息在该协议下失去 recency 位。
- **R7 圆环挂载违反布局公约**：独立一行 `Align(centerRight)` 悬在 InputToolbar 上方（`advanced_chat_page.dart` ~:384），外层 Container 无 padding 致其贴屏幕右缘 0px（打破全输入区 12px 内容边距）；裸 CustomPaint 无 chip 外衣；常态色 faint 在深底上近乎隐形。

## 2. 设计原则

1. **recency 在位**：每轮都要出现在离生成点最近的位置的内容（工作契约、文风铁律），不许只依赖位置 0。
2. **示范在历史**：行为先验靠历史塑造，跨轮保留"这是一个会查会记的 agent"的痕迹。
3. **机械检测替代模型自觉**：模型无法自省遗忘，漂移必须由 harness 用确定性信号检测并明确告知。
4. **append-only、缓存友好**：不改写已生成的历史消息；新增内容只追加在尾部或装配期合成。
5. **非流程性措辞**：所有新注入只提醒"能力在场、自问自查"，不规定步骤顺序——不推翻 08-18 自主性重构（原语而非固定流程）。
6. **尊重既有决策**：圆环保持"纯环无文字（点开才有文字）"、满刻度=压缩触发线；压缩摘要文风不动；闸门豁免机制保留但可升级；maxTokens 共享思考预算与 reasoning 参数（问题 2）不动。

## 3. 方案

### S1 跨轮工作痕迹（对 R1；支撑 S4/S5 的数据口径）

**目标**：恢复历史中的 agent 行为示范。

**设计**：装配期从 `StoryRoundArtifacts` 合成，**零 schema 改动、不落 chat_messages、不进压缩输入**：

- 数据源（均已持久化）：`agentSteps[].toolName/title/status`、`factsChanges.length`、`eventSummary`、`storyAnchor` 是否更新、`read_skill` 的技能名（从 argsPreview 提取）。
- 在 `director_round_runner` 的 surface 组装处，为最近 `kWorkTraceWindow = 8` 轮各生成一行 trace，作为 `AgentMessage.user` 合成消息插在对应 assistant 正文消息之后：
  `〈round-work n=12〉查记忆×2 · 事实+3 · 读技能:战斗场面 · 锚点更新〈/round-work〉`
  无工具轮诚实标注：`〈round-work n=13〉本轮无工具调用，直写正文〈/round-work〉`（不美化、不伪造）。
- trace 由装配期即时合成，老会话无 artifacts 时按缺失回退（跳过该轮 trace）。

**不变量**：冻结前缀/core blocks 与缓存断点不受影响（trace 全在历史区）；压缩读库内历史，trace 不入库、天然不参与摘要。

**风险与备选**：assistant 后紧跟 trace（user 角色）会产生连续 user 消息。OpenAI 兼容端无问题；Anthropic 端需回归验证 messages 转换路径，若连续 user 被拒则由适配器转换层合并连续 user（不改上提逻辑本身）。

**测试**：trace 文案生成（有/无工具、旧数据缺失）、surface 顺序与角色、窗口截断、缓存前缀不变。

### S2 每轮尾部契约+铁律注入（对 R2/R3/R6）

**目标**：每轮 recency 位恒定存在"一行工作契约 + 一行文风铁律"，且不被 Anthropic 上提。

**设计**：

- 在 `surfaceTailMessages`（`agent_pacing.dart`）每轮注入的尾部消息中，于节奏指令之外追加两行：
  - 工作契约（非流程性）：如"记忆/事实/锚点/技能工具本轮随时可用。提交前自问：该查的查了吗？该记的记了吗？"
  - 文风铁律：复用 `kDefaultPenReminderText` 的铁律句（禁破折号/虚假对仗/三连排比、句长错落、允许毛边）压缩为一行。
- **角色规范（本设计的关键约定）**：harness 生成的轮尾内容（能力提示、节奏指令、契约铁律）统一改为 `role=user` 合成消息，内容用固定标记包裹（如 `〈workbench-reminder〉…〈/workbench-reminder〉`），从根上绕开 R6——**不修改 anthropic_adapter 本体**。
- penReminder 保留现状（≥3 步长轮的二次兜底），条件不动；S2 覆盖的是 1-2 步直写的快轮。

**注意**：本项会触及六锚点逐字节回归测试（尾部注入文案/角色变化），锚点测试须同步更新；改动范围控制在 `agent_pacing.dart`、`agent_runner.dart` 注入点与其测试。

**测试**：锚点回归更新、Anthropic 端 user 消息原位不再上提、OpenAI 兼容端行为不回退。

### S3 lint 补"无标点长段"检测（对 R4）

**设计**：

- `agent_style_lint.dart` 新增检查 `runNoPunctuation`：单段内连续 ≥ `kNoPunctuationRunLimit = 60` 字符（命名常量，可调）未出现任何分隔符（中英文标点与空白：`，。！？；：、""''（）…—·,.!?;:()` 及空白）即命中，报告违规位置。
- 走既有 FinishRoundTool 定向重写一次路径（`agent_session_tools.dart` ~:1517），`buildFeedback()` 补对应条目文案。

**测试**：无标点长段样本命中、正常短段/对话体省略号不误报、与既有 7 类检查共存。

### S4 风格漂移监测器（对"模型不知道自己忘了 skill"）

**目标**：由 harness 检测文风劣化并明确告知模型重读规范。

**设计**：

- **留痕**：FinishRoundTool 完成 lint 后，把违规数写入本轮 `AgentWorkSummary` 新增可选字段 `styleLintHits`（该对象是 artifacts JSON blob 内的手写序列化类，加可选字段无 drift 变更；若实现中发现其为代码生成模型则跑 build_runner）。旧数据缺字段 = null，不参与统计。
- **判定**：轮开始装配尾部消息时读最近 5 轮 artifacts：若 ≥2 轮 `styleLintHits` 非零，且这些轮内未出现过 `read_skill: deai-flavor`（直接读最近轮 `agentSteps`，S1 已保证该数据可用），则本轮尾部消息追加一句：
  "近几轮正文多次命中写作规范红线（共 N 处）。动笔前先用 read_skill 读取 deai-flavor，按其逐条自查。"
- 触发的注入是**一次性告知**（当轮生效），持续劣化则持续触发——即"记住"由 harness 负责，不由模型负责。

**测试**：滚动窗口判定、读 skill 后抑制、老会话无字段回退。

### S5 零工具轮升级闸门（对 R5）

**目标**：连续多轮完全不用记忆类工具时，把"免费豁免"升级为"说明原因才能豁免"。

**设计**：

- **计数口径**：轮开始时从最近 artifacts 统计连续轮数——连续 N 轮（`kZeroToolEscalateAfter = 3`，命名常量）内 `update_facts` 与 `record_event_memory` 均未调用且 `eventSummary == null`。本轮调用任一记忆类工具即清零。
- **升级**：升级态下 gate B 的二次提交不再直接放行，要求模型在 `finish_round` 新增的**可选**参数 `noEventReason`（string）中说明原因后再次提交；reason 仅入 L2 审计。非升级态保持现状（一次豁免放行），行为不回退。
- finish_round JSON schema 增加可选字段（`agent_tool` 定义处）；description 锚点回归测试同步更新。

**测试**：连续计数与清零、升级触发/未触发两态、reason 校验、非升级态回归。

### S6 上下文圆环重嵌入（对 R7）

**目标**：圆环进入工具栏行，获得与同级 chip 一致的着装与对齐。**既定决策不变**：纯环无文字、点开详情、满刻度=压缩触发线。

**设计**：

- `InputToolbar`（`core/theme/intermediate/components/input_toolbar.dart`，**故事模式共用**）加通用尾部插槽 `trailing`（`Widget?`）：Row 内 `Spacer()` + trailing，故事模式不传则零变化。
- 圆环重做为 chip 形态（改造 `DirectorContextRing` 或包一层 `DirectorContextChip`）：
  - 外层与 `_ToolbarButton` 同语言：InkWell(rSm 圆角) + AnimatedContainer，0.5px `colors.divider` 描边，hover `primaryDim`，padding h8/v4；
  - 内部环缩至 14–16px，三态语义保留（常态色由 faint 提升为 muted 系保证对比；≥70% warning、≥100% error 不变）；
  - 命中区 ≥32px，Tooltip 补充语义；
  - 默认不加文字（既定决策）。
- 挂载：`advanced_chat_page.dart` 两处（正常态 ~:384、失败态 ~:476）删除 `Align` 独行，改为 `InputToolbar(trailing: …)`；12px 边距由 toolbar 自带 padding 保证。
- 详情 sheet（`DirectorContextDetailSheet`）：补 handle bar 与关闭按钮，对齐 simple 主题 sheet / `director_session_settings_sheet` 先例；"立即压缩"与流式刷新逻辑不动。

**实施硬约束**：前端部分按夜航视觉语言执行（见 `doc/design/06B_中级模式视觉规范.md`）。

**测试**：widget 测试（挂载位置、右对齐 12px、两分支均有、故事模式 toolbar 不受影响）、环形 painter 既有测试迁移。

## 4. 实施顺序与验证

| 阶段 | 内容 | 提交粒度 |
|---|---|---|
| A（快赢） | S6 圆环重嵌入 → S3 lint 检测 → S2 尾部契约铁律 | 每项独立 commit |
| B（结构） | S1 工作痕迹 → S4 漂移监测 → S5 升级闸门 | 每项独立 commit |

每批完成后：`dart format` 触碰文件、`flutter analyze` 零新增告警、相关 focused 测试 + 全量 `flutter test`、`git diff --check`。涉及序列化模型改动跑 `dart run build_runner build --delete-conflicting-outputs`（预期 S1-S6 均不需要 drift 变更）。

交付后同步：用户可见文案走 slang（预计仅 S6 tooltip）。

## 5. 明确不做

- **问题 2（思考深度忽深忽浅）**：不在本任务范围内；reasoningEffort 默认值/预算映射另立任务。
- maxTokens 与推理共享预算：此前已定暂不动。
- Anthropic adapter 上提逻辑本体：通过 S2 的装配期角色约定绕开，适配器不改。
- 历史会话数据迁移：旧轮无 trace / 无 styleLintHits，按缺失回退，不回填。
- 压缩摘要文风（列表式）：维持现状。
