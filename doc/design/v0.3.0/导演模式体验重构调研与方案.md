## 1. 任务与边界

用户对已实施的导演模式（纠偏后版本）提出两个核心不满与一个开放问题：

1. **前端**：界面像"传统数据处理系统"，要求以 PM/UI 视角批评并给出重构方案。
2. **Harness/提示词**：现状只是"把故事模式流程口述一遍让 agent 做"，缺乏作为叙事引擎/世界驱动引擎的深度设计；要吸收 opencode、deepagents 等方案，并结合故事模式多年提示词调优的踩坑记录。
3. **开放问题**：编程 harness 的会话短（一个会话=一个 bug/功能），导演模式的会话长（一个会话=一部剧情，数百轮）。像去AI味这种 skill 不可能每轮全文注入，上下文变长后模型"忘了 skill 也不会自知"怎么办？并要求沿此发散找出同类潜在问题。

**边界**：本文档只做调研与方案，不实施。分歧与决策用问题卡片（§9）与用户沟通。

### 2.2 当前系统提示词（用户不满的样本，逐字）

`agent_system_prompt.dart` 冻结前缀三段：①项目规则（用户 `systemPromptOverride` 或两句兜底）→ ②编辑部工作法 → ③工具名顿号列表+一句话。②全文（`kAgentWorkRules`）：

> 你是一位自主工作的总编辑（GM）。每一轮你的工作循环是：理解导演意图 → 按需检索记忆 → 核对事实 → 撰写正文 → 记录新事实 → 提交本轮。工作守则：1.**检索优先**… 2.**先查后写**… 3.**任务完成即停**… 4.**工具调用之间保持简短**… 5.**不虚报**… 6.**每轮一次关键事件**… 7.**方向不明问导演**… 8.**写作规范**…

问题诊断：这是**流程复述**（"把故事模式六步翻译成祈使句"），不是**决策原则**。缺：何时必须检索的判定条件、执笔步的定义（哪一步输出正文、正文即终稿）、质量闸门（写完自检什么）、文风约束（只剩"延续既有文风"六个字——故事模式打磨出的去AI味资产完全没进来）。另有硬伤：第 7 条指向一个恒返回 null 的工具。

### 2.3 当前 UI 构成与观感

专属 UI 仅三块：`director_chat_body.dart`（354 行，时间线：用户气泡→工具卡序列→衬线正文块+思考折叠+呼吸光标）、`director_tool_card.dart`（263 行）、设置 sheet。外壳（AppBar/输入/失败条/停止）复用故事模式。

"数据处理系统"观感的根源——**工具卡是 CLI 语言，正文是文学语言，同一屏幕两种方言**：等宽字体工具名（`search_story`）、等宽 glyph（✱→◈%⚙）、副标题直接拼原始参数串（`检索记忆 · {query: 古碑} · 1.2s`，`director_tool_card.dart:147-159`）、展开输出等宽灰字、耗时秒数。故事模式打磨出的"衬线正文+夜航琥珀"阅读面之上，浮着一排终端日志。次要问题：每轮所有工具卡常驻平铺（过程是"可选审计抽屉"却默认全展示）；空态只有一行 hint；纯思考阶段无心跳（思考默认折叠，屏幕近似静止）。

## 3. 调研摘要

### 3.1 前端（opencode 源码 + 15 个产品）

**opencode（<https://github.com/sst/opencode>，直接读源码）**——最相关的机制：
- **Part 模型**：消息=part 流（text/reasoning/tool/…），每 part 独立状态机与独立结束时间；中断清理协议保证"取消后无悬挂、半截文本保留为合法部分"。
- **工具行三态**（pending `~ Writing…` / running spinner / complete muted 摘要）+ **颜色语义表**：warning=待确认、error=失败、muted=完成、删除线=被拒；失败行点击展开错误。**单行操作紧凑成流、块级内容独占段落**（`alwaysSeparate`）。
- **Thinking 默认折叠成单行** `+ Thought: 标题 · 4s`，设计注释明言"**layout never shifts**"——布局零跳动压倒信息可见性。
- **折叠策略**：输出超 10 行折叠、宽度感知字符预算；会话级开关"隐藏所有成功工具只留失败与进行中"。
- **MAX_STEPS 软着陆**：步数上限不硬切，注入最后通牒提示（工具停用、只准文本收尾）——`core/src/session/runner/max-steps.ts`。
- 压缩三件套：结构化锚定模板（Objective/Work State/Next Move…）+ 尾部 15k 原文保留 + 旧工具输出打标清除。

**业界共识**（harness UI：Claude Code/Codex/Gemini CLI/Cursor/Cline；chat：ChatGPT/Chatbox/Claude/Poe；叙事工具：Sudowrite/NovelAI/SillyTavern/AI Dungeon/彩云小梦）：
1. **控制流与成品流分离**（ChatGPT Canvas、Claude Artifacts、NovelAI 阅读优先单栏）——LMStory 的"正文主角/过程幕后"与此完全同向。
2. **步骤翻译成人话动词短语**（Copilot "reading X…"）；**任何时刻必须有心跳**（Copilot 纯推理无显示被当 bug 报告）。
3. **骨架屏优于转圈**（NN/g：2-10s 等待用版式骨架）；粘性"当前动作"条（Gemini CLI sticky headers）。
4. **动画隔离**（Claude Code OffscreenFreeze→Flutter 对应 RepaintBoundary）；流式 Markdown"容错解析→完成后严格重排"。
5. **停止=合法半成品**（ChatGPT Stop 状态不一致的反例）；**重生成=并行备选而非覆盖**（SillyTavern swipes/彩云小梦三条走向/NovelAI 版本树三方共识）；**回滚语义必须显式**（Cursor 恢复 vs 重跑混淆的反例）。
6. **生成中可排队批注**（Cursor ⌥+Enter）；**计划清单实时可见可勾选**（Claude Code Todo/Cline）；**章末 Recap 蒸馏卡**（Cline checkpoint summaries）。
7. **世界状态面板收在后台**（AI Dungeon Gameplay 标签）；SillyTavern 设置密度过载是反面教材。
8. 字体/行距/主题可定制是叙事产品标配（NovelAI 18 套主题+阅读设置）；来源着色（初稿/已改/定稿）用极低饱和实现"需要时能分辨"。

### 3.2 Agent harness（Anthropic/OpenAI/deepagents/Letta/叙事研究）

- **Anthropic**：agent=LLM 用工具在循环里根据环境反馈行动；**"找最简单的方案，必要时才加 agent 性"**；工具设计四大原则——面向意图合并多步操作、描述写给"新同事"看、返回只留高信号字段（UUID 解析成名字可显著降幻觉）、错误必须可行动；**示例胜过规则**。
- **OpenAI《Harness engineering》(2026-08)**："给 agent 一张地图而非一千页手册"；手册会**立刻腐烂**，解法是渐进披露+机械强制（lint/CI，"错误信息里内嵌修复指引"）；"**品味一次性编码为可执行检查，然后持续机器强制**"；"运行期在上下文里够不着的东西等于不存在"。
- **deepagents**：计划工具本质是 **no-op 的上下文锚点**（对抗目标漂移，不是执行机制）；文件系统=共享外部记忆；子代理=干净上下文只回传蒸馏结果。
- **长会话退化证据**：Chroma《Context Rot》（长而"通顺"的旧上下文最伤注意力，聚焦 300 token 胜过全量 113k）；《Lost in the Middle》（U 形注意力：首尾强、中部弱）；《Drift No More》（**第 4/7 轮注入目标重述使漂移显著下降**）；Microsoft《LLMs Get Lost in Multi-Turn》（多轮碎片化平均掉 39%）。
- **Claude Code 长会话答案**：CLAUDE.md 在**每次压缩后从磁盘重注入**——规则不放进会被摘要掉的历史层，而是放在每轮重新装配的持久层；配合 prompt caching（system 层稳定前缀，读缓存仅 0.1× 价格）。
- **技能遗忘的解法谱系**（按证据强度）：① 模型外确定性强制（hooks/lint）＞ ② 持久层每轮重注入（CLAUDE.md/Skills 三级渐进披露）＞ ③ 周期性目标重述 ＞ ④ 压缩时定制保留指令 ＞ ⑤ 结构化笔记锚点 ＞ ⑥ 子代理干净上下文。
- **叙事架构**：Generative Agents（recency×importance×relevance 检索+反思回写）；Dramatron/DOC（大纲层级条件化，误差传播是已知风险）；RecurrentGPT（每段以最新长期摘要重新条件化——**短生成单元+频繁锚定**）；Hidden Door 复盘（先写后果摘要再写正文、"允许有后果的失败"、节奏失控=角色小癖好无限复读）；Intra（状态只能经 resolution 变更、按角色视角过滤事件日志）；《Lost in Stories》（**文风类错误与事实类错误不相关，局部窗口检查即可处理**——去AI味 lint 不需要远程上下文）。

## 4. 前端重构方案

### 4.1 设计原则与美学方向

- 继承夜航主题（Restrained：深蓝黑+琥珀金 ≤10%）与"正文主角"既定方向，**不换皮，换语言**：把过程的表达从"终端方言"翻译成"剧场方言"。场景句：深夜书房里读一部正在自己生长的小说，导演偶尔瞥一眼幕后工作灯。
- **Register**：product（设计服务于阅读任务），动效 150-250ms、只表达状态、reduced-motion 全覆盖（项目已有 `disableAnimations` 先例）。
- 命名体系（slang，全部走 i18n）：过程行用舞台词汇——"翻阅前情 / 回读第 N 幕 / 查证设定 / 修订设定集 / 记入大事记 / 请示导演 / 落幕"。等宽与原始参数**降级到审计层**。

### 4.2 分层信息架构（核心改动：L1/L2 分离）

| 层 | 内容 | 默认态 | 视觉 |
|---|---|---|---|
| L0 成品面 | 叙事正文 | 永远可见 | 衬线正文（现状保留） |
| L1 过程行 | 一轮一条汇总："幕后 6 步 · 翻阅前情、修订设定集… · 12s" | **收起**（一轮一行，muted，无等宽）；进行中的轮次显示实时步骤行 | 一行 caption，前置小图标（灯/笔），点击展开 L2 |
| L2 审计层 | 逐步卡片：舞台动词+宾语（`翻阅前情 ·「古碑」· 12 处命中`），展开后才是工具名/参数/原始输出/耗时（等宽） | 仅 L1 展开时可见；error 步骤例外——失败步骤直接升到 L1 常显 | 现有 `DirectorToolCard` 改造：头部去等宽名，参数翻译成人话，等宽全部下沉 |

依据：纠偏第 2 条"默认收起、一行 muted 摘要"；opencode"隐藏成功工具只留失败与进行中"；SillyTavern 反面教材（复杂度必须藏进后台）。进行中一轮：L1 显示当前动作+已完成步数（"正在翻阅前情… 3/6"），布局高度稳定（opencode thinking 单行原则），步骤变化原地更新不跳动。

### 4.3 组件规格

1. **过程汇总行 `DirectorProcessRow`**（新，替代逐卡平铺）：一轮 assistant 块上方一行；内容=舞台动词串+步数+时长（复用闲置的 `AgentWorkSummary` 与 i18n `advanced.workProcess.collapsedWorking` 键族）；点击展开 L2 步骤列表（`AnimatedSize` 禁用教训适用——用固定动画时长的显式展开，勿在流式态做自适应高度）。
2. **心跳行**：发送后首字前的等待期，输入栏上方浮一行"导演正在构思…/翻阅前情…"（随首个工具事件切换文案）+ 段落骨架（2-3 行浅色占位，NN/g 骨架屏），首字到达即替换。纯思考期不再静默。
3. **步骤卡 `DirectorToolCard` 改造**：头部=舞台动词+人话宾语（`AgentWorkStep` 增加 `humanTitle` 字段，由工具结果信封的 `title` 承载——信封里本来就有 `title`，接上即可）；副标题=命中摘要（`12 处命中`/`已记 1 件事`），**去掉 argsPreview 与耗时的默认展示**；展开层=原始工具名（等宽小字标签）、参数 JSON、输出全文（可复制）、耗时、缓存命中（`advanced.workProcess.cache` 闲置键启用）。running 态保留微光，error 用 error@0.08 底（现有）。
4. **回到最新浮标**：reverse ListView 天然贴底，用户上滚即脱离；滚动位置不在底部且正在生成时，右下浮现"↓ 最新"胶囊（故事模式若无可平移）。
5. **空态**：从一行 hint 升级为引导：开场语示例（可一键填入，如"雨夜，旧宅门被敲响第三次。"）+「项目规则」入口提示（教用户这里可以立规矩）。
7. **幕间 Recap 卡 `DirectorRecapCard`**（已定，见 §9 卡片 C）：每轮正文块之后一行极简章末行——「第 N 幕 · {叙事时间} · {一句主线进展}」，书脊形态复用压缩摘要卡（`IntermediateCompactionSummaryCard`）的观感语言：整宽、surfaceVariant、muted、无统计；点击展开锚详情（当前弧线/未兑现伏笔清单）；**无编辑入口**（锚只由 AI 经工具维护），与"正文唯一成果"的张力以此规格消解。
8. **失败条**：保留现有 FailureBar 结构；错误文案全部人话化（EAGENT 文案已可，补"步数耗尽"软着陆后的新文案，见 §5.2）。
9. **合规**：所有新文案进 slang（`dart run slang`）；对比度按 06B 硬规则（占位 muted 不用 faint）；触控目标 ≥44dp。

### 4.4 动效规格（全部表达状态，均有 reduced-motion 静态替代）

| 动效 | 规格 | 语义 |
|---|---|---|
| 步骤完成 | 标题 160ms 一次淡入加深（muted→ink） | 状态切换（现状 AnimatedContainer 保留） |
| 心跳行图标 | 800ms 呼吸（同现有流式光标节拍） | 进行中 |
| 正文完成"落幕" | 底部 1px 琥珀细线 240ms 淡入+操作行浮现 | 本轮定稿 |
| L1 展开 | 200ms ease-out-quart 高度动画 | 信息下钻 |

## 5. Harness 重构方案

### 5.1 系统提示词重写：从"流程口述"到"原则+闸门+节奏"

结构仍三段（布局铁律 `tools → system 冻结 → 历史 → 新内容` 不变，缓存断点保留），②重写为：

1. **身份与产出契约**：你是叙事引擎。你输出的叙事正文会被直接呈给读者，**没有后审环节**——落笔即终稿（吸收故事模式"删暗示字眼"教训：全文禁"草稿/初版/待审"字眼）。
2. **每轮节奏（轻协议）**：检素（可并行）→ 修订设定 → 执笔（一次成型完整正文）→ 提交。**执笔步不得调用工具**；正文只在执笔步输出。
3. **何时必须检索**（判定条件，不是口号）：出现专名（人名/地名/物件）；某角色 ≥3 轮未出场；时间/地点跳跃；用户输入涉及往事。何时可跳过：紧接上轮的连续对话且所需上下文在场记板内。
4. **质量闸门（执笔前自检三问）**：事实是否都有出处（检索结果/场记板）？是否承接了上轮最后一个画面？是否只推进"一个"关键事件？
5. **文风铁律**（常驻短表：禁破折号、禁三段式凑排比、禁"不是A而是B"、句长错落、允许毛边、具体细节代替抽象形容——从故事模式 kDefaultRolePrompt 硬约束精编，全文在 deai-flavor skill，见 §5.3）。
6. **事实记录规范**：合并保真（新值=旧值信息+新增，"侍奉三代→当了管家"反例）、importance 评"今后出场可能性"默认 2 宁低勿高、世界书只读。（这些是故事模式踩坑的直接平移。）
7. 删除现第 7 条（ask_user）——直至 UI 接线（§5.2）。

③工具索引：每工具一行"做什么+何时用+何时不用"（Anthropic ACI：描述写给新同事），替换现在的顿号名单。

### 5.3 Skill 长效机制（对开放问题的正面回答）

"长会话里 skill 被忘了怎么办"——三层防线（对应 §3.2 解法谱系 ①②③）：

1. **常驻层（缓存友好）**：把"写作必读"类 skill（目前=deai-flavor）的**精编正文（≤500 token）并入冻结 system 前缀**。因为前缀会话内冻结，逐轮命中 prompt cache，边际成本≈0.1×；且它永远不会被压缩掉、不会被上下文增长稀释——这就是 Claude Code"CLAUDE.md 压缩后重注入"的等价实现（我们的 system 本来就每轮重建，更简单）。场景类 skill（战斗/对话/悬疑/跑团）保持目录常驻+`read_skill` 按需（先接线 `loadSkillBody`）。
2. **尾部重述层**：执笔步前（harness 检测到"本轮尚未输出正文且距上次正文输出已 ≥N 步"或固定每轮一次），在消息尾部注入一条极短 system reminder："即将执笔。铁律：禁破折号/凑三连/虚假对仗；允许毛边。"（≤50 token）——利用 U 形注意力曲线的尾部强区做再锚定（《Drift No More》第 4/7 轮重述证据）。
3. **机检兜底层（确定性）**：完稿后（finish_round 提交前）跑本地 lint：禁用词表（彰显/凸显/勾勒/沉淀/磅礴/那一刻/时光荏苒…）、破折号频率、"不是A而是B"正则、句长方差过小、段落过长、开场客套（"好的/我来续写"）。违规>阈值→结果作为 tool result 反馈给模型**定向重写一次**（明确"只改标记处"）；≤阈值→只记录到 L2 审计层不改稿。文风错误与事实错误不相关、局部窗口即可查（《Lost in Stories》），lint 成本极低。"品味一次编码、机器持续强制"（OpenAI）。

配套：skill 资产头部加 `alwaysInject: true`（写作必读类）标记，加载器识别；去AI味 skill 的正文按"常驻精编版+完整版（read_skill 可得）"两级拆分。

### 5.4 长会话上下文总策略

每轮上下文=冻结前缀（规则+文风+场记板锚）→ 压缩摘要（触发后）→ 近期原文窗口 → 尾部重述 → 本轮输入。事实真相始终在故事 DB（检索/场记板重建），transcript 只是工作记忆——"运行期够不着=不存在"（OpenAI）。导演轮的工具调用不进入跨轮历史（现状 surface 每轮从消息重建，天然如此），无需跨轮工具输出 prune。

## 7. 其他主动发现（非用户提出）

## 9. 问题卡片与决策记录

> 约定：有明确技术答案的不占卡片；以下是真实设计分叉。每卡：背景→选项→推荐+理由。

**卡片 A｜过程呈现的语言体系**
背景：纠偏定了"正文主角+过程折叠"，但没定过程的"方言"。现状 L1 就是 CLI 等宽方言，与衬线正文同屏断层。
选项：① 剧场语言为表、CLI 为里（L1 全人话，等宽只存在于 L2 审计展开层）② 保持 opencode CLI 风仅调密度 ③ 彻底文学化（连 L2 也不放原始参数）。
推荐 ①：兼顾"界面消失进故事"与"审计透明"；③ 会丧失 debug 能力（用户即开发者）。
**✅ 决定（2026-08-16）：①——剧场为表、CLI 为里。**

**卡片 B｜harness 主形态**
背景：调研最强证据支持"导演决策/执笔分离"双通道，但改动大；单通道也可用"节奏+闸门+lint"逼近。
选项：① 单 agent+执笔步协议+完稿 lint（§5.1-5.3 全案）② 双通道（执笔为独立受约束 pass，条件=已提交库状态）③ 仅改提示词不动机制。
推荐 ①：先兑现已建成机制的价值，双通道作为 v0.4 评估项（成本/延迟双倍是叙事产品硬约束）。
**✅ 决定（2026-08-16）：①——单 agent+执笔协议+lint；双通道不排期。**

**卡片 C｜剧情锚（与"无大纲"原则的边界）**
背景：无大纲=不暴露"规划"给用户；但长剧情需要内部锚（当前弧线/未兑现伏笔/叙事时间），否则伏笔全靠检索召回。core blocks 只覆盖"现在时"，覆盖不了"将来时"。
选项：① 加隐藏锚工具（update_story_anchor），数据只在记忆浏览器可见，UI 零暴露 ② 严格不加，靠检索+宏摘要硬扛 ③ 加锚且配"幕间 Recap 卡"（正文流中极简章末行，复用压缩摘要卡的书脊形态）。
推荐 ①：符合"规划是 AI 内部思考"的纠偏原文；③ 的 Recap 与"正文唯一成果"有轻微张力，留观。
**✅ 决定（2026-08-16）：③——锚工具＋幕间 Recap 卡。**张力消解约束（执行时必须遵守）：Recap 卡仅一行、muted、书脊形态（复用 `IntermediateCompactionSummaryCard` 观感语言），内容限于「第 N 幕 · 叙事时间 · 一句主线进展」；点击展开才见锚详情（弧线/伏笔清单）；不得出现编辑入口（锚只由 AI 经工具维护）。组件规格补入 §4.3.8。

**卡片 D｜重生成语义（本迭代范围）**
背景：业界共识"重生成=并行候选（swipes/三条走向）"，数据模型需支持分支；当前是单次覆盖式重生成（复用故事模式）。
选项：① 本迭代维持单次重生成，并行候选进 v0.4 专项（需消息分支数据模型）② 现在就做并行候选。
推荐 ①：分支模型牵动 schema/持久化/记忆一致性，不宜与本次体验重构混在一起。
**✅ 决定（2026-08-16）：维持单次覆盖式重生成；用户明确"暂时没有多分支的计划"——并行候选不排期，仅在 §3.1 留作业界模式记录。**
