# 记忆库实体归并设计

- 版本：v0.3.0（2026-08-24）
- 状态：已实施（2026-08-24）
- 关联：DOC-11（事实层中间方案）、DOC-15（世界书与角色卡）、`facts_delta.dart` 中 MERGE_ENTITY 的历史预留注释

## 1. 背景与问题

事实层此前只有增量新增（create_entity）+ 更新（update_attr/append_list/add_alias）
+ 归档/手动删除，没有任何归并、别名归一或清理机制。抽取提示词虽有【实体去重
规则】（intermediate_prompts_v2.dart「庄园 vs 异世界庄园」正例），但属软约束，
且低重要度实体不进 `{{known_entities}}` 已知列表，同一实体以不同名称重复建档
（如"庄园"与"边境庄园"各自成条带独立属性）持续发生，导致注入分散、配额浪费。

## 2. 设计决策

| 决策点 | 选择 | 理由 |
|---|---|---|
| 定期自动整理任务 | 不做 | 用户明确要求手动触发 |
| 手动合并执行机制 | 轻量整理器（单次结构化 LLM 调用），不做完整子代理循环 | 全模式可用、快、失败面小 |
| 抽取侧相似名处理 | 只告警不转换 | 零误合并风险；中文短名包含关系有误判空间（"剑"≠"断水剑"），自动转换不可逆 |

**核心架构原则：归并 = 组合既有标准动作（add_alias / update_attr /
append_list / archive_entity），不新增 FactsDelta 原子动作。**

收益：

1. 完整复用 FactApplier 的世界书只读守卫、schema 白名单、置信度门。
2. 完整复用 `deleteFactsByTurns._rollbackSurvivingEntities` 的审计逆放回滚
   （add_alias→移除、update_attr→恢复旧值、archive→unarchive 均已实现），
   导演模式草稿随轮取消/失败不留残 state。
3. `factual_memory_history` 表只写标准动作串——读取路径
   `_historyFromRow` 用 `FactAction.fromString` 解析，自定义动作串会抛
   ArgumentError。

## 3. 三层能力

### 3.1 抽取侧相似名告警（观测增量）

`FactApplier._applyCreateEntity`：精确查重未命中后，取会话内未归档实体做包含
关系检测（`isNameContainmentSimilar`：互为 contains 且短名长度≥2，排除单字
符名）。命中仅记 warn 日志后照常创建。让重复创建可观测（可统计复发率）。

### 3.2 导演模式 merge_entities 工具（agent 入口）

`MergeEntitiesTool implements AgentTool`（write 权限，watchMode 写前审批覆盖）：

- 参数：source/target 各支持 entity_id 或 name 定位 + confidence + reason。
- invoke 机械拆解并暂存进 `draft.factsDeltas`：
  1. 源主名+别名去重并入 target 别名（add_alias × n）；
  2. 源有 target 无的属性整体搬迁（update_attr / list 型逐条 append_list，
     append_list 缺失键时会自动建 list 行）；
  3. 同键 list 补差集；同键单值冲突不搬，在工具输出中列出交模型决策；
  4. archive_entity(source) 收尾（可逆）。
- 单次暂存上限 50 条；世界书来源实体拒绝参与；finish_round 统一提交。

### 3.3 记忆查看器手动合并（用户入口）

事实 Tab 复用现有多选模式（v0.2.3 强制注入那套勾选交互），底栏新增「AI 合并」：

```
多选 ≥2 条（可行归并组合：全普通实体；或恰 1 张角色卡 + ≥1 条普通实体，
卡片为强制保留者。世界书实体两角色皆不可，多条只读必有一条被吸收 → 均拦）
→ 意图确认弹窗
→ FactsMergeService.planMerge（一次非流式 JSON 调用，30s 超时，
   temperature 0.2，禁思考；仿 MemoryConsolidator：容错解析首尾大括号，
   失败返 null → SnackBar 可重试）
→ 预览弹窗（规范条目/别名并集/合并后属性/LLM 备注/被归档条目）
→ 确认后在 repo.runInTransaction 内组合标准动作原子落库：
   updateEntityBasic（规范名+重要度，开自身事务故置于合并事务外）
   updateEntityAliases + add_alias 审计行
   属性：已有 auto 行 → updateAttributeValue；无 → createAttribute
        （AttributeSchema.defaultImportance 取默认重要度）+ updateAttr 审计行
   被吸收条目逐个 archiveEntity + archive_entity 审计行
→ _loadData 刷新 + 退出多选
```

- 模型配置：复用会话 summarizing 阶段配置
  （`resolveIntermediatePhaseNamingConfig(session, 'summarizing')`）；
  未配置时提示引导设置。查看器仅在故事/导演两模式可见，均持有真实 session。
- 轮次约定（2026-09-02 收窄）：别名/属性审计行 turnNumber 沿用
  查看器编辑惯例（target.updatedTurn ?? createdTurn，即历史轮号）；**归档
  审计行与被吸收实体 updatedTurn 改用「当前会话最大轮+1」**——越过任何
  既有轮次后，重生成回滚（fromTurn ≤ 当前最大轮）不会命中复活被吸收实体。
  原表述「沿用历史轮号即永远不会被回滚重放命中」不成立：历史轮号 ≤ 当前
  最大轮，重生成该轮及之后会精确命中归档行并逆放复活。实际保证是：
  归档侧跨任何重生成存续；别名/属性侧与手动编辑一致，随其历史轮号所在
  轮的重生成回滚（完整逆放，非半截）。
- 归并口径（B10 对齐导演 merge_entities，唯一真源：
  `agent_session_tools.dart` MergeEntitiesTool——source 拒只读、
  target 拒 worldbook）：世界书实体既不能被吸收也不能作保留者；
  角色卡实体不能被吸收、可作保留者（含单张卡片时为强制保留者，
  方案层校验 target 落卡片上）。原表述「世界书/角色卡投影
  （source.isReadOnly）禁止参与合并」按此口径细分。

### 3.4 明确不做

- 自动静默合并（含 applier 层模糊匹配转换）。
- 定期/压缩时机自动整理任务。
- chat 对话模式入口（该模式本无记忆库 UI）。
- 同 sessionId 重进会话横幅仍在的 provider 生命周期问题（另一缺陷的边界，
  不在本特性范围）。

## 4. 测试约定

- `facts_merge_service_test.dart`：正常解析/容忍前后杂文/非法 target 与空名
  拒绝/LLM 异常与单条目短路。
- `facts_merge_apply_test.dart`：内存 drift 库复现落库写序列，断言终态
  （改名/别名并入/属性更新新建/源归档/审计可读/findByName 命中转移到 target）。
- `agent_session_tools_test.dart` MergeEntitiesTool 组：暂存序列、世界书守卫、
  同实体与缺参失败、list 差集；buildAgentTools 清单预期含 merge_entities（write）。
- `fact_applier_test.dart`：相似名创建行为不变 + isNameContainmentSimilar 规则表。
