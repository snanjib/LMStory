# 导演模式设置体系设计

- 状态：已实施（2026-08-27 设计定稿并同日实施）
- 范围：导演模式（advanced）全局配置段、全局设置页、会话设置面板、工具权限模型、与故事模式（intermediate）的配置解耦
- 参考：`doc/design/v0.3.0/导演模式体验重构调研与方案.md`、opencode、deepseek-harness 配置面调研

## 0. 结论摘要

导演模式的设置体系从"3 个会话级专有设置 + 寄生 intermediate 全局配置 + 大量硬编码常量"重构为：

1. **`default_config.json` 新增完全独立的 `advanced` 配置段**——导演运行时消费的每一个键都在 `advanced` 段内有家，不再从 `intermediate.*` 读任何值。即使某些键当前默认值与 intermediate 相同，也是两套独立真相。
2. **工具权限模型**——`watchMode` 布尔泛化为 opencode 式三态权限（allow/ask/deny）× 12 工具，全局与会话两层叠加，保留「监督模式」预设兼容旧交互。
3. **会话设置面板扩为 6 节**——补齐生成参数、上下文压缩、工具调用开关（全部复用已有数据库列），新增轮时间预算与工具权限两个新列。
4. **全局设置页新增「导演模式设置」一级菜单**——自包含，不跳转故事模式设置页。
5. 分家时刻**零行为变化**：advanced 段默认值 = 当前实际生效值（intermediate 寄生值或硬编码值），用户已写入的 `intermediate.*` overrides 做一次性复制迁移。

附带修复一个存量缺陷：导演轮生成参数直读会话列、NULL 时透传 null 给 LLM 不回退全局（`director_round_runner.dart:364-366`），与压缩预留使用合并值的口径分裂。

## 1. 背景与现状缺口

### 1.1 会话级现状

`DirectorSessionSettingsSheet`（472 行）仅 5 节：主模型（GM，写 `phaseModels['generating']`）、项目规则（`systemPromptOverride`）、每轮最大步数（`maxSteps`，NULL=8/0=无限）、监督模式（`watchMode`）、记忆库入口。

缺口：`chat_sessions` 表中 temperature/topP/maxTokens/双惩罚/reasoningEffort、`effectiveContextLimit`、`autoCompaction`/`compactionThreshold`、三比例 override（`compactionTriggerRatioOverride`/`recentMinRatioOverride`/`retrievalRatioOverride`）、`jsonModeOverride`（工具调用开关）等列**运行时被导演读取但无导演侧 UI**，用户只能靠故事模式面板或物化快照残留值间接影响导演。

### 1.2 全局现状

`default_config.json` 无任何 `advanced` 段（grep 零命中）。导演全部全局行为寄生 `intermediate` 段：`system_prompt`、`generation.*`、`phase_models.generating_*`、`contextBudget.*`、`context.*`、`memory.factual.*`、`embedding*`、`consolidation.*`、`retrieval.*`（17 键）、`stream.tool_calling_enabled`、`suggest_reply.*`、`prompts.consolidationPrompt`、`reviewEnabled`。设置页对导演只有一张开关卡片（`_AdvancedModeCard`）。

### 1.3 硬编码常量清单（无任何配置入口）

| 常量 | 当前值 | 位置 |
|---|---|---|
| 轮时间预算 `maxDuration` | 5 分钟（AgentBudget 默认，导演未传） | `agent_budget.dart:14` |
| 轮 token 预算 `maxTotalTokens` | `(contextWindow * 0.6).round()` | `director_round_runner.dart:205` |
| 请求重试 `maxRequestRetries` | 1 | `agent_budget.dart:15` |
| doom-loop 阈值 | 连续 3 次同工具同参 | `director_round_runner.dart`（`DoomLoopDetector(threshold: 3)`） |

| 写前审批超时（fail-closed） | 5 分钟 | `director_round_runner.dart:536` |
| 子代理步数/时长 | 6 步 / 2 分钟 | `agent_subagent.dart:34-35` |
| maxSteps 默认 | 8 | `director_session_extension.dart` |
| watchMode 默认 | false | 同上 |

### 1.4 存量缺陷（本次一并修复）

`director_round_runner.dart:364-366` 直读 `state.session.temperature/topP/maxTokens` 构造 `AgentCallConfig`，会话列为 NULL 时把 null 透传给 LlmService（走 API 默认，静默偏离全局配置）；而同文件 726-727 行压缩预留用合并后的 `round.settings.maxTokens`——同一轮内两种口径。

## 2. 设计原则

### 2.1 两个产品原则（最高优先级）

故事模式与导演模式本质是**"单次生成"与"agent loop"两种形态**，即使都服务于叙事引擎，也按**两个产品**对待：配置键、解析链、默认值、设置 UI 全部独立，**不允许任何关联与依赖**（含设置页之间的跳转）。即使某个键两边默认值暂时相同，也是各自段内独立维护的两份真相，后续可各自演化。

解耦的唯一共享物是**代码资产**：值类（`ContextBudgetConfig` 等纯数据形状）与 story_runtime 共享服务实现（压缩、持久化）——这是 Clean Architecture 允许的方向（两个 feature 共同依赖 Core/story_runtime 基础设施），共享的是形状与实现，不是配置。

### 2.2 从 opencode / deepseek-harness 提炼的配置面原则

1. **少而准**：dsh 刻意不暴露步数上限，opencode 把重试/退避参数硬编码。暴露标准 = 用户有真实调优动机且能感知差异。工具输出截断、并发度、退避曲线等内部细节不进配置面。
2. **权限是 agent 配置的核心**：opencode 精华为三态 `allow/ask/deny` + 层级叠加（内置默认→全局→会话，逐工具后写优先）；dsh 用权限预设捆绑。`watchMode` 即"write 类全部 ask"的预设，应泛化为完整权限模型。
3. **fail-safe 默认**：审批 fail-closed 已有；本次所有键默认值 = 当前行为，不借配置化擅自改默认（唯一例外：ask_user 超时默认 10→3 分钟，见第 11 节）。
4. **复用仓库既有三层管线**：asset 默认 → `user_overrides`（SharedPreferences 扁平点分 key）→ `chat_sessions` 会话列（NULL=跟随全局）。advanced 段零新机制。

### 2.3 基础设施边界

`network.*`（HTTP 超时）、供应商与 API 预设（`api_presets` 表、`ProviderListPage`）、`common.title_model`（会话标题生成）属于**跨产品 Core 基础设施**，不属于任何一种模式，两边共同依赖 Core——这符合依赖方向（feature → core），不构成"两个产品"之间的相互依赖。advanced 段不复制这些键。

## 3. 总体架构

```
default_config.json                user_overrides (SP)           chat_sessions (drift)
┌─ intermediate（故事，不动）       intermediate.* 覆盖           会话列 NULL=
├─ advanced（新增，导演自足）  ←─   advanced.* 覆盖          ←─   跟随 advanced 全局
└─ broadcast_chat / network / common / ...

解析链（导演会话）：
ConfigurationResolver.resolveAdvancedSettings(session, AdvancedConfig, ...)
  → ChatSessionSettings（复用结构，全局来源换成 AdvancedConfig）
  → RoundContext（config 字段改型为模式无关参数对象，见 3.1）
  → DirectorRoundRunner / AgentRunner
```

- `lib/core/config/` 新增 `AdvancedConfig`（与 `IntermediateConfig` 平级的解析产物），含自己的一切子段。
- 守门测试 `settings_config_roundtrip_test.dart` 增加 advanced 段逐叶子比对。
- 会话列仍是 `chat_sessions` 共享表（每行属于单一模式，按模式解析不同全局来源，互不干扰）。

### 3.1 RoundContext 与共享服务的改型

现状 `RoundContext.config` 定型为 `IntermediateConfig`（`round_context.dart:69`），导演控制器全程按 `IntermediateConfig` 取数（`advanced_chat_controller.dart:78/428/567-625`）。改型方案：

1. **值类下沉**：`ContextBudgetConfig`、`ContextConfig`、`EmbeddingConfig`、`MemoryConfig`/`FactualConfig`、`ConsolidationConfig`、`RetrievalConfig`、`StreamConfig`、`GenerationConfig`、`SuggestReplyConfig`、`PromptsConfig` 等纯数据类移到（或重新归属）共享层，`IntermediateConfig` 与 `AdvancedConfig` **组合**同一批值类。
2. **RoundContext.config 改型**：由 `IntermediateConfig` 改为模式无关的窄聚合（如 `StoryRuntimeConfig`：仅含共享服务实际消费的子配置——初步为 contextBudget/context/embedding/memory.factual/consolidation/retrieval/prompts.consolidationPrompt/reviewEnabled 对应物）。故事控制器从 `IntermediateConfig` 组装，导演控制器从 `AdvancedConfig` 组装，构造侧各自负责。
3. **消费点穷尽审计（实施第一步）**：grep 全部 `IntermediateConfig` 消费点（已知真消费：`suggestReply`（`_suggest.dart:102`）、`prompts.consolidationPrompt`（`_persist.dart:254`）、`reviewEnabled`（`_persist.dart:281`）；`fork`/`retry` 目前仅出现在整体 copy-with 透传）。逐个映射到 advanced 键或移除透传，保证 `lib/features/advanced/` 内对 `IntermediateConfig` 的 import 清零。

## 5. 工具权限模型

### 5.1 三态语义

| 态 | 行为 |
|---|---|
| `allow` | 直接执行（当前默认行为） |
| `ask` | 走现有 `AgentToolPipeline` 审批 seam → 横幅确认，超时 fail-closed（现有 watchMode 机制复用） |
| `deny` | 工具不注册（模型不可见，系统提示词工具索引同步移除）；子代理 research 白名单与主代理 allow 集求交集 |

### 5.2 求值（opencode 式逐工具后写优先）

```
内置默认（12 工具全 allow）
  → 全局 advanced.tools（user_overrides 写入）
    → 会话 chat_sessions.tool_permissions（JSON 列，NULL=跟随全局）
```

新工具注册时默认加入 allow，无需改配置。

### 5.3 预设（dsh permission-presets 模式）

- 「自由创作」：全 allow（= 今天 watchMode=false）
- 「监督模式」：write/control 类 → ask、只读类与 ask_user/finish_round → allow（= 今天 watchMode=true）

会话面板原 watchMode 开关**保留原位原交互**，语义变为"套用监督模式预设"（一键写入完整权限 map）——老用户心智不变，per-tool 细调是增量能力。

工具分类（固定，随 `buildAgentTools` 维护）：
- 只读：`search_story`、`read_story`、`query_facts`、`read_compact_summary`、`read_skill`
- 写入：`update_facts`、`merge_entities`、`update_story_anchor`、`record_event_memory`
- 控制：`spawn`、`ask_user`、`finish_round`

## 6. 会话设置

### 6.1 解析链路与缺陷修复

- 新增 `ConfigurationResolver.resolveAdvancedSettings`：复用 `ChatSessionSettings` 结构，生成参数/上下文/压缩/工具调用 override 列的回退来源全部换成 `AdvancedConfig`。
- **缺陷修复**：`DirectorRoundRunner` 构造 `AgentCallConfig` 改从合并后的 `round.settings` 取 temperature/topP/maxTokens（及惩罚/思考档若网关支持），不再直读会话列。这是本次唯一存量行为变更（NULL 透传 → 正确回退）。
- 项目规则三级回退：`session.systemPromptOverride > advanced.system_prompt > 内置编辑部规则`。
- 预算：会话 `max_duration_minutes` 列 > `advanced.budget.max_duration_minutes`。
- `maxSteps` NULL 回退 `advanced.defaults.max_steps`（原硬编码 8）。

### 6.2 面板信息架构（DOC-14 折叠方案对齐）

交互约定沿用 DOC-14 §3.4（故事会话设置重构）同款：**「查看记忆库」常驻置顶不参与折叠**（一键折叠跳过，记忆库始终可达）、「重建向量索引」并入可折叠「记忆管理」组、标题栏一键折叠/一键展开、折叠状态按分区 id 全局记忆（key：`user_overrides.ui.directorSession.collapsedSections`，`collapsed_sections_store.dart` 参数化复用）、单项瓦片边界 + 数值点按输入；默认态仅首次生效。默认态原则：高频认知项展开（模型/规则/监督），低频调参项折叠（记忆管理/预算/上下文压缩）。复用 `session_settings_fields.dart` 现成组件与 DOC-14 的折叠/瓦片组件。

| 分区 | 内容 | 数据 | 默认态 |
|---|---|---|---|
| 查看记忆库（常驻置顶） | MemoryBrowserPage 入口 | — | 不参与折叠 |
| 记忆管理 | 重建向量索引 | — | 折叠 |
| 模型与生成 | 主模型（GM）+ 温度/topP/maxTokens/双惩罚/思考档 | 已有列 | 展开 |
| 项目规则 | TextField + 模板库（现有） | 已有列 | 展开 |
| 监督与工具 | 监督模式预设开关 + 12 工具三态表（按只读/写入/控制分组） | 新列 `tool_permissions` | 展开 |
| 运行预算 | 每轮最大步数（已有滑块）+ 轮时间预算 | `max_steps` + 新列 `max_duration_minutes` | 折叠 |
| 上下文与压缩 | 上下文窗口档位 + 压缩三比例 + 工具调用开关 | 已有列 | 折叠 |

会话覆盖旋钮合计 3 个：maxSteps（已有）、轮时间预算（新）、工具权限（新）。token 比例/重试/doom-loop/HITL 超时/子代理预算只做全局——会话间无真实差异需求，控制新列数量。

### 6.3 新列（schemaVersion 44）

| 列 | 类型 | 语义 |
|---|---|---|
| `tool_permissions` | TEXT NULL | JSON map `{工具名: allow|ask|deny}`，仅存差异或完整 map 均可（解析时后写优先）；NULL=跟随全局 |
| `max_duration_minutes` | INT NULL | 轮时间预算会话覆盖；NULL=跟随全局 |

迁移（M44）：
- 存量 `watchMode=true` 会话 → 物化「监督模式」完整 map 写入 `tool_permissions`；`false/null` → 置 NULL。
- 旧 `watch_mode` 列**保留不删不读**（AGENTS.md 保数据要求；后续大版本再清理）。
- 其余新列 NULL 起步，无回填。

写入仍统一走 `AdvancedChatController.updateSession()`（生成中拒绝的快照语义不变）。

## 7. 全局设置页

`SettingsPage` 一级菜单新增「导演模式设置」，与「故事模式设置」平级；`_AdvancedModeCard` 开关卡片迁入该页顶部（主页简化）。页面**自包含，不跳转故事模式设置**。

布局为**单页折叠式**（导演 6 分区的量级不足以拆故事模式的分类子页）：标题栏一键折叠/一键展开，「模型与生成」常驻置顶不参与折叠，其余分区用 `CollapsibleSettingsSection` 折叠；折叠状态全局记忆（key：`user_overrides.ui.directorSettings.collapsedSections`）；默认态=展开（项目规则、工具权限）/折叠（运行与预算、上下文与压缩、检索与记忆），高级子折叠（doom-loop/HITL/子代理/检索权重）保持分区内部 `ExpansionTile`。单项瓦片 + 数值点按输入同 6.2 约定。

| 分区 | 内容 | 配置键 |
|---|---|---|
| 模型与生成默认 | GM 默认模型（复用模型选择交互）+ 生成参数默认 | `advanced.phase_models.*`、`advanced.generation.*` |
| 项目规则默认 | 多行文本 | `advanced.system_prompt` |
| 运行与预算 | maxSteps 默认、轮时间预算、token 预算比例、请求重试、doom-loop 阈值、HITL 双超时、子代理步数/时长（后五项折叠进"高级"子区） | `advanced.defaults/budget/doom_loop/hitl/subagent.*` |
| 工具权限 | 「自由创作/监督模式」预设按钮 + 12 工具三态表 | `advanced.tools.*` |

推荐回复（`advanced.suggest_reply.*`）随模型分区或独立小组，后续细化。

## 8. 解耦重构与兼容迁移

### 8.1 user_overrides 一次性复制（分家零行为变化）

分家前，用户在全局设置页改过的 `intermediate.*` overrides 同时影响导演。分家后导演改读 `advanced.*`，需一次性迁移：首启检测（迁移标记存 SharedPreferences），把导演实际消费的 `intermediate.*` override 键值复制为对应 `advanced.*` 键（映射表随第 4 节），复制后**不删**原键（故事侧继续用）。default_config 层面 advanced 默认值本就 = intermediate 默认值，故仅需复制 overrides。

### 8.2 涉及面

- `lib/core/config/`：`AdvancedConfig` + 值类归属调整 + `AppConfig.fromJson`。
- `lib/features/advanced/`：控制器/Runner 全面改型（`IntermediateConfig` import 清零），权限求值器，面板，设置页。
- `lib/features/story_runtime/`：`RoundContext.config` 改型为共享聚合；故事侧构造链路同步调整（行为不变）。
- `assets/configs/default_config.json`：advanced 段。
- `lib/i18n/zh_CN.i18n.yaml`：`settings.director.*`（新）+ `advanced.settings.*`（扩充）。
- drift M44、守门测试、`ConfigurationResolver` 单测、权限求值/迁移单测。

## 9. 实现计划（4 阶段，每阶段独立可交付可回归）

- **配置段与解析链路（含缺陷修复）**：消费点穷尽审计 → 值类下沉 + `AdvancedConfig` + default_config.json 段 + `RoundContext` 改型 → `resolveAdvancedSettings` + 导演链路接线（AgentCallConfig 改读合并值，修复 NULL 透传）→ user_overrides 一次性迁移 → 守门/单元测试。
- **工具权限模型**：三态实体 + 求值器（默认→全局→会话）→ pipeline 接线（ask）/注册过滤（deny）/子代理交集 → 预设 → schema M44（watchMode 转换）→ 求值/迁移单测。
- **全局设置页**：页面 + 6 分区组件 + 开关卡片迁移 + user_overrides 写入 + i18n。
- **会话面板重构**：6 节布局 + 新控件接线（工具三态表、时长预算）+ i18n 扩充 + 全量 `flutter test` 回归。

## 10. 明确不做（YAGNI）

- 每条消息级覆盖（opencode per-message model/variant）
- 临时 always-allow 记忆（opencode ask 回复 once/always）
- 工具输出截断、并发度、重试退避曲线配置
- pattern 粒度权限（文件 glob/命令前缀对叙事工具无意义，per-tool 即可）
- skill 目录开关（留给外部 skill 导入一起做）
- penReminder/首回合能力提示等提示词常量配置化
- advanced 段复制 network/供应商/标题模型（Core 基础设施，非模式配置）
