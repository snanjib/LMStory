# LMStory UI 设计基础

> **创作与档案补充（2026-10-08）**：长稿编辑采用限高与内部滚动，保存动作允许换行；资源集合优先名字与档案留白，内容区至少 760px 且字号不超过 1.3 倍时两列，否则单列。导演技术页继承 Kit 表面与公共标题，遥测正文至少 13px；提示词技术内容使用已打包 LMMono。审批/问题标题与倒计时分行，动作可换行；失败栏有限高低于 320px，或大字号且可用高度低于 600px 时整体滚动，其他情况下保留固定操作与独立详情。候选回复支持完整阅读与焦点反馈，过渡遵循减弱动态。统一待设备验收。

> **叙事视觉完善（2026-10-08）**：面板采用 `PanelHeading`，长标题最多三行，多操作在窄屏或大字号时另起一行；单个关闭按钮保持可达。数值说明采用 `LabeledValue`，窄屏/大字号纵向排列并完整换行。模型条目名称、ID 与能力/长度分层；搜索预览继承主题字体及系统字号。数据/诊断表面使用 `context.lmUi.card`，四结构继续掌管材料与边界。三轮统一待设备验收。

> **叙事视觉扩展**：首轮已获得用户真机体验认可，继续在 `feat/narrative-visual-iteration` 上扩展公共标题、设置分组、侧栏、输入区、供应商、模板、引导与帮助。配置/操作仍用清楚的 UI 字体，章节与内容名称采用衬线层级；四结构通过 Kit 维护各自表面与边界，输入区不使用模糊。第二轮仍待真机验收。

> **叙事视觉迭代实验（2026-10-07）**：在独立分支 `feat/narrative-visual-iteration` 上以文字建立页面身份，沿用 `LmComponentKit` 的结构与现有配色。首页突出最近活跃的故事/导演会话；已有会话不受新建入口开关影响。普通屏幕保留固定一屏与下拉刷新，短屏/大字体收紧入口与标题。角色详情以名字的首个完整字素作无语义装饰，不暗示已保存头像；名字与原有资料仍完整可读。资源条目强调名称层级。事实实体保留既有操作，经历时间线只表示按轮次排列的记录，不在重要性或创建时间排序时暗示叙事先后。全组合自动化通过不等于真机视觉接受。

## 0. 设计文档体系导航

LMStory 采用"两个产品"架构：Simple 模式是**工具**（克制、高效、消失于任务），中级/高级模式是**体验**（沉浸、氛围、有存在感）。两者共享基础零件（间距、圆角、原子组件），但视觉语言完全独立。

UI 设计文档体系按模式拆分：

| 文档 | 内容 | 版本 |
|------|------|------|
| **DOC-06（本文档）** | 设计基础——共享设计令牌、通用布局、设置页面、交互基础、基础组件、主题架构、验收标准 | v0.1+ |
| **DOC-06A** | Simple 模式视觉规范——Simple 色彩、字体、页面布局、页面设计、交互、动效、业务组件、设计令牌 | v0.1 |
| **DOC-06B** | 中级模式视觉规范——夜航配色、配色皮肤架构、衬线+无衬线字体、进入转场动效、特色组件 | v0.2 |
| **DOC-06C** | 高级模式视觉规范（已取消） | 不再建设：导演模式复用 06B 夜航主题，无独立视觉规范 |

**使用原则**：
- 实现某模式的功能时，先查本文档（共享基础），再查对应模式文档（06A/06B/06C）
- 当模式文档与本文档冲突时，该模式范围内以模式文档为准
- 跨模式共享的组件（如设置页面）以本文档为准

## 1. 共享设计令牌

以下设计令牌为所有模式共享，各模式不得自定义不同的圆角/间距/图标尺寸。

### 1.1 圆角系统

| Token 名 | 半径 | 用途 | 示例 |
|---------|------|------|------|
| rXs | 4 | 小徽章、行内标签 | — |
| rSm | 8 | 芯片、小按钮 | Token 计数芯片 |
| rMd | 12 | 输入框、列表项、主按钮 | ChatInput、ElevatedButton |
| rLg | 16 | 卡片、面板、BottomSheet | 设置卡片、会话卡片 |
| rXl | 20 | 大容器、模态框 | Dialog |
| rFull | 9999 | 胶囊形 | 发送按钮、Chip、输入框 |

> **v0.1 实际实现差异**：旧文档中圆角为 large=16/medium=12/small=8/button=24（胶囊形）。实际代码使用 rXs=4/rSm=8/rMd=12/rLg=16/rXl=20/rFull=9999。输入框和 Chip 使用 rFull（胶囊形），主按钮使用 rMd（12px），不再使用 24px 胶囊形按钮。

## 3. 设置与配置页面设计

设置页面为所有模式共享的通用功能（通用设置、对话模式设置、故事模式设置、数据管理等）。各模式可能有独立的会话设置入口（如 Simple 模式的 SessionSettingsSheet，详见 DOC-06A），但全局设置页面统一使用本节规范。

### 3.1 设置主页 (SettingsPage)

**路由**: `/settings`（NavigationBar Tab 1）

**布局结构**：
```
AppBar
├── 标题：i18n key "tabs.settings"

设置列表
├── 设置卡片
│   ├── 图标（22×22）
│   ├── 标题（bodySm，ink）
│   ├── 说明（caption，muted）
│   └── 右箭头（faint）
├── 通用设置          → GeneralSettingsPage（含供应商入口置顶）
├── 对话模式设置      → ChatSettingsPage（默认模型 + 新对话默认生成参数 + 自动压缩 + 显示偏好）
├── 故事模式设置      → IntermediateSettingsPage
├── 提示词模板        → TemplateManagementPage
├── 数据管理          → DataManagementPage
└── 诊断信息          → DiagnosticsPage
```

**设置卡片规范**：
- 背景色：surface
- 圆角：rLg (16)
- 内边距：sLg (16)
- 图标颜色：primary
- 卡片间距：sMd (12)

> **v0.2 重构变更**：一级菜单由 7 项精简为 6 项。
> - "模型提供商"独立入口移入「通用设置」顶部
> - "默认模型"独立入口拆分到「对话模式设置」（卡片入口 + 底部 sheet）与「故事模式设置」（dropdown）
> - 新增「对话模式设置」页（ChatSettingsPage），承载默认模型、新对话默认生成参数（v3.4.0 新增）、自动压缩、显示偏好
> - 原 DefaultModelPage 已删除

### 3.2 模型提供商列表页 (ProviderListPage)

**路由**: `/settings/providers`（入口位于「通用设置」顶部，非一级菜单）

**对标 ChatBox**: `ProviderList.tsx`

**布局结构**：
```
AppBar
├── 标题：i18n key "settings.provider.title"（"模型提供商"）
└── 新建按钮（+）

供应商列表（ListView）
└── ProviderCard（每个供应商一项）
    ├── 图标（dns_outlined，40×40，primaryDim 背景）
    ├── 供应商标题（body w600）+ 内置徽章（isBuiltIn 时显示）
    ├── baseUrl（caption，单行省略）
    ├── 状态行
    │   ├── API Key 状态点（success/warning）
    │   └── 模型数量（"N 个模型"）
    └── 右箭头（chevron_right）
```

**交互**：
- 点击卡片 → 跳转 `ProviderDetailPage`（3.3）
- 点击 "+" → 弹出新建对话框（输入 name + baseUrl）
- 空列表状态：图标 + emptyList 文案 + "新建"按钮

**关键设计原则**：
- 供应商只是"连接信息 + 模型列表"的配置容器，**没有"激活/选择"概念**
- 真正选择模型是在每个对话中，默认模型由「对话模式设置」页的卡片入口 + 底部 sheet 设置（v0.2 重构后，原 DefaultModelPage 已删除）

### 3.3 供应商详情页 (ProviderDetailPage)

**路由**: `/settings/providers/:presetId`

**对标 ChatBox**: `$providerId.tsx`（一个页面整合 API Key + Host + 模型列表）

**布局结构**：
```
AppBar
├── 标题：供应商名称
└── 删除按钮（仅自定义供应商显示，内置供应商不可删除）

ListView（单页四区块）
├── 名称区块（_NameField）
│   ├── 显示当前名称（muted）
│   └── 编辑按钮 → 切换为 TextField + 保存/取消
├── BaseUrl 区块（_BaseUrlField）
│   ├── 显示当前 baseUrl（muted）
│   ├── 编辑按钮 → 切换为 TextField + 保存/取消
│   └── 内置供应商提示："修改将创建自定义副本"（fork-on-write）
├── API Key 区块（_ApiKeyField）
│   ├── 状态点（success=已设置 / warning=未设置）
│   ├── 编辑按钮 → 密文输入框 + 显隐切换 + 保存/取消
│   └── 测试连接按钮 → 通过"获取模型列表"（GET {baseUrl}/models）验证连接，不消耗 token，SnackBar 反馈
└── 模型列表区块（_ModelsSection）
    ├── 区块标题 "模型 (N)"
    ├── 多选按钮（checklist_outlined 图标，v0.1.3+ 新增）→ 进入/退出多选模式
    ├── 获取模型列表按钮（按协议分发到对应适配器拉取，loading 时显示转圈）
    │   └── 拉取后弹出 ModelPickerDialog（搜索+勾选，避免 OpenRouter 数百模型全加）
    ├── 添加模型按钮 → 弹出 ModelEditDialog（类型+能力+上下文+Test Model）
    ├── 多选模式操作栏（_BatchActionBar，多选模式下出现）
    │   ├── 左：已选 N 项（caption，muted）
    │   ├── 中：全选 / 取消全选（按当前 allSelected 切换文案）
    │   └── 右：删除选中 (N)（0 选中时 disabled，muted 色）
    └── 模型列表
        ├── 普通模式：模型项双行布局（第一行：图标 + 名称 + 能力徽章；第二行：contextWindow/maxOutput 徽章 + Spacer + 编辑/删除按钮）
        ├── 多选模式：模型项双行布局（第一行：checkbox + 名称 + 能力徽章；第二行：contextWindow/maxOutput 徽章，无编辑/删除按钮）
        │   └── 选中态：行背景 primary.withValues(alpha:0.05) + checkbox 切到 check_box
        ├── 编辑按钮 → 弹出 ModelEditDialog（modelId 只读，可改类型/能力/上下文/输出）
        ├── 单项删除按钮 → 确认对话框
        └── 批量删除 → 二次确认后从 cachedModels 过滤掉选中 modelId
```

**ModelPickerDialog（模型选择弹窗，对标 ChatBox ModelList）**：
- 拉取 /v1/models 后弹出，让用户勾选要加入的模型
- 搜索过滤 + 复选勾选（check_circle / radio_button_unchecked）
- 显示能力徽章 + contextWindow/maxOutput chips
- 已存在的模型默认勾选
- 保存后合并：用户勾选的 + 原有但不在拉取列表里的（手动添加的保留）

**ModelEditDialog（模型编辑弹窗，对标 ChatBox ModelEdit）**：
- Model ID 字段（编辑时只读）
- Display name 字段
- Model Type 下拉（chat/embedding/rerank）
- Capabilities 复选 chip（vision/reasoning/toolUse/webSearch，仅 type=chat 时显示）
- Context Window 数字输入（tokens）
- Max Output 数字输入（tokens）
- Test Model 按钮（调用 ModelTestService，自动勾选检测到的 vision/toolUse）

**ModelCapabilityBadges（能力图标组件）**：
- 紧凑横向排列，每个图标带 Tooltip
- vision → visibility_outlined / primary
- reasoning → lightbulb_outline / warning
- toolUse → build_outlined / success
- webSearch → travel_explore_outlined / accent

**Fork-on-Write 策略**：
- 内置供应商（OpenAI / DeepSeek / OpenRouter）的 baseUrl 修改会触发 fork-on-write：创建自定义副本
- 内置供应商不可删除，只可创建副本
- 自定义供应商可删除（删除前弹确认对话框）

### 3.4 默认模型选择底部 sheet (DefaultModelPickerSheet)

**入口**: 「对话模式设置」页 → ChatDefaultModelSection 卡片 → `showModalBottomSheet`

**v0.2 重构变更**：原独立路由页 `DefaultModelPage` 已删除，改为底部 sheet 形式，简化为只展示 `ModelType.chat` 类型模型（去掉类型过滤 chip），因为对话模式默认模型语义上只关心对话模型。

**v3.3.0 扩展（2026-07-21 配置架构重构）**：`DefaultModelPickerSheet` 从「对话模式默认模型」专用 sheet 重构为**可复用模型选择 sheet**，支持标题模型等跨场景复用。新增 3 个参数：

| 参数 | 类型 | 用途 |
|------|------|------|
| `title` | `String` | sheet AppBar 标题文案。默认 `t.chat.defaultModel.selectModel`（"选择默认模型"）；标题模型场景传入 `t.settings.general.titleModel` |
| `onModelSelected` | `Future<void> Function(String? presetId, String? modelId)?` | 选中模型回调。默认调用 `setDefaultModel(presetId, modelId)` 写入 `broadcast_chat.default_model.*`；标题模型场景传入写入 `common.title_model.*` 的回调。**接受 null 表示"清除选择/跟随全局"**（v3.5.0 改造） |
| `successMessage` | `String` | 选中后 SnackBar 提示文案。默认 `t.chat.defaultModel.selected`（"已选择"）；标题模型场景传入 `t.settings.general.titleModelSaved` |

**v3.5.0 双菜单→单菜单统一改造**（2026-07-24，对标 ChatBox MobileModelSelector）：所有模型选择场景统一为**单一底部 sheet**，废弃原"供应商下拉 + 模型下拉"双菜单模式。新增 4 个参数：

| 参数 | 类型 | 用途 |
|------|------|------|
| `modelType` | `ModelType`（默认 `ModelType.chat`） | 模型类型过滤。故事模式 4 阶段都是 chat 类型；嵌入模型场景传 `ModelType.embedding`。当供应商全部模型 `type=null`（旧数据/API 未返回）时不过滤直接展示，避免空列表误导 |
| `clearLabel` | `String?` | 清除按钮文案。非 null 时在列表顶部显示"清除/使用全局"tile。会话级模式下传"使用全局配置"，点击返回 `(null, null)` 表示跟随全局；全局级模式不传（不显示清除按钮） |
| `clearSuccessMessage` | `String?` | 清除成功 SnackBar 文案。null 时静默清除不弹 SnackBar |
| `onBeforeSelect` | `Future<bool> Function(String presetId, String modelId)?` | 选择前异步确认钩子。嵌入模型切换时已有向量会失效，传此钩子弹确认对话框。返回 false 取消选择。清除操作不触发此钩子 |

**可折叠供应商分组**（对标 ChatBox MobileModelSelector）：供应商作为可折叠分组标题，模型作为子列表。解决"模型列表过长"问题。

- 默认行为：**包含当前选中模型的供应商默认展开**，其他供应商默认收起
- 用户点击组标题切换展开/收起
- 组标题显示：chevron 图标（展开时向下，收起时向右）+ 供应商名 + 模型数量 badge（如 `5`）
- 折叠动画：`AnimatedSize` 200ms easeOutCubic
- 折叠状态为 sheet 内局部 state，关闭 sheet 后重置

**复用方式**：调用方通过传入不同的 `onModelSelected` 回调，将选中结果写入不同的 `user_overrides` key，实现"同一 sheet，多种用途"。原生对话默认模型场景不传 3 个参数（使用默认值）；标题模型场景显式传入 3 个参数；会话级覆盖场景传入 `clearLabel` + `clearSuccessMessage` + 自定义 `onModelSelected`（写入会话字段）。

**标题模型场景示例**（2026-07-21 配置架构重构新增）：

```dart

  selectedPresetId: state.titleModelPresetId,
  selectedModelId: state.titleModelModelId,

  successMessage: t.settings.general.titleModelSaved,

```

**交互**：
- 点击组标题 → 切换该供应商分组的展开/收起状态（AnimatedSize 200ms 动画）
- 点击模型项 → 调用 `onModelSelected` 回调（默认 `setDefaultModel(presetId, modelId)`，标题模型场景为 `setTitleModel(presetId, modelId)`，会话级覆盖场景为自定义回调）
- 选中后显示 SnackBar（文案来自 `successMessage` 参数），sheet 自动关闭
- 点击"清除/使用全局"tile → 调用 `onModelSelected(null, null)`，sheet 关闭，显示 `clearSuccessMessage` SnackBar（若配置）

**选中态判定**：必须 `presetId` 与 `modelId` 同时匹配（基于 `selectedPresetId` / `selectedModelId` 参数），避免跨供应商同名 modelId 误判。

**未设置时的副标题显示**（2026-07-19 v0.2 新增）：`ChatDefaultModelSection` 在用户未选择默认模型时，副标题显示"未设置（将使用 {第一个可用供应商} · {第一个 chat 模型}）"，让用户知道新对话实际会使用哪个模型。若无任何供应商有 chat 模型，显示"暂无可用供应商"。

**关键设计原则**：
- 此 sheet 只是设置"新对话建立时的默认填充值"
- 每个对话仍可单独切换模型（在 SessionSettingsSheet 中）
- 默认模型与供应商配置解耦：删除供应商不会自动迁移到另一个供应商，但会清理悬空引用（2026-07-17 修订）——引用该供应商的 preset_id/model_id 配置被清空，回退到"使用默认"状态，避免设置页因 DropdownButtonFormField 找不到 initialValue 而飘红。详见 DOC-05 `deletePreset` 注释。
- **默认值显示规则**（2026-07-19 v0.2 新增）：所有配置项使用默认值时必须显示实际生效值，而非静态"使用默认"占位文案。适用于全局设置 + 会话级设置两层。详见 DOC-09B §10.2"默认值显示规则"段落。

#### 3.5.2 FontSizeSelectorSection（v3.6.0 改造）

通用设置 → 外观子页的字体大小选择区块，对标 ChatBox `LazySlider` 设计。

- **位置**：通用设置 → 外观 → `SimpleSettingSection(title="字体大小", child=FontSizeSelectorSection)`
- **结构**：
  ```
  Container(surfaceVariant, rLg)
  ├── Row：当前字号 "实际字号 N px"（primary 色 + w600 + tabular figures）
  │       + _DefaultBadge "默认"（仅当 fontSize == 15 时显示，primaryDim 底 + rFull 胶囊）
  ├── Slider(min=12, max=22, divisions=10, step=1) — 连续整数 11 档
  │   拖动时显示数值气泡（primary 底 + surface 字）
  │   整数位置显示 tick mark 小圆点（surface 色）
  ├── _DefaultValueRuler — 默认值标记尺
  │   ├── 顶部 1px divider 横线（连接 Slider 与标记尺的视觉锚点）
  │   ├── 默认值 15 位置的彩色竖线（primary 色，2×10px，比端点 tick mark 更突出）
  │   ├── "默认" label（primary 色，居中于竖线下方）
  │   ├── min 端点 label "12"（faint 色，tabular figures）
  │   └── max 端点 label "22"（faint 色，tabular figures）
  └── _FontSizePreview：模拟消息气泡，用当前 fontScale 渲染示例文本
      ├── 示例文本（body 字号 × fontScale，ink 色，line-height 1.6）
      └── 预览说明（overline 字号，faint 色）"预览效果（与聊天页字号一致）"
  ```
- **字号范围常量**（`font_size_selector_section.dart` 顶层 const，与 `ChatModePage` 共享避免漂移）：
  - `kFontSizeBaseSize = 15`（与 `SimpleTextStyles.body.fontSize` 一致）
  - `kFontSizeMin = 12` / `kFontSizeMax = 22` / `kFontSizeDefault = 15`
- **fontScale 计算**：`fontScale = fontSize / kFontSizeBaseSize`
  - fontSize=12 → fontScale≈0.80（小）
  - fontSize=15（默认）→ fontScale=1.0
  - fontSize=22 → fontScale≈1.47（大）
- **持久化**：`general.font_size`（SettingsRepository `user_overrides`），int 类型，12-22。旧 key `general.font_size_index` (0/1/2 离散) 已废弃，dev 阶段覆盖式重建（项目未发布）
- **生效路径**：`SettingsNotifier.setFontSize(int)` → state → 两个聊天页通过 `ref.watch(settingsNotifierProvider.select((s) => s.fontSize))` 监听 → 计算 `fontScale = fontSize / kFontSizeBaseSize`：
  - **Simple 模式**（`ChatModePage`）：传入 `SimpleMessageBubble.fontScale` 与 `SimpleMarkdownBody.fontScale` → 助手消息文本 `fontSize: (body.fontSize ?? 15) * fontScale`、用户消息同样应用
  - **Intermediate 模式**（`IntermediateChatPage`）：传入 `IntermediateChatBody.fontScale` → `IntermediateMessageBubble.fontScale` → 助手消息 `narrativeBody` 16px × fontScale、用户消息 `bodyUi` 15px × fontScale、思考区块 `narrativeQuote` 14px × fontScale（保留双字体策略与字号差异，仅缩放基准字号；UI 标签 caption/label 不受影响）。同时透传到 `buildCurrentRoundPanels` 的流式回复气泡与终稿气泡。详见 DOC-06B §4.2 字号缩放
- **预览一致性**：预览卡片使用与 `SimpleMessageBubble` 相同的 `SimpleTextStyles.body × fontScale` 渲染逻辑，确保设置页所见即聊天页所得
- **默认值标记尺定位**：用 `LayoutBuilder` 计算 Slider track 实际宽度（`parentWidth - 2 * _sliderTrackPadding`，`_sliderTrackPadding = 12` 对应 Material Slider 默认 overlay 半径），在默认值 15 对应的像素位置画彩色竖线 + "默认" label。该定位逻辑独立于 Slider 内部几何，避免 SliderTheme 自定义 tickMarkShape 无法区分默认档位的限制
- **设计动机**：
  1. 用户反馈"3 档字体太少"——改为 11 档连续整数（min=12 max=22 step=1），对标 ChatBox `LazySlider`
  2. 用户要求"默认值上有标记"——在 Slider 下方独立画"默认值标记尺"，默认值 15 位置有彩色竖线 + "默认" label，与 Slider 的普通 tick mark 形成视觉区分；同时字号等于默认值时，顶部字号数值旁额外显示 "默认" 徽章
  3. 保留预览卡片，所见即所得
- **i18n**：`settings.general.fontSize`（section 标题）/ `settings.general.fontSizeOptions.{small|medium|large}`（保留兼容）/ `settings.general.fontSizeActualPx(value)`（实际字号显示，参数化）/ `settings.general.fontSizeDefaultLabel`（默认值 label）/ `settings.general.fontSizePreviewText`（预览示例文本）/ `settings.general.fontSizePreviewCaption`（预览说明）

- **作用范围**：仅对新会话生效（作为全局默认），会话级设置（DOC-06A §4.3）可覆盖
- **持久化**：通过 `SettingsController.setDefaultReasoningEffort(ReasoningEffort?)` 持久化到 SharedPreferences（user overrides 的 `broadcast_chat.reasoning_effort` key），null = 清除配置
- **配置解析**：`ConfigurationResolver.resolveSettings` 中 `_resolveReasoningEffort` 方法按优先级解析：会话级 > 全局默认 > null
- **API 请求**：`ChatModeController._sendToApi` 仅当模型 `capabilities` 包含 `ModelCapability.reasoning` 且解析后的 `reasoningEffort != null && isEnabled` 时，将 `reasoning_effort` 参数加入请求体

> **v0.1 实际实现差异**：旧文档仅含"主题模式 / 语言 / 自动压缩"三项，且备注"字体大小设置项暂未包含"。实际代码已实现字体大小、发送键模式、超时设置、压缩阈值滑块、默认思考预算、显示偏好（含 7 个开关 + 布局模式选择器）等完整设置项。

### 4.3 色层与 ink splash 宿主

> **背景**：`ListTile` / `InkWell` 等组件需要 `Material` 作为父级才能正常显示水波纹和背景色。若用 `ColoredBox` / `DecoratedBox` 等带背景色的容器直接包裹，色层会遮挡 ink splash，导致：
> - 水波纹不可见
> - 控制台输出 `FlutterError: ListTile background color or ink splashes may be invisible` 警告

**规范**：当需要给可点击区域（`ListTile` / `InkWell` / `SwitchListTile` 等）加背景色时，必须用 `Material(color: ..., child: ...)` 作为色层宿主，**禁止**用 `ColoredBox` / `DecoratedBox` 包裹。

```dart
// ❌ 禁止：ColoredBox 遮挡 ink splash
ColoredBox(
  color: colors.surface,
  child: InkWell(onTap: ..., child: ...),
)

// ✅ 推荐：Material 作为色层宿主
Material(
  color: colors.surface,
  child: InkWell(onTap: ..., child: ...),
)
```

**已修复位置**（参考样板）：
- `lib/features/chat/presentation/widgets/chat_sidebar.dart` 侧边栏根容器
- `lib/features/chat/presentation/widgets/session_settings_sheet.dart` BottomSheet 根容器
- `lib/features/intermediate/presentation/widgets/intermediate_session_settings_sheet.dart`
- `lib/features/diagnostics/presentation/pages/diagnostics_page.dart`

**Code review 检查点**：新增/修改 UI 代码时，若 `InkWell` / `ListTile` 的父级链上有 `ColoredBox` / `DecoratedBox` 带背景色，必须改为 `Material`。

```dart
// lib/core/theme/theme_controller.dart

/// 主题模式（浅色/深色/跟随系统）
final themeModeProvider = StateNotifierProvider<ThemeModeNotifier, ThemeMode>(...);

/// 应用模式（Simple/Intermediate/Advanced）
enum AppMode { simple, intermediate, advanced }
final appModeProvider = StateNotifierProvider<AppModeNotifier, AppMode>(...);

/// 根据 mode + brightness 解析 ThemeData
ThemeData resolveTheme(AppMode mode, Brightness brightness) {
  switch (mode) {
    case AppMode.simple:
      return brightness == Brightness.light
          ? SimpleTheme.lightTheme : SimpleTheme.darkTheme;
    case AppMode.intermediate:
      // 中级模式只有暗色主题（夜航），亮色主题 v0.3 补齐
      return IntermediateTheme.darkTheme;
    case AppMode.advanced:
      // v0.3 实现，基于 intermediate 扩展
      return IntermediateTheme.darkTheme;
  }
}
```
