# 前端组件接口层（LmComponentKit）现状盘点

> 用途：LmComponentKit（业务代码只依赖抽象组件接口，每套外观结构提供一套实现）接口设计的输入。
> 全部断言提取自真实代码（2026-09-23 时点快照），逐条带 file:line，无臆测。
> 路径约定：`ROOT` 指仓库根目录，下文 `ROOT\lib\...` 均为仓库根目录下的相对路径。
> 统计口径：lib\features 全体 `*.dart`，字边界匹配（`GlassCard(` 不计入 `Card(`）。

---

## §0 一句话总览

仓库现状是「**结构轴（classic / glass / brutal）× 模式轴（对话 / 故事 / 导演）**」两张正交的网：

- 结构轴的 **ThemeData 装配**由 `ThemeCatalog` 统一注册（`ROOT\lib\core\theme\system\theme_catalog.dart:38-53`），三结构各自产出一份全局主题（ClassicStructure / GlassStructure / BrutalStructure 均实现 `LmStructure.assemble`）。
- 结构轴的 **组件工厂**只有玻璃（18 件）与棱角（8 件）两套；经典结构没有工厂组件，它的"组件"是 **模式组件库**（classic\conversation = 对话模式、classic\narrative = 故事/中级模式），全量经 `context.lm.palette` 取色，**不随结构轴换实现**。
- 已有的结构分流失点是散落的 `context.isGlassSurface / isBrutalSurface` if-分支 + 一个先行范式 `AdaptiveSettingCard`（三结构同调用面，见 §3.4）。

### §1.3 经典结构 = ThemeData 骨架 + 模式组件库

`ClassicStructure`（`ROOT\lib\core\theme\system\structures\classic\classic_structure.dart:32`，443 行）**只装配 ThemeData**（唯一 `ThemeData(` 构造点 ：77，明暗差异仅 brightness/colorScheme 两项 ：48-73），**不产出任何 widget**。经典结构的"组件"由两套模式组件库承担（§2）；琉璃/棱角结构下这些模式组件**原样沿用**，仅经 `context.lm.palette` 换色（另有 3 处 `lmSettingCardFace`/`scaffoldBgOf` 槽位微调，见 §3.3）。

组件数量对比：玻璃 18 工厂、棱角 8 工厂、classic\conversation 公开组件 13 类、classic\narrative 公开组件 20+ 类（详表 §2）。三套的**重合词汇**只有：卡片、按钮、输入容器、chip、横幅、snackBar、模态（玻璃/棱角两工厂间）；**会话核心面（气泡、输入区、会话卡、空状态、AppBar、消息导航）只存在于模式组件库，两套工厂均无对应物**。

## §5 接口设计的坑位提示（如实罗列）

1. **聊天核心面无工厂覆盖**：气泡、输入区、会话卡、AppBar、空状态、消息导航只存在于模式组件库；玻璃 18 工厂/棱角 8 工厂均无对应物。接口若以两工厂为蓝本，聊天页将无件可换。
2. **两工厂覆盖不齐**：棱角缺 listRow/settingRow/segmented/tag/sectionHeader/divider/readingCard/bottomSheet/floatingBar；玻璃缺 checkbox/dialog 有·无按钮分歧（Glass 无 checkbox、Brutal 无 segmented/snackBar 内容件以外的浮条）。接口抽象需先对齐闭集。
3. **领域实体倒灌结构层**：`SimpleSessionCard` 吃 `ChatSession`（simple_session_card.dart:24）、`SimpleTemplateCard` 吃 `Template`（simple_template_card.dart:18）、气泡吃 `ChatMessage`；theme 层反向依赖 features 领域实体，接口化时必须打断（改为数据参数或回调）。
4. **`colors`/`t` 线程参数 vs context 自取两派并存**：factual_memory\ 全系与 bubble\ 子件要求显式传 `colors: LmPalette` 与 `t: Translations`（如 factual_entity_card.dart:117-118），Simple/Intermediate 主件则内部 `context.lm.palette`；同一接口里必须统一。
5. **三套"设置行/卡"API 漂移**：SimpleSettingCard（无 enabled）、IntermediateSettingCard（+enabled）、GlassSettingRow（String value 槽+chevron 内建）、BrutalCard+手写 Row（AdaptiveSettingCard 内）——语义同源参数各异。
6. **命名三重错位**："classic" 既是结构 id 又是组件目录名；目录内 conversation=旧"Simple"模式、narrative=旧"Intermediate"模式；而 narrative 件已被**导演（advanced）模式复用**（director_chat_body.dart:941 用 IntermediateMessageBubble、advanced_chat_page.dart:653 用 IntermediateChatInput）——模式前缀名不副实。
7. **死代码**：`SimpleTemplateCard` 全仓 0 消费者（仅自身定义文件命中）；`SimpleForkNav`、`CompactionFailedCard`、`SimpleCodeBlock`、`SafeLatexElementBuilder` 仅被气泡/Markdown 内部装配，对外不可见但占公开命名空间。
8. **SnackBar 未收口**：92 处裸 `SnackBar(` 分布 34 文件、各页私建 `_showSnack` helper（resource_library_page.dart 甚至保留 `_showSnack/_showSnackFloating` 双别名 :303/:317）；`GlassSnackBar`/`BrutalSnackBar` 内容件**无任何消费路径**（不存在 `showLmSnackBar` 入口）。这是浮层三兄弟（dialog/sheet 已收口）里唯一漏网。
9. **确认弹窗三种形态**：static show 工厂（IntermediateConfirmDialog.show、MemoryDetailDialog.showEventSummary/showExperientialMemory、FactualDetailDialog.show、FactsChangeDetailDialog.show、showFactualSimilarClustersSheet/showFactualMergePreviewDialog）、裸 StatefulWidget（IntermediateEditDialog）、showLmDialog+AlertDialog 手写（resource_library_page.dart:271）。
10. **状态机复制**：`_GlassInteractive`（glass_factories.dart:138-224）与 `_BrutalInteractive`（brutal_factories.dart:60-146）是逐行同构的五态采集器（含同一 `_activationShortcuts` 键绑定）；接口层可把"五态契约"提升为公共抽象，两结构只实现视觉映射。
11. **内联结构分支待收编**：home_page.dart:375-394、sidebar_session_item.dart:96-124 的 if(glass)/else if(brutal) 三分逻辑与 AdaptiveSettingCard 范式重复，同一"选中/悬停面"语义至少 3 处手写。
12. **隐私垫片层**：simple\components 与 intermediate\components 共 56 个单行 re-export 垫片仍在被业务 import（chat_mode_page.dart:7-8 等）；接口层落地时需决定垫片去留与迁移路径。
13. **参数粒度失衡**：ChatModeInputArea 19 参、SimpleMessageBubble 24 参、FactualSearchHeader 13 参 vs GlassPillButton 6 参——"聚合大件"与"原子小件"若进同一接口需要分层（页面级区块 vs 基元控件）。
14. **气泡行为旗标堆积**：SimpleMessageBubble 把 fork/compaction/search 等正交能力全堆在构造参数（:56-71），接口化时宜拆能力接口或配置对象，否则玻璃/棱角实现将被 24 参签名绑架。
