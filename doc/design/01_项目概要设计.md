## 1. 项目定位

LMStory 是一个世界叙事引擎：本地优先、可自配模型供应商的 AI 对话与长篇故事应用。当前交付三种用户体验：

- **对话模式**（代码历史名 Simple / Chat）：通用多模型对话、会话管理、分支、附件、上下文压缩与生成参数控制。
- **故事模式**（代码内部名 Intermediate）：在对话基础上增加分阶段生成、经历记忆、事实记忆、混合检索、失败恢复和故事专属界面。
- **导演模式**（代码标识 `advanced`，实验性）：AI 作为幕后执行者按「项目规则」运转世界，正文是唯一成果；具备过程分层（台前/幕后）、请示导演/审批、纠偏、监督模式、事件日志与重启恢复等能力。内核位于 `lib/features/advanced/`，与故事模式共享 `lib/features/story_runtime/` 运行时。

首页入口默认为「新对话」「新导演」并排双卡（「新导演」由 `advancedModeFlagProvider` 门控，v0.4.0 起默认开启，可在设置中关闭）；故事模式入口默认隐藏（设置 → 故事模式设置 开启后，首页回到「新对话/新建故事」双竖卡 + 「新导演」横卡布局）。

## 3. 故事模式主流程

一轮故事处理的可观察阶段为：

```text
compacting? → extracting → retrieving → generating
            → reviewing? → summarizing → persisting
```

- `compacting` 与 `reviewing` 按配置和上下文条件出现。
- 常规情况下包含 3 次 AI 调用；启用审查时为 4 次。检索与持久化是本地阶段，因此“四步生成”只可作为历史产品名，不能理解为完整状态机只有四个阶段。
- `extracting` 提取检索关键词；`summarizing` 生成事件摘要并提取事实变更。
- 持久化整体在 drift 事务内完成；事实变更由 `FactApplier` 按单条 delta 容错，因此某条无效事实可能被跳过，而经历记忆仍可写入。

导演模式另提供独立的历史正文搜索（`search_story_text`）：摘要不足以核实时直接扫描已保存原文，按关键词定位轮号后回读，不受记忆评分与工作上下文压缩边界影响，不新增数据库表或索引。

## 4. 记忆模型

### 4.1 经历记忆

经历记忆记录“发生过什么”，以追加为主。检索结合 FTS5 与纯 Dart 向量相似度，并叠加时效、重要性和宏摘要等信号。

两类摘要不得混写：

- **累积压缩摘要**：替代过早对话原文，维持当前上下文连续性。
- **分段宏摘要**：聚合连续事件，参与长期记忆检索。

### 4.2 事实记忆

事实记忆记录“现在是什么”，由实体、属性和审计历史组成。实体类型为 `character`、`location`、`item`、`lore`、`organization`、`misc`；旧 `npc` / `pet` 输入仅作为兼容值映射到 `character`。

## 5. 系统结构

代码以 feature-first + Clean Architecture 为目标组织：

```text
lib/
├── core/                 # 数据库、网络、配置、日志等共享基础
├── features/
│   ├── chat/             # 对话与共享会话基础、外壳路由（main_layout）
│   ├── intermediate/     # 故事流程（历史内部命名）
│   ├── advanced/         # 导演模式（AgentRunner/工具/事件日志/导演 UI）
│   ├── story_runtime/    # 故事与导演模式共享运行时（压缩/持久化/失败分类等）
│   ├── resource_library/ # 世界书/角色卡资源库（导入/应用/投影）
│   ├── memory/           # 经历/事实记忆
│   ├── settings/         # 供应商、模型与应用设置
│   ├── templates/        # 提示词模板
│   ├── help/             # 应用内 Wiki
│   ├── onboarding/       # 新手引导
│   └── diagnostics/      # 日志与失败诊断
└── i18n/                 # 当前仅 zh-CN
```

现存部分 `core` 对 feature/domain 的反向引用属于待收敛的历史例外，不能据文档绝对声称依赖边界已经完全满足。

## 6. 配置、数据与平台

- 数据管理的覆盖导入与同一数据库上的聊天生成互斥，保护贯穿备份快照和实际写入。会话正在准备、生成或收尾时，页面提示等待完成或停止后重试。覆盖期间新发送被拒时可以保留输入，演示库和正常库独立。
- 覆盖仅替换备份含有且可应用的域。受影响域已有数据时，先验证无 API Key 的可读快照。各 SQLite 域在同一事务提交。偏好与显式导入的密钥另存写前值，异常时补偿并读回校验，校验失败交给现有备份恢复入口。
- 原生启动先检查数据库文件。已有有效 SQLite 签名的库在首次可写打开前，将主文件和已有 WAL、SHM 或回滚日志一起复制到同级目录。正常打开及升级继续使用原路径并删除本次副本。开库失败时关闭执行器，保留副本并在恢复页显示位置。重试仍打开活动路径，历次失败留下的副本独立保存。暂存失败时显示文件及空间提示，等待用户处理后重试。
- 开库失败时从启动界面选取已有快照或本地备份。纯元数据和格式错误的备份有独立提示。原生在隔离库试恢复，按会话核对正文、事实、流水与经历的读回，并提示跳过条目。确认后以激活记录选择恢复库与对应设置。Web 支持选择或检查浏览器快照及本地文件。
- `assets/configs/default_config.json` 提供共享默认值；会话覆盖、兼容字段、平台差异和运行期解析仍由代码处理。
- 当前数据库 `schemaVersion = 43`。v32/v33 采用 `review_*`、`generating_*`、`reviewing_*` 命名；v38 引入导演模式 `agent_events` 事件日志表；升级和“修复表结构”走 additive `repairSchema`，不应按旧稿清库重建。
- 本地数据库是用户数据权威来源；密钥使用平台安全存储。Web 的存储和跨域行为受浏览器环境限制。

## 7. 后续方向

Advanced（导演模式）已于 v0.3.0 实现为实验性模式（见第 1、2 节与 `doc/design/v0.3.0/`）。仍在推进的方向：digest 摘要替换、导演模式真机验收与打磨、World 一级领域对象讨论（与世界书深化一起评估）。（durable surface prune 议题已随 `agent_surface_pruner` 删除收束。）

以下内容明确不再作为后续要求：独立 HUD、HUD 专用 `update_world` 双写、`state_patch` 展平、单表 `factual_memories`、`state_snapshots`、`06C` HUD 视觉稿。若未来需要模型主动调用写事实工具，必须重新设计权限、事务、审计和用户可见反馈，不能直接复用旧蓝图。

## 8. 验收原则

1. README、CLAUDE、贡献指南、设计文档、术语字典和应用内 Wiki 对当前能力使用同一口径。
2. “已实现”“计划中”“已废弃”“历史快照”必须显式区分。
3. Schema、配置键、协议列表和 UI 入口以可运行代码验证。
4. 修改 `zh_CN.i18n.yaml` 后必须重新运行 `dart run slang`；当前没有英文 locale，不得用中文 key 数量冒充英文覆盖率。
