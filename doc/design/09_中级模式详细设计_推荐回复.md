## 7A. 输入框工具栏与推荐回复交互

### 7A.1 IntermediateChatState 新增字段

推荐回复功能在 `IntermediateChatState` 新增 3 个字段（2026-07-29 新增）：

```dart
class IntermediateChatState {
  // ... 原有字段（见 DOC-09B §7.1）...

  /// 推荐回复候选列表（2026-07-29 新增）
  /// 由 generateSuggestReplies() 填充，closeSuggest() / sendMessage() 清空。
  /// 空列表 + isGeneratingSuggest=false 表示生成失败。
  final List<String> suggestReplies;

  /// 是否正在生成推荐回复（2026-07-29 新增）
  /// true 时 InputToolbar 推荐按钮显示 loading 且禁用重复点击。
  /// 生成期间用户仍可正常输入和发送消息（不阻塞原则）。
  final bool isGeneratingSuggest;

  /// 推荐回复浮层是否展开（2026-07-29 新增）
  /// true=展开显示所有候选气泡；false=折叠为单行 chip。
  /// 折叠态保留 suggestReplies 数据可恢复，避免重复生成浪费 token。
  final bool suggestExpanded;
}
```

**字段状态转换**：

| 操作 | suggestReplies | isGeneratingSuggest | suggestExpanded |
|------|---------------|--------------------|----------------- 
| 初始态 | `[]` | false | false |
| 点击推荐按钮 | `[]`（清空旧候选） | true | false |
| 生成成功 | `[回复1, 回复2, 回复3]` | false | true（自动展开） |
| 生成失败 | `[]` | false | false |
| 点击折叠 | 不变 | 不变 | false |
| 点击展开 | 不变 | 不变 | true |
| 点击候选 | 不变（不清空，可再选） | 不变 | 不变 |
| 点击关闭 × | `[]` | false | false |
| 发送消息 | `[]` | false | false |

### 7A.2 工具栏交互逻辑

输入框上方的 `IntermediateInputToolbar`（视觉规范见 DOC-06B §6.6A）提供 3 个按钮：

**按钮 1 — 添加引号**（`format_quote_outlined`）：
- 点击后在输入框光标位置插入成对英文引号 `""`
- 光标自动定位到引号中间，方便用户直接输入对话内容
- 始终可用，不依赖会话状态

**按钮 2 — 添加括号**（`rounded_corner`）：
- 点击后在输入框光标位置插入成对英文括号 `()`
- 光标自动定位到括号中间
- 始终可用，不依赖会话状态

**按钮 3 — 推荐回复**（`auto_awesome_outlined`）：
- 点击触发 `controller.generateSuggestReplies()`
- **可用条件**：`state.messages.isNotEmpty`（需至少 1 轮历史消息）+ `!state.isGeneratingSuggest`（非生成中）
- **不可用时**：onPressed=null，图标/文字变 faint 色
- **生成中**：图标替换为 14×14 CircularProgressIndicator，onPressed=null
- 设置 Tooltip 帮助初次用户识别功能

### 7A.3 推荐浮层交互

`SuggestReplyOverlay`（视觉规范见 DOC-06B §6.6B）在输入框上方浮出，由 `state.suggestReplies` / `isGeneratingSuggest` / `suggestExpanded` 三字段驱动：

**展开/折叠**：
- 生成成功后自动展开（`suggestExpanded=true`）
- 点击头部折叠/展开按钮 → `controller.toggleSuggest()` 切换 `suggestExpanded`
- **折叠态保留数据**：`suggestReplies` 不清空，用户可再次展开查看，避免重复生成浪费 token
- 折叠态显示为单行 chip（lightbulb_outline + "{n} 条推荐回复" + expand_more）

**关闭**：
- 点击头部 × 按钮 → `controller.closeSuggest()` 完全清空（suggestReplies=[] + isGeneratingSuggest=false + suggestExpanded=false）
- 与折叠的差异：折叠保留数据可恢复，关闭完全清空

**候选选择**：
- 点击展开态的候选气泡 → `controller.selectSuggestReply(index)` 返回选中回复文本
- UI 层将文本插入到输入框光标位置
- **不清空 suggestReplies**——用户可能想再次选择其他候选

### 7A.4 生命周期

**不阻塞原则**：推荐回复生成期间用户仍可正常输入和发送消息。用户发送消息时 `sendMessage()` 会清空 `suggestReplies`，正在进行的生成结果作废（不报错，静默丢弃）。

**自动关闭时机**：
- 用户发送消息（`sendMessage`）→ 清空候选（本轮结束）
- 用户编辑重发（`editAndResend`）→ 清空候选（本轮结束）
- 用户点击 × 关闭 → 清空候选

**不会自动关闭的时机**：
- 切换会话（Controller autoDispose 保活，但 state 重置时 suggestReplies 随之清空）
- 阶段切换（generating/extracting/reviewing 等不影响推荐浮层；v0.2.2 阶段名重命名：drafting→generating、revising→reviewing）

## 10A. 推荐回复配置参数

### 10A.1 全局配置 `intermediate.suggest_reply.*`

`default_config.json` 的 `intermediate.suggest_reply` 子节点（7 项参数）：

```json
{
  "intermediate": {
    "suggest_reply": {
      "preset_id": "",
      "model_id": "",
      "prompt": "",
      "temperature": 0.8,
      "max_tokens": 600,
      "candidate_count": 3,
      "max_reply_length": 150
    }
  }
}
```

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| preset_id | String | ""（空串） | 推荐回复专用供应商 ID。空串=未配置，fallback 到 generating 阶段供应商。持久化 key: `intermediate.suggest_reply.preset_id` |
| model_id | String | ""（空串） | 推荐回复专用模型 ID。空串=未配置，fallback 到 generating 阶段模型。推荐使用小模型降低成本（推荐回复是轻量任务）。持久化 key: `intermediate.suggest_reply.model_id` |
| prompt | String | ""（空串） | 推荐回复系统提示词。空串=未配置，回落到内置默认 `kSuggestReplyDefaultPrompt`（定义在 `core/config/intermediate_prompts_v2.dart`）。持久化 key: `intermediate.suggest_reply.prompt` |
| temperature | double | 0.8 | 生成温度（0.0-2.0） |
| max_tokens | int | 600 | 单次生成最大 token 数，所有候选共用；可配置 |
| candidate_count | int | 3 | 候选回复数量。默认 3 条，LLM 输出 JSON 数组 `{"replies": ["...", "...", "..."]}`，解析后截断/补齐到此数量 |
| max_reply_length | int | 150 | 单条候选回复默认最大字符数；可配置 |

> **省 token 设计**：推荐回复是辅助功能，单次非流式调用（禁用 reasoning），预估 500-800 token/次。上下文仅传最近 1 轮全文 + 前 2 轮 micro 摘要，不传完整历史。

> **`SuggestReplyConfig` 实体**：上述 7 字段由 `SuggestReplyConfig.fromJson` 反序列化（`core/config/intermediate_config.dart`）。用户覆盖通过 `SettingsRepository` user_overrides 机制（key 前缀 `intermediate.suggest_reply.*`），由 `ConfigLoader._expandFlatKeys` + `_deepMerge` 展开合并。

### 10A.2 会话级覆盖

`chat_sessions` 表新增 3 列（schemaVersion=30，详见 DOC-02 §6.1/§6.5），支持会话级推荐回复配置覆盖：

| 字段 | 类型 | 说明 |
|------|------|------|
| `suggest_reply_preset_id` | TEXT NULLABLE | 推荐回复会话级供应商 ID。NULL=使用全局 `intermediate.suggest_reply.preset_id`，仍空则 fallback 到 generating 阶段供应商 |
| `suggest_reply_model_id` | TEXT NULLABLE | 推荐回复会话级模型 ID。NULL=使用全局 `intermediate.suggest_reply.model_id`，仍空则 fallback 到 generating 阶段模型 |
| `suggest_reply_prompt_override` | TEXT NULLABLE | 推荐回复会话级提示词覆盖。NULL=使用全局 `intermediate.suggest_reply.prompt`，仍空则使用内置默认 `kSuggestReplyDefaultPrompt` |

**优先级链**（两级 + fallback）：

```
模型解析（resolveSuggestReplyNamingConfig）：
  会话级 suggest_reply_preset_id/model_id
    → 全局 intermediate.suggest_reply.preset_id/model_id
      → generating 阶段模型（resolveIntermediatePhaseNamingConfig(session, 'generating')）
        → null（所有层级均未配置，禁用推荐按钮）

提示词解析（resolveSuggestReplyPrompt）：
  会话级 suggest_reply_prompt_override
    → 全局 intermediate.suggest_reply.prompt
      → 内置默认 kSuggestReplyDefaultPrompt
```

> **会话设置面板暴露**：3 字段在 `IntermediateSessionSettingsSheet` 区段 7「推荐回复」暴露（视觉规范见 DOC-06B §6.8）。会话物化时由 `snapshotIntermediateDefaults()` 快照全局值到会话字段（与区段 1-5 一致的快照语义）。

> **全局设置子页**：`IntermediateSuggestReplySettingsPage`（视觉规范见 DOC-06B §6.19）提供全局配置入口，3 区块（模型配置 / 提示词 / 生成参数）。

## 7A.5 IntermediateChatController 新增方法时序

`IntermediateChatController` 新增 4 个推荐回复方法（2026-07-29 新增）：

### generateSuggestReplies() → Future<bool>

**职责**：调用 LLM 生成 3 条候选回复，写入 state。

```
1. 守卫检查
   ├── isGeneratingSuggest == true → return false（拒绝重复点击）
   └── messages.isEmpty → return false（无历史消息无法生成）

2. 提取上下文
   ├── lastUserMsg = messages.lastWhere(role == 'user')
   ├── lastAssistantMsg = messages.lastWhere(role == 'assistant')
   └── 内容为空 → return false

3. 置生成中状态
   └── state = state.copyWith(isGeneratingSuggest: true, suggestReplies: [], suggestExpanded: false)

4. 解析模型配置
   ├── namingConfig = ConfigurationResolver.resolveSuggestReplyNamingConfig(session)
   └── namingConfig == null → state.isGeneratingSuggest = false, return false

5. 解析提示词
   └── systemPrompt = ConfigurationResolver.resolveSuggestReplyPrompt(session)

6. 提取前 2 轮 micro 摘要
   └── prevSummaries = experientialMemories.where(level == 'micro').takeLast(2).map(summary)

7. 调用 SuggestReplyGenerator.generate()
   ├── LLM 单次非流式调用（禁用 reasoning，responseFormat=JSONObject）
   └── 超时 20 秒

8. 解析 JSON {"replies": ["...", "...", "..."]}
   └── 失败/空 → state.isGeneratingSuggest = false, return false

9. 写入 state，自动展开
   └── state = state.copyWith(isGeneratingSuggest: false, suggestReplies: replies, suggestExpanded: true)
   └── return true
```

**不阻塞原则**：生成期间用户仍可正常输入和发送消息。`sendMessage()` 会清空 `suggestReplies`，生成结果作废。

### selectSuggestReply(int index) → String?

**职责**：返回选中的回复文本，由 UI 层插入到输入框光标位置。

```
1. 越界检查
   └── index < 0 || index >= suggestReplies.length → return null

2. 返回候选文本
   └── return suggestReplies[index]
```

**不清空** suggestReplies——用户可能想再次选择其他候选。完全清空由 `closeSuggest()` 或 `sendMessage()` 负责。

### toggleSuggest() → void

**职责**：切换浮层展开/折叠状态。

```
1. 空列表守卫
   └── suggestReplies.isEmpty → return（无候选可切换）

2. 切换展开状态
   └── state = state.copyWith(suggestExpanded: !state.suggestExpanded)
```

**折叠态保留数据**：`suggestReplies` 不清空，用户可再次展开查看，避免重复生成浪费 token。

### closeSuggest() → void

**职责**：完全清空推荐回复状态。

```
1. 清空所有字段
   └── state = state.copyWith(suggestReplies: [], isGeneratingSuggest: false, suggestExpanded: false)
```

**与 toggleSuggest 的差异**：折叠保留数据可恢复，关闭完全清空。
