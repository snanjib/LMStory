## 1. 设计目标

1. **文本与代码分离**：所有用户可见文本（UI 标签、按钮、提示、错误消息）从代码中提取到独立翻译文件，禁止硬编码
2. **类型安全**：翻译 key 拼写错误或参数类型错误在编译期报错，而非运行时崩溃
3. **动态语言切换**：用户可在设置中切换语言，立即生效，无需重启应用
4. **渐进式支持**：v0.1 仅中文（zh-CN），但框架一步到位；后续添加新语言零重构
5. **全层覆盖**：Presentation 层 + Domain 层（错误码映射）均可使用翻译，不依赖 BuildContext

## 2. 技术选型：slang

### 2.1 选型理由

| 维度 | slang | gen_l10n | easy_localization | i18n_extension |
|------|-------|----------|-------------------|----------------|
| 类型安全 | ★★★★★ | ★★★★ | ★★ | ★★★ |
| Domain 层可用 | ✅ 纯 Dart | ✅ 纯 Dart | ❌ 需 BuildContext | ❌ 需 BuildContext |
| 嵌套命名空间 | ✅ 按 feature 组织 | ❌ 扁平结构 | ❌ 扁平结构 | ❌ 内联定义 |
| Riverpod 兼容 | ✅ 全局单例 | ✅ 需手动桥接 | ⚠️ 需 widget 包裹 | ⚠️ 需 widget 包裹 |
| Fallback 链 | ✅ zh_Hant→zh→en | ✅ | ✅ | ❌ |
| 维护稳定性 | ★★★★ | ★★★★★ | ★★★ | ★★ |

**关键决策因素**：
- slang 是纯 Dart 生成代码，Domain 层可直接使用（符合 Clean Architecture）
- 嵌套命名空间与 Feature-first 目录结构天然匹配
- 编译期 key 校验 + 参数类型检查，与 `very_good_analysis` 严格 lint 一致
- v0.1 仅需一个 `strings.i18n.yaml`（中文），后续添加语言零成本

## 3. 翻译文件管理体系

### 3.1 目录结构

```
lib/
  i18n/
    strings.i18n.yaml              # 默认语言（zh-CN）主翻译文件
    strings_en.i18n.yaml           # 英文翻译（v0.2+）
    strings_ja.i18n.yaml           # 日文翻译（v0.2+）
    _translations.g.dart           # slang 自动生成（勿手动编辑）
    _strings.g.dart                # slang 自动生成
```

> **设计决策**：翻译文件集中在 `lib/i18n/` 而非分散到各 feature 目录。原因：
> 1. 翻译文件需整体交付给翻译人员，集中管理更高效
> 2. slang 的命名空间机制已支持按 feature 逻辑分组
> 3. 避免翻译 key 在多个 feature 间重复或冲突

### 3.3 翻译 key 命名规范

| 规则 | 说明 | 示例 |
|------|------|------|
| 顶层按 feature 分组 | 对应 `features/` 目录结构 | `chat.*`, `settings.*`, `tabs.*` |
| 第二层按页面/组件分组 | 对应页面或组件 | `chat.branch.*`, `settings.provider.*` |
| 使用 camelCase | 与 Dart 命名一致 | `apiKeyStatus`, `fetchError` |
| 布尔/状态用形容词 | is/has 前缀 | `isSet`, `hasError` |
| 含参数用描述性名称 | 参数名与 key 语义匹配 | `branch.indicator(current, total)` |
| 通用文本放 `common` | 跨 feature 复用 | `common.confirm`, `common.cancel` |
| 验证消息放 `validation` | 表单验证专用 | `validation.required` |
| 错误消息放 `error` | 通用错误码映射 | `error.unauthorized` |

### 3.4 参数插值规范

## 4. 代码集成方案

### 4.1 初始化

```dart
// lib/i18n/i18n.dart
import 'package:slang/slang.dart' as slang;
import 'package:slang_flutter/slang_flutter.dart';

/// 初始化国际化系统
///
/// 在 main() 中调用，必须在 runApp() 之前。
/// [savedLocale] 从 SharedPreferences 读取的用户语言偏好，
/// 若为 null 则使用系统语言。
Future<void> initI18n({Locale? savedLocale}) async {
  if (savedLocale != null) {
    LocaleSettings.setLocale(savedLocale.toSlangLocale());
  } else {
    // 使用系统语言，fallback 到 zh-CN
    await LocaleSettings.useDeviceLocale();
    final supported = AppLocale.values;
    final device = LocaleSettings.currentLocale;
    if (!supported.contains(device)) {
      LocaleSettings.setLocale(AppLocale.zhCn);
    }
  }
}
```

### 4.2 MaterialApp 集成

```dart
// lib/main.dart
import 'package:flutter/material.dart';
import 'package:flutter_riverpod/flutter_riverpod.dart';
import 'package:flutter_localizations/flutter_localizations.dart';

  WidgetsFlutterBinding.ensureInitialized();

  // 初始化 i18n（从 SharedPreferences 读取保存的语言偏好）
  final savedLocale = await _loadSavedLocale();
  await initI18n(savedLocale: savedLocale);

  runApp(
    const ProviderScope(
      child: MyApp(),
    ),
  );
}

class MyApp extends ConsumerWidget {
  const MyApp({super.key});

  @override

    final locale = ref.watch(localeProvider);

    return MaterialApp(
      title: 'LMStory',

      supportedLocales: AppLocale.values.map((e) => e.flutterLocale),
      localizationsDelegates: const [
        GlobalMaterialLocalizations.delegate,
        GlobalWidgetsLocalizations.delegate,
        GlobalCupertinoLocalizations.delegate,
      ],
      home: const MainLayout(),
    );
  }
}
```

### 4.3 Riverpod Provider

```dart

/// 当前语言 Provider
///
/// 监听此 provider 可在语言切换时自动重建 UI。
/// 切换语言时调用 [switchLocale]。
@riverpod
class Locale extends _$Locale {
  @override
  AppLocale? build() {
    // 返回 null 表示使用系统语言
    return LocaleSettings.currentLocale;
  }

  /// 切换语言
  ///
  /// 同时持久化到 SharedPreferences，下次启动时恢复。
  Future<void> switchLocale(AppLocale locale) async {
    LocaleSettings.setLocale(locale);
    state = locale;

    // 持久化语言偏好
    final prefs = await SharedPreferences.getInstance();
    await prefs.setString('locale', locale.languageTag);
  }

  /// 重置为系统语言
  Future<void> resetToSystem() async {
    await LocaleSettings.useDeviceLocale();
    state = null;

    final prefs = await SharedPreferences.getInstance();
    await prefs.remove('locale');
  }
}

/// 便捷访问：获取当前 locale 的 flutter Locale 对象
@riverpod
Locale flutterLocale(Ref ref) {
  final appLocale = ref.watch(localeProvider);
  return (appLocale ?? LocaleSettings.currentLocale).flutterLocale;
}
```

```dart

  ///
  /// 此方法在 Domain 层使用，不依赖 Flutter/BuildContext。
  static String mapUserMessage(String errorCode, {Map<String, dynamic>? params}) {

      'SERVER_ERROR' => t.error.serverError,
      'NOT_FOUND' => t.error.notFound,
      'TIMEOUT' => t.error.timeout,
      'DB_ERROR' => t.error.dbError,
      _ => t.error.generic,

  }
```

## 6. 动态语言切换机制

### 6.1 切换流程

```
用户在 GeneralSettingsPage 选择语言
    │
    ├── 1. 调用 ref.read(localeProvider.notifier).switchLocale(AppLocale.en)
    │
    ├── 2. LocaleSettings.setLocale(AppLocale.en)
    │   └── slang 内部更新全局翻译实例
    │
    ├── 3. localeProvider 状态更新
    │   └── MaterialApp.locale 变更 → 触发 widget tree 重建
    │
    ├── 4. 持久化到 SharedPreferences
    │   └── key: 'locale', value: 'en'
    │
    └── 5. 所有使用 Translations.of(context) 的 Widget 自动更新
```

### 6.2 语言偏好存储

| 存储位置 | Key | 值 | 说明 |
|---------|-----|-----|------|
| SharedPreferences | `locale` | `zh-CN` / `en` / `ja` / null | null 表示跟随系统 |

### 6.3 启动时语言恢复

```dart
Future<Locale?> _loadSavedLocale() async {
  final prefs = await SharedPreferences.getInstance();
  final tag = prefs.getString('locale');
  if (tag == null) return null;
  return AppLocale.parse(tag).flutterLocale;
}
```

## 8. 版本管理与更新流程

### 8.1 翻译文件变更流程

```
开发人员新增/修改 UI 文本
    │
    ├── 1. 在 strings.i18n.yaml 中添加/修改 key-value
    │
    ├── 2. 运行 dart run slang 生成代码
    │   └── 编译期校验：key 拼写、参数类型、缺失翻译
    │
    ├── 3. 若新增 key，同步到其他语言文件（strings_en.i18n.yaml 等）
    │   └── 暂无翻译的 key 留空或使用英文占位
    │
    ├── 4. 提交翻译文件 + 生成代码到 Git
    │
    └── 5. CI 中运行 dart run slang verify 确保无缺失翻译
```

### 8.2 翻译完整性校验

```bash
# 检查所有语言文件是否包含默认语言的全部 key
dart run slang verify

# 输出示例：
# ✅ zh-CN: 156 keys (default)
# ⚠️ en: 152 keys (4 missing: chat.branch.switchLeft, ...)
# ❌ ja: 0 keys (not started)
```

### 8.3 Git 管理规范

| 规则 | 说明 |
|------|------|
| 翻译文件纳入 Git | `strings.i18n.yaml` + 生成代码均提交 |
| 生成代码不手动编辑 | `_strings.g.dart` / `_translations.g.dart` 由 slang 生成 |
| 每次功能提交包含翻译 | 新增 UI 文本时同步更新翻译文件 |
| CI 校验 | `dart run slang verify` 作为 CI 步骤 |
