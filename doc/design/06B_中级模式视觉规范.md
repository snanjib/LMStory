## 1. 视觉定位与设计哲学

### 1.1 两个产品的设计理念

LMStory 采用"两个产品"架构：Simple 模式是**工具**（克制、高效、消失于任务），中级/高级模式是**体验**（沉浸、氛围、有存在感）。两者共享基础零件（间距、圆角、原子组件），但视觉语言完全独立。

| 维度 | Simple 模式（DOC-06A） | 中级模式（本文档） |
|------|----------------------|------------------|
| 设计哲学 | 工具消失于任务——克制、安静 | 沉浸式叙事——氛围感、仪式感 |
| 色彩策略 | Restrained（亮色基调，≤10% 强调色） | Restrained（暗色基调，≤10% 强调色） |
| 主题基调 | 亮色为主（Daylight/Twilight） | 暗色沉浸（夜航） |
| 字体 | 无衬线（Inter） | 衬线（消息内容）+ 无衬线（UI 元素） |
| 冲击力 | 无（一致性优先） | 进入时刻 + 交互过程仪式感 |

### 1.2 使用场景

- **什么时候用**：晚上居多，用户想逃离日常进入故事世界
- **环境**：窝在沙发或被窝，可能戴耳机，只有手机屏幕的光
- **心情**：想要"被带入感"，不想被界面提醒"这是个 App"
- **设备**：手机竖屏为主

场景强烈指向**暗色为主**：亮色在晚上刺眼，暗色营造"钻进故事里"的氛围，且与 Simple 模式亮色形成反差，进入即冲击。

### 1.3 色彩策略

采用 **Restrained** 策略：暗色基调（深蓝黑 bg/surface，低彩度着色中性）+ 单一琥珀金强调色 ≤10% 表面。琥珀金仅用于主按钮、选中态、关键高亮，其余皆为低彩度深蓝黑层次。既有冲击力又不花哨，保留可读性。

> **与 Simple 模式的差异**：两模式均为 Restrained，差异不靠色彩 commitment 级别，而靠四维对位：
> 1. **明度反转**：Simple 亮色（暖米白底），中级暗色（深蓝黑底）——进入即反差
> 2. **强调色相**：Simple 靛蓝（冷），中级琥珀金（暖）——冷暖对位
> 3. **字体**：Simple 全无衬线，中级衬线（叙事）+ 无衬线（UI）配对
> 4. **动效**：Simple 高效克制，中级仪式感（进入转场 + 草稿/检索小窗折叠）
>
> 「夜航点灯」隐喻天然指向 Restrained：广袤黑暗中一点暖光，而非满屋琥珀。原 v1.0 声明 Committed 系误标（bg/surface 彩度 0.025-0.03 实为 tinted neutral，非 saturated surface），本次修订纠正，与 impeccable 定义对齐。

## 2. 配色皮肤系统架构

### 2.1 可插拔设计

中级模式的配色采用**骨架固定 + 配色皮肤可插拔**架构：

- **骨架不变**：布局、组件结构、字体、间距、圆角——保证视觉识别
- **配色可变**：bg、surface、ink、primary 等语义色彩——保证新鲜感

配色皮肤以"语义角色"为单位定义，切换皮肤只换色值，不换结构。

### 2.2 交付路线

| 版本 | 配色皮肤 | 切换方式 |
|------|---------|---------|
| v0.2 | 夜航 1 套（本文档定义） | 默认，不切换 |
| v0.3 | 夜航 + 墨章 + 幽林 + 暗幕 | 按故事类型智能匹配 |
| 更远 | 持续增量 + 骨架微调 | 留出设计余地 |

### 2.3 皮肤数据结构

每套配色皮肤定义以下语义角色：

```
bg / surface / surfaceElevated / surfaceVariant
ink / muted / faint
primary / primaryDim / accent / accentDim
divider / success / warning / error / scrim
```

代码层通过 `IntermediateColorScheme` 抽象类承载，运行时替换实例即可切换皮肤。详见第 7 节。

## 3. 夜航配色系统（v0.2 默认）

### 3.1 设计意象

**夜航**：深夜独处、点灯夜读的氛围。深蓝黑底色（夜空，带靛蓝色相）+ 琥珀金点缀（暖灯光、烛火）+ 月白文字（月光，带微暖）。感觉像在黑暗里点一盏暖灯读故事，沉静、内敛、有温度。

### 3.2 暗色主题色值表

色彩采用 OKLCH 色彩空间定义，确保感知均匀和未来可扩展。

| 角色 | OKLCH | HEX 近似 | 用途 |
|------|-------|---------|------|
| bg | `oklch(0.14 0.025 260)` | `#0E1018` | 页面背景（深蓝黑，夜空） |
| surface | `oklch(0.17 0.03 258)` | `#141722` | 消息气泡、卡片（深蓝） |
| surfaceElevated | `oklch(0.21 0.035 256)` | `#1B1E2C` | 弹窗、提升层 |
| surfaceVariant | `oklch(0.19 0.03 258)` | `#171A26` | 输入框背景 |
| ink | `oklch(0.94 0.008 70)` | `#EFEDE6` | 主要文字（月白） |
| muted | `oklch(0.76 0.012 70)` | `#B9B7AE` | 次要文字、时间戳、占位符 |
| faint | `oklch(0.64 0.01 70)` | `#9B9990` | 禁用态图标、装饰性大字（≥18px） |
| primary | `oklch(0.75 0.14 80)` | `#D4A042` | 强调色（琥珀金，主按钮） |
| primaryDim | `oklch(0.75 0.14 80 / 0.12)` | `#1FD4A042` | 选中态底色 |
| accent | `oklch(0.65 0.10 65)` | `#B8862E` | 辅助高亮（深琥珀） |
| accentDim | `oklch(0.65 0.10 65 / 0.12)` | `#1FB8862E` | 辅助高亮淡化 |
| divider | `oklch(0.28 0.02 258)` | `#2A2D3A` | 分割线 |
| success | `oklch(0.70 0.13 145)` | `#4CAF6E` | 成功状态 |
| warning | `oklch(0.78 0.12 85)` | `#D4B842` | 警告状态 |
| error | `oklch(0.62 0.18 25)` | `#C44830` | 错误状态 |
| scrim | `oklch(0.10 0.02 260 / 0.7)` | `#B30E1018` | 遮罩层 |

> **占位符文字色规则**：占位符需 4.5:1 对比度（无障碍硬要求），faint(3.6:1) 不达标，故占位符统一使用 muted 色（4.5:1 ✅）。faint 仅用于禁用态图标、装饰性大字（3:1 阈值达标）。

### 3.3 对比度验证

WCAG AA 标准要求：正文 ≥4.5:1，大字（≥18px 或 bold ≥14px）≥3:1。

| 组合 | 对比度（近似） | 达标 |
|------|--------------|------|
| ink vs bg | 5.2:1 | ✅ |
| ink vs surface | 4.7:1 | ✅ |
| muted vs bg | 4.5:1 | ✅ |
| faint vs bg | 3.6:1 | ⚠️ 仅用于大字/装饰/禁用图标（3:1 达标）；占位符改用 muted |
| primary vs bg | 5.8:1 | ✅（琥珀金可用于标题/图标） |
| bg 文字 vs primary 按钮 | 需用 bg 深色文字 | ✅（ink vs primary ≈ 2.7:1 不达标→按钮文字用 bg 深色） |
| ink vs primaryDim（选中态底） | 3.8:1 | ⚠️ 仅大字/粗体（≥18px 或 bold≥14px）；正文不用 primaryDim 底色 |
| error 文字 vs error/0.12 | 2.7:1 | ❌ 不达标；FailureBar 改用 surface 底 + ink 文字 + error 图标（见 §6.4） |

> **primaryDim 使用规则**：primaryDim（primary/0.12）有效明度 ≈ 0.21，ink 文字对比度 3.8:1，仅满足大字 3:1 阈值。选中态列表项若含正文，正文区不用 primaryDim 底色，仅标题/图标区可用。
>
> **error/0.12 使用规则**：error/0.12 有效明度 ≈ 0.20，error 文字对比度仅 2.7:1，不可用于文字底色。FailureBar 采用 surface 底 + ink 文字（4.7:1 ✅）+ error 图标传递错误语义（见 §6.4）。

> **按钮文字色规则**：primary 按钮背景用 bg 深色文字（`#0E1018`），不用 ink 月白。因为 primary(0.75) vs ink(0.94) 对比度仅 2.7:1，不达标；primary(0.75) vs bg(0.14) 对比度 5.8:1，达标。

### 3.4 亮色主题（预留，v0.3）

v0.2 不实现亮色主题。v0.3 可扩展"晨读"亮色变体，色相方向保持一致（暖琥珀 + 蓝灰），明度反转。本文档预留位置，v0.3 补齐。

## 4. 字体层级

### 4.1 双字体策略

中级模式采用**衬线 + 无衬线配对**，与 Simple 模式（全无衬线）形成差异：

| 用途 | 字体族 | 理由 |
|------|--------|------|
| 消息内容（叙事文本） | 衬线（Source Serif 4 + Noto Serif SC） | 叙事感、文学感，像在读小说 |
| UI 元素（按钮/标签/输入框） | 无衬线（Inter，与 Simple 共享） | 操作效率、可读性 |

配对符合对比轴原则（衬线 vs 无衬线），避免相似字体冲突。

### 4.2 字体规格表

**消息内容（衬线）**：

| 角色 | 字号 | 字重 | 行高 | 用途 |
|------|------|------|------|------|
| narrative-body | 16px | 400 | 1.75 | 消息正文 |
| narrative-quote | 16px | 400 斜体 | 1.7 | 引用、独白 |
| narrative-large | 18px | 500 | 1.7 | 重要段落强调 |

**UI 元素（无衬线，Inter）**：

| 角色 | 字号 | 字重 | 行高 | 用途 |
|------|------|------|------|------|
| title | 18px | 600 | 1.4 | AppBar 标题 |
| label | 14px | 500 | 1.4 | 标签、按钮文字 |
| body-ui | 15px | 400 | 1.5 | UI 正文 |
| caption | 12px | 400 | 1.4 | 时间戳、辅助说明 |
| input | 16px | 400 | 1.5 | 输入框文字 |

**字号缩放（fontScale）**：通用设置中的"字体大小"（范围 12-22，默认 15）通过 `fontScale = fontSize / 15` 同时控制 Simple 模式与中级模式的消息字号。中级模式下 `fontScale` 仅应用到内容字号——`narrative-body`（助手消息正文）、`body-ui`（用户消息正文）、`narrative-quote`（思考区块展开态，基准 14px）按 `基准字号 × fontScale` 缩放；UI 标签（`caption` / `label` / `title`）保持固定字号不缩放，保留视觉层次。基准字号差异（助手 16px / 用户 15px）与双字体策略在缩放后保持不变，确保用户调整字号时中级模式仍比 Simple 模式略大、衬线叙事感不被破坏。

### 4.3 行长控制

叙事文本行长约 65-75 字符（中文约 32-37 字），超过时换行。UI 文本可更密集。

## 5. 动效规范

### 5.1 设计原则

impeccable 要求动效"传达状态，不是装饰"。中级模式是沉浸式体验，允许比工具型 App 多一些动效，但每个动效都要有叙事意义。

- **进入时刻**：营造"进入另一个世界"的冲击力
- **交互过程**：草稿/检索/回复的呈现有仪式感
- **reduced-motion**：所有动效必须有即时备选，照顾敏感用户

### 5.2 进入转场（冲击力核心）

从 Simple 模式切换到中级模式的转场，是"耳目一新"的关键瞬间：

```
背景层：始终为夜航 bg（colors.bg），不做透明渐变
  - 避免首帧透明导致底层浅色页面透出形成白屏闪烁（release 模式修复）

阶段 1（0-400ms）：夜航暗色淡入
  - surface/surfaceElevated 色彩呈现
  - 文字内容淡入（ink 月白）
  - primary 琥珀金随内容一起淡入（"点灯"效果自然体现）
  - 曲线：ease-out-quart
```

> **2026-08-10 修订**：原设计为 3 阶段（背景渐暗 -> 暗色淡入 -> 琥珀金点灯），
> 背景 `DecoratedBox` 从 `Colors.transparent` 渐变到 `colors.bg`。但 release 模式下
> 首帧透明态被实际渲染（debug 模式因渲染较慢而未暴露），导致白屏闪烁。修复方案：
> 背景始终固定为 `colors.bg`，仅做内容 `Opacity` 淡入，消除透明首帧。

**reduced-motion 备选**：瞬时切换，无过渡（`prefers-reduced-motion: reduce`）。

### 5.3 交互动效（仪式感）

| 交互 | 动效 | 时长 | 曲线 |
|------|------|------|------|
| 草稿小窗展开 | 高度展开 + 内容淡入 | 200ms | ease-out |
| 草稿文字流式 | 无动效，直接出现 | — | —（流式本身即动效） |
| 检索结果出现 | 命中结果逐条淡入，stagger 80ms | 每条 150ms | ease-out |
| 主回复气泡淡入 | 气泡从下方上浮 + 淡入 | 250ms | ease-out |
| 主回复文字流式 | 无动效，直接出现 | — | — |
| 小窗自动折叠 | 高度收缩为单行摘要 | 200ms | ease-in-out |
| 小窗入场（实时态） | ClipRect + Align(heightFactor) + Opacity 淡入展开 | 200ms | ease-out |
| 失败灰显 | opacity 0.4 + 灰度滤镜 | 300ms | ease-out |
| 重试清空 | 旧内容淡出 → 新草稿淡入 | 150ms + 200ms | ease-out |

**小窗自动折叠的视口可见延迟机制（2026-07-17 修订；2026-08-05 修订）**：面板在到达完成态触发自动折叠前，先通过 `context.findRenderObject()` + `localToGlobal(Offset.zero)` 检测自身是否在屏幕可见区域。若可见（说明用户可能正在阅读），延迟折叠一次并重新计时；最多延迟 2 次（`_maxFoldRetries = 2`），总阅读时间 ≈ `foldDelayMs × 3`；不可见或达到最大延迟次数后执行折叠。避免用户正在阅读面板内容时被自动折叠打断阅读节奏。**2026-08-05 修订**：自动折叠定时器仅在 `phase == idle` 时启动；生成过程中（phase != idle）面板完成后保持展开，不自动折叠，避免打断用户阅读。用户发送新消息时旧面板切换到历史模式（默认折叠），不需要自动折叠定时器。

**小窗入场动画（实时态，2026-07-17 新增；2026-08-05 修订）**：4 个面板（GeneratePanel/ExtractPanel/RetrievalPanel/SummarizePanel）首次出现时通过 `_PanelEntrance` 包裹，使用 `TweenAnimationBuilder<double>` 从 0 -> 1 过渡，配合 `ClipRect` + `Align(heightFactor)` + `Opacity` 实现从顶部展开 + 淡入的入场效果（200ms ease-out）。`reduced-motion` 时长改 0 保持无动画降级。面板因 `if` 条件增删--首次出现时是全新 widget 重新触发入场动画；后续 phase 变化但面板继续存在时（同 Key 复用），不重复触发。**2026-08-05 修订**：idle 分支（artifacts 模式）同样用 `_PanelEntrance` 包裹所有面板，确保 phase 从生成中切到 idle 时外层组件类型一致，Flutter 可复用 Widget 实例而非销毁重建。

**GeneratePanel 流式态禁用 AnimatedSize（2026-07-17 修订；v0.2.2 重命名：DraftPanel → GeneratePanel）**：GeneratePanel 在 `generating` 阶段（流式 token 持续到达；v0.2.2 阶段名重命名：drafting → generating）**完全不用 AnimatedSize**，直接返回 Container。原因：`AnimatedSize` 的 `RenderAnimatedSize.performLayout` 在检测到 child size 变化时会在 layout 过程中 `markNeedsLayout` 自己，违反 Flutter 的"A RenderObject must not re-dirty itself while still being laid out"规则。流式态每个 token 到达都触发一次 child size 变化，导致连续报错。仅在不频繁变化尺寸的场景（状态切换 generating→completed / 展开↔折叠）使用 AnimatedSize 做 200ms 过渡动画。`reduced-motion` 场景同样直接返回 Container（不用 duration=Duration.zero 的 AnimatedSize，因为 duration=0 仍会触发 performLayout 自我标脏）。其他面板（Extract/Retrieval/Summarize）因无流式 token、内容变化低频，暂不强制改此模式。

### 5.4 禁止的动效

- 装饰性循环动效（不传达状态的旋转、脉冲）
- 弹性/反弹曲线（bounce/elastic）——与沉浸克制基调不符
- 页面加载编排序列（用户进入任务，不想看 App 加载）
- 任何依赖动效才能显示内容的设计（reduced-motion 下必须可见）

## 6. 特色组件设计

### 6.1 IntermediateMessageBubble（消息气泡）

中级模式的消息气泡，区别于 Simple 模式：

| 属性 | 值 | 说明 |
|------|-----|------|
| 背景 | surface | 深蓝气泡底 |
| 文字 | ink + 衬线字体 | 月白叙事文字 |
| 圆角 | rMd（12px） | 共享圆角令牌（偏离 06A rLg，见下） |
| 内边距 | 12px 16px | 共享间距令牌 |
| 用户消息对齐 | 右侧，primaryDim 底色 | 琥珀金淡化底 |
| 助手消息对齐 | 左侧，surface 底色 | 深蓝底 |
| 最大宽度 | 92% 屏宽 | 减少移动端换行 |
| 内容渲染 | IntermediateMarkdownBody（有限 Markdown） | 见下「消息内容渲染」 |

**避免**：不用 border-left 侧条标记角色（impeccable 禁令），用底色区分。

**圆角偏离说明**：中级模式消息气泡使用 rMd（12px），偏离 06A Simple 模式的 rLg（16px）。理由：中级模式追求"收敛沉浸"的阅读氛围，较小圆角强化书页感；Simple 模式工具感更强，大圆角传达柔和。此为有意偏离，非笔误。

**消息内容渲染**（v3.13 新增）：消息正文由 `IntermediateMarkdownBody` 渲染（`lib/core/theme/intermediate/components/intermediate_markdown_body.dart`），与 Simple 模式的 `SimpleMarkdownBody` 平行但能力收敛。

| 维度 | IntermediateMarkdownBody | SimpleMarkdownBody |
|------|---------------------------|---------------------|
| 启用语法 | CommonMark 基础语法（`ExtensionSet.none`） | GFM 扩展 + LaTeX |
| 代码块 | 无语法高亮，surfaceVariant 底 + rMd 圆角 | `flutter_highlighting` 高亮 + 语言标签 + 折叠 |
| LaTeX 公式 | 不支持 | 行内 `$...$` + 块级 `$$...$$` |
| 表格/任务列表/删除线 | 不支持 | 支持（GFM 扩展） |
| Mermaid | 不支持 | 降级提示 + 源码 |
| 字体策略 | 双字体（助手 narrativeBody 衬线 / 用户 bodyUi 无衬线） | 单字体（body 无衬线） |
| 引用块装饰 | surfaceVariant 底 + rSm 圆角 + 斜体（**不用 border-left 侧条**） | surfaceVariant 底 + rSm 圆角 + 左 3px primary 边框 |
| 链接点击 | `url_launcher` 打开外部浏览器（与 Simple 一致） | 同左 |

支持的基础语法：粗体 `**bold**`、斜体 `*italic*`、行内代码 `` `code` ``、引用 `> quote`、有序/无序列表、分隔线 `---`、链接 `[text](url)`。

设计动机：用户反馈"星号问题"——LLM 输出 `*斜体*` `**加粗**` 时，原 `SelectableText` 纯文本渲染会原样显示星号。引入有限 Markdown 即可消解。故事场景不需要代码高亮 / 公式 / 表格等工具型能力，保持衬线叙事感即可。

**点击交互**：`MarkdownBody` 不消费非链接区域的 tap 事件，外层 `GestureDetector`（`HitTestBehavior.opaque`）收到 tap 后切换 `IntermediateMessageActions` 可见性（`_toggleActions`）。链接点击由 `onTapLink` 处理打开浏览器，与动作菜单切换互不干扰。长按选择文字（`selectable: true`）与 tap 是不同手势，不冲突。

**流式生成**：`flutter_markdown` 对未闭合标记（如 `**未闭合加粗`）有容错能力，会作为纯文本渲染，流式生成中无需特殊处理。光标动画 `_StreamingCursor` 在 Markdown 内容下方持续显示。

### 6.1C IntermediateCompactionSummaryCard（压缩摘要隔断卡片，v0.2.2 新增 2026-08-04）

故事模式 CompactionPoint 压缩触发后，压缩摘要作为「上下文隔断」展示在对话流最前，区别于普通消息气泡。参考 ChatBox 的 SummaryMessage，但适配夜航主题。

**设计动机**（用户需求 2026-08-04）：压缩摘要的 role=system + isSummary=true，若用普通助手气泡渲染则与对话消息视觉同质，用户无法感知"早期对话已被压缩"。需要一种隔断式视觉，让摘要像书脊一样横跨对话流，明确区分「已压缩的早期剧情」与「保留原文的近期对话」。

**触发条件**：`IntermediateCompactionService.compact` 成功并持久化后，`chat_messages` 表写入一条 `isSummary=true, role=system` 的摘要消息。`filterByCompactionPoint` 加载历史时将该消息置于列表最前，UI 据此渲染隔断卡片。

| 属性 | 值 | 说明 |
|------|-----|------|
| 容器底色 | surfaceVariant | 比气泡 surface 略浅，区分「非对话消息」 |
| 圆角 | rMd（12px） | 与消息气泡一致 |
| 边框 | divider 1px | 强化隔断感（不用侧边条，impeccable 禁令） |
| 宽度 | 整宽（消息列表可用宽度） | 偏离气泡 92% 限制，形成「横跨」视觉 |
| 外边距 | horizontal: sSm, vertical: sMd | 上下 sMd（12px）比气泡 s2xs（4px）更大，呼吸感强化隔断 |
| 折叠态 | 标签行：图标 + "早期消息已摘要" + 展开箭头 | 高度约 44px，像带文字的分隔条 |
| 展开态 | 标签行 + divider + 衬线斜体摘要内容 | 用 `IntermediateMarkdownBody(isUser=false)` 渲染，保持夜航叙事感 |
| 标签字体 | caption + italic + muted | 弱化存在感，不抢正文 |
| 标签图标 | `auto_awesome_outlined` 16px + accent | 琥珀金暗示「AI 摘要」语义 |
| 展开箭头 | `expand_less`/`expand_more` 18px + muted | 与标签同行右对齐 |
| 字体缩放 | 仅展开态正文受 fontScale 影响 | 折叠态标签用 caption 固定字号，保持 UI 层次 |
| 无障碍 | `Semantics(button: true)` 包裹箭头 | 展开收起语义标签 |

**折叠态视觉**：
```
┌──────────────────────────────────────────────┐
│ ✦  早期消息已摘要                         ▾  │
└──────────────────────────────────────────────┘
```

**展开态视觉**：
```
┌──────────────────────────────────────────────┐
│ ✦  早期消息已摘要                         ▴  │
│ ─────────────────────────────────────────── │
│ [衬线斜体摘要正文，可能含加粗/列表等基础 MD]  │
│                                              │
└──────────────────────────────────────────────┘
```

**位置语义**（用户需求 2026-08-04）：摘要卡片由 `filterByCompactionPoint` 置于消息列表最前，boundary 之后的消息（含新用户消息）排在摘要之后，确保新用户消息始终在压缩摘要后边。

**多轮压缩**：多次触发压缩时，旧摘要消息（isSummary=true）从列表中过滤丢弃，仅保留最新一条。视觉上对话流始终只有一张隔断卡片，不会堆积。

**与 Simple 模式的差异**：

| 维度 | IntermediateCompactionSummaryCard | Simple 摘要卡片 |
|------|-----------------------------------|----------------|
| 容器宽度 | 整宽（横跨对话流） | 受限宽度（与气泡一致） |
| 底色 | surfaceVariant + divider 边框 | surface（与气泡同质） |
| 字体 | 衬线斜体（夜航叙事感） | 无衬线（工具感） |
| 图标 | auto_awesome_outlined（琥珀金） | 无图标 |
| 折叠态 | 标签行（图标+文案+箭头） | 仅单行文案 |

**impeccable 合规**：
- 不使用 border-left 侧条（用底色 + 全边框 + 图标实现区分）
- 不使用渐变文字、glassmorphism
- 折叠/展开过渡用 Material InkWell ripple，无弹性动画

**国际化 key**（DOC-07）：
- `intermediate.chat.compaction.earlierSummarized`：折叠态标签文案
- `intermediate.chat.compaction.expand`：展开按钮无障碍标签
- `intermediate.chat.compaction.collapse`：收起按钮无障碍标签

关键词提取阶段的折叠小窗（v0.2.2 检索前置：extracting 步骤前置到 generating 之前，从「用户当前消息（优先）+ 最近 n 轮对话」提取 5 类分类关键词，结构化步骤无流式显示）：

> - **位置前置**：extracting 从 generating 之后 → generating 之前。流程顺序变为 `extracting → retrieving → generating → [reviewing] → summarizing → persisting`（v0.2.2 阶段名重命名：drafting→generating、revising→reviewing）。

> **v0.2.2 改造说明**（2026-07-30）：
> - **5 路并行检索**：从「FTS5 单路 + Vector 单路 共 2 路」→ 「5 路并行」：characters / items / locations 3 类实体词走 FTS5 精确匹配（3 路），actions / plots 2 类事件词走 Vector 语义匹配（2 路）。任一通道失败自动降级（不影响其他通道）。
> - **topK 扩容**：3 → **12**（约 1800-2400 token，加事实层约 3000-4000 token，128K 上下文可承受）。
> - **质量阈值上调**：绝对阈值 0.4 → **0.5**，相对阈值 0.6 → **0.65**（抵消注意力稀释）。
> - **关键实体强制注入**：`importance >= 4` 的实体最多 3 个，无论检索分数如何都注入，避免关键角色因检索分数低被漏掉。
> - 详见 DOC-09A-2 v2.x、DOC-09B v2.x。

**5W1E 详情查看**（v3.4 新增）：展开态下用户点击记忆条目文本可弹出 `MemoryDetailDialog`（§6.3C）查看完整 5W1E 6 字段详情。micro 与 macro 记忆均可点击；macro 记忆额外展示聚合微摘要数和触发原因。实现方式：内层 `InkWell` 包裹 `Text(m.displayText)`，与外层折叠 `InkWell` 通过 Flutter tap 区域优先级自然分离（内层优先消费）。

**检索模式标签 `_buildModeBadge`**（v3.6 新增，2026-07-21 embedding 降级修复）：摘要行（"找到 N 条相关经历"）右侧追加一个紧凑的胶囊徽章，明确告诉用户当前用的是哪种检索模式，**杜绝"偷偷降级"**。三种状态：

| 状态 | 触发条件 | 文字色 | 底色 | 边框色 | i18n key |
|------|---------|--------|------|--------|---------|
| 语义检索 | `embeddingConfigured=true` 且 `embeddingDegradedForRound=false` | primary（琥珀金） | `primary.withValues(alpha:0.12)` | `primary.withValues(alpha:0.4)` | `retrievalMode.semantic` |
| 关键词检索 | `embeddingConfigured=false`（未配置嵌入模型） | muted（灰色） | `muted.withValues(alpha:0.12)` | `muted.withValues(alpha:0.4)` | `retrievalMode.keyword` |

- **不使用 border-left 侧条**（AI slop），使用透明底色（alpha 0.12）+ 完整 1px 边框 + rXs（4px）圆角

设计动机（详见 DOC-09A-2 §6.5.1、DOC-09B v2.18）：用户反馈"embedding 调用失败静默降级到字符串匹配"完全不告知——三种状态必须让用户**一眼可辨**，"临时降级"用红色强化警示感。

**RetrievalPanel 历史态（统一组件，v2.7 重构）**：RetrievalPanel 接收可选的 `artifacts` 参数，非 null 时进入历史态渲染，用 `HistoryPanelShell` 容器。与实时态的差异同 GeneratePanel 历史态（见 §6.2）：

| 差异点 | 实时态（artifacts=null） | 历史态（artifacts≠null） |
|--------|--------------------------|--------------------------|

**详情区内容**（从上到下）：
1. 技术详情标题 → 错误码（E010-E018）/ HTTP 状态（null 不显示）/ 失败阶段（phaseLabels）/ 错误类型（categoryLabels）
2. divider → 建议操作标题 + 内容（suggestedActions 按 ErrorCategory 映射）
3. divider（仅 rawError != null）→ 原始异常标题 + monospace 可滚动文本

**动效**：
- 时长 200ms，曲线 `easeOutQuart`（impeccable: 指数 ease-out，无 bounce/elastic）
- 减弱动效兜底：`MediaQuery.accessibleNavigation == true` 或键盘弹出时 `duration = Duration.zero`，跳过 `AnimatedSize` 直接渲染（避免 `RenderAnimatedSize` 在 performLayout 中自我标脏，同时防止键盘弹出时收起动画的中间尺寸导致瞬态溢出）
- `AnimatedRotation` 展开箭头同步动画

**键盘场景**（2026-08-02 底部溢出修复 v6，最终版）：键盘弹出时（`viewInsets.bottom > 0`）FailureBar 自动收起详情，把空间让给输入框；键盘收起后恢复用户之前的展开选择。v1-v5 均失败，v6 为最终架构（滚动分而治之）：

- **v1 失败原因**：`Flexible(loose)` + `ConstrainedBox`。loose fit 不强制子组件收缩，FailureBar 内部 MediaQuery 估算高度不准，多算 ~214px。
- **v2 失败原因**：LayoutBuilder 放 Column 末尾非 Flexible child → height constraint unbounded(∞) → maxHeight=∞，限高逻辑失效。同时 `didChangeDependencies` 漏 `setState()`。
- **v3 失败原因**：`Flexible(tight, flex=4/2)` → tight fit 强制撑满 flex 份额 → 收起态下方大片空白。
- **v3.1 失败原因**：去 Flexible(tight) 后外层 `ConstrainedBox(minHeight=0)` → Flutter 允许自然高度，详情超高时直接溢出。
- **v4 失败原因**：`SizedBox(height=H*70%)` 无论是否失败态都占 → **正常态输入框跑到屏幕中间，下方大片空白**。
- **v5 失败原因**：正常/失败态分离了，但 FailureBar 内部整体包在 SingleChildScrollView 里 → 标题行+按钮行和详情一起滚动，FailureBar 受限时标题/按钮也被挤到可视区域外，用户认为"显示不全"。
- **v6 最终方案**（滚动分而治之，标题按钮永远可见）：
  1. Scaffold body 整体 LayoutBuilder → 拿到有限可用高度 H
  2. **正常态**：底部区 `Column(mainAxisSize.min)`，按自然高度紧贴底部，无空白
  3. **失败态**：底部区 `ConstrainedBox(maxHeight: H×55%/70%)` + `SingleChildScrollView` → 终极兜底，永远不溢出黄黑条纹
  4. **FailureBar 内部结构**（标题+按钮永远可见，不参与滚动）：
     - `Column(mainAxisSize.min)` 外层
     - **固定区**：Padding → 标题行（错误图标+文字+展开箭头）+ 按钮行（清空/降级/从中断/重试 Wrap）→ 永远不滚动，始终在 FailureBar 可视范围内
     - **详情区**：`Flexible` + `LayoutBuilder` 拿到剩余可用高度 remH → `_buildDetailArea(remH)` 内部再套 `ConstrainedBox(maxHeight: remH)` + `SingleChildScrollView` → 详情超高时**只让详情卡片自己滚动**
  5. 键盘未弹出时 FailureBar 不限高（`failureBarMaxHeight = null`）→ 标题+按钮+详情全显，外层 SingleChildScrollView 作为终极兜底
  6. 键盘弹出时 FailureBar 限高（`failureBarMaxHeight = bottomMaxHeight × 60%`）+ `didChangeDependencies` 强制 `_expanded=false` + `AnimatedSize Duration.zero`

**对比度规则**（DOC-06B §3.3）：不用 error/0.12 底色（error 文字对比度仅 2.7:1，不达标）；改用 surface 底 + ink 文字（4.7:1 ✅）+ error 图标传递错误语义。

| 属性 | 值 | 说明 |
|------|-----|------|
| 触发条件 | `onContinueFromFailed != null` | 所有失败阶段都显示（包括 generating 失败，此时等价于整轮重试） |
| 位置 | "临时降级继续"右侧（如存在）、"整轮重试"左侧 | 次要到主要操作的视觉梯度（左→右） |
| 样式 | TextButton + ink 色 | 比 muted 更突出（推荐操作），但弱于 primary ElevatedButton（避免与"整轮重试"主操作竞争） |
| i18n | `failure.continueFromFailed` | "从中断处继续"文案 |
| 行为 | 调 `onContinueFromFailed` 回调 → Controller `continueFromFailed()` → 重新解析配置（用户可能修改过）+ 保留已完成阶段产出 + 从 `failureContext.failedPhase` 对应阶段继续重试 | generating 失败时无产出可复用，行为等价于 retry |

设计动机（v3.7）：用户反馈"某轮报错后只有'清空本轮'和'整轮重试'两个选项，如果生成正文满意不想推翻重做就没法继续"。新按钮给用户第四条路：保留已完成阶段产出（如生成正文），从失败阶段继续重试。同时配合"failed 状态下可修改会话配置"（`isGenerating = phase != idle && phase != failed`），用户可先修改模型/温度等配置再从中断处继续，解决"因模型限额报错后无法调整配置重试"的问题。

**"整轮取消"回填用户消息**（v0.2.2 明确，2026-07-30）：点击"清空本轮"（`onClear` 回调）后，`IntermediateChatPage` 在调用 `controller.clearRound()` 前先读取 `state.userInput`，clearRound 完成后通过 `_inputKey.currentState?.setText(userInput)` 将原用户消息回填到输入框。这样用户修改消息后可直接重发，避免"清空后还要重新打字"的体验断层。回填逻辑由 `IntermediateChatPage` 承载（非 FailureBar 内部），因为 FailureBar 不持有输入框引用。详见 `intermediate_chat_page.dart` 的 `onClear` 回调实现。

**键盘弹出溢出防护**（v0.2.2 修复，2026-08-02）：FailureBar 在失败状态下与 InputToolbar + Input 共存于 body Column 底部。键盘弹出时可视区域减少 40-50%，展开态 FailureBar + 输入区总高度可能超过可用空间导致底部溢出（黄黑斑马纹）。修复方式：键盘弹出时（`MediaQuery.viewInsets.bottom > 0`）给 FailureBar 的 Container 添加 `BoxConstraints(maxHeight: 可用高度*50%)`，内部用 `SingleChildScrollView` 包裹使内容可滚动；键盘未弹出时不限制（`double.infinity`），保持展开态完整显示。

### 6.7A IntermediateEditDialog（编辑弹窗）

中级模式的消息编辑弹窗，支持"仅保存"和"保存并发送"两种模式。由 §6.7 IntermediateMessageActions 的"编辑"按钮触发，根据消息角色自动选择模式。

**双模式设计**：

| 模式 | 触发条件 | 按钮组合 | 主要操作 |
|------|---------|---------|---------|
| allowResend=true | 用户消息 | 取消 + 保存 + 保存并发送 | 保存并发送（ElevatedButton，primary 底） |
| allowResend=false | 助手消息 | 取消 + 保存 | 保存（ElevatedButton，primary 底） |

**视觉规范**：

| 元素 | 样式 | 说明 |
|------|------|------|
| 容器 | 标准 `AlertDialog`（主题 dialogTheme：surfaceElevated 底 + rXl 圆角） | 不重新发明 affordance（impeccable product register） |
| 标题 | title 字体 + ink 色 | "编辑"（i18n: `editTitle`），maxLines: 2 + ellipsis |
| 输入框 | `TextField`（maxLines: null 自适应高度）+ surfaceVariant 填充 + rMd 圆角 + focused 时 primary 1.5px 边框 | 主题 inputDecorationTheme 自动应用 |
| 输入框文字 | input 字体 + ink 色 | - |
| 取消按钮 | `TextButton` + muted 色 | dirty 时触发 PopScope 确认丢弃 |
| 保存按钮（次要） | `TextButton` | allowResend=true 时作为次要操作 |
| 保存按钮（主要） | `ElevatedButton` + primary 底 + bg 深色文字 | allowResend=false 时作为主要操作 |
| 保存并发送按钮 | `ElevatedButton` + primary 底 + bg 深色文字 | 仅 allowResend=true 时显示，主要操作 |

**交互规范**：
- **dirty 检测**：`TextEditingController` 监听文本变化，内容与初始值不同时 `_isDirty=true`，保存按钮才启用（`_canSave = _isDirty && text.trim().isNotEmpty`）
- **PopScope 防误退**：dirty 时 `canPop=false`，点返回键或取消按钮触发 `_confirmDiscard()` 弹确认对话框（标题 + "未保存的修改" + 继续编辑/确认丢弃）；非 dirty 直接关闭
- **返回值**：`({String content, bool resend})`，resend=true 表示保存并发送（删下游 + 重新生成），resend=false 表示仅保存文本

**与 Simple 模式 MessageEditDialog 的差异**：

| 维度 | IntermediateEditDialog | Simple MessageEditDialog |
|------|----------------------|------------------------|
| 助手消息编辑 | 支持（仅保存模式，allowResend=false） | 不支持（Simple 模式助手消息无编辑按钮） |
| 用户消息按钮 | 取消 + 保存 + 保存并发送（三按钮） | 取消 + 保存并发送（两按钮） |
| "仅保存"模式 | 支持（不重新生成，仅更新消息文本） | 不支持（Simple 模式编辑即重发） |

设计动机：故事模式允许用户修改助手消息的文本（如修正措辞、补充细节）而不触发重新生成，保留对话流不被打断。用户消息编辑时也可选择"仅保存"避免下游消息被删除。

| 字符计数 | caption 样式 + muted 色，右对齐 | `ValueListenableBuilder` 驱动，"N 字"（i18n: `charCount`） |
| 保存按钮 | ElevatedButton + primary 色 + rFull 圆角 | dirty 时启用，非 dirty 禁用 |
| 恢复默认按钮 | TextButton + muted 色 | 始终可见，点击弹确认对话框 |
| 用法说明区 | surfaceVariant 底 + rMd 圆角 + sMd 内边距 | 灯泡图标（accent 色）+ usage 文本（ink 色）+ divider + "内置默认值"标题（label + ink）+ 默认值预览（caption + muted + monospace） |

**交互**：
- **TextEditingController + `_ensureInit` 模式**：与 `IntermediateSystemPromptSection` 一致，避免 `didUpdateWidget` 重复初始化
- **保存**：`repo.setUserOverride(meta.overrideKey, text)`；若 `text == meta.defaultValue`，改调 `removeUserOverride`（避免存冗余覆盖）；保存后 SnackBar 提示"已保存"
- **恢复默认**：弹 `AlertDialog` 确认 → `removeUserOverride(meta.overrideKey)` → 重置 TextEditingController 为默认值 → SnackBar 提示"已恢复为默认设定"
- **PopScope 拦截**：`_isDirty()`（当前文本 ≠ 初始化值）时拦截返回，弹"放弃修改"确认对话框（标题/内容/继续编辑/放弃 四要素）；非 dirty 直接返回
- **ValueListenableBuilder**：监听 TextEditingController 驱动字符数 + 保存按钮 dirty 状态，避免 setState 开销

**视觉规范要点**：
- 编辑器是中级模式第二个全屏编辑场景（第一个是 IntermediateSessionSettingsSheet 的展开版），延续夜航配色
- 用法说明区的灯泡图标用 accent 色（非 muted），强调"提示性而非装饰性"
- 字符数用"N 字"而非"N / MAX"——提示词无硬性长度上限（受 LLM 上下文窗口限制，动态变化）

**与 IntermediateSystemPromptSection 差异**：
- SystemPromptSection 是 inline 编辑（TextField 直接在设置页内），PromptsSection 是 tile 列表 + 全屏编辑器（10 段内容较长，inline 会撑爆设置页）
- 持久化 key 不同：SystemPromptSection 写 `intermediate.system_prompt`，PromptsSection 写 `intermediate.prompts.{fieldKey}`
- PromptsSection 的"恢复默认"对比的是 `intermediate_prompts.dart` 常量；SystemPromptSection 对比的也是 `kDefaultRolePrompt`（两者 defaultRolePrompt 字段的恢复默认逻辑一致）

**设计规范**：

|------|-----|------|
| 容器背景 | surfaceElevated | 夜航深蓝提升层 |
| 圆角 | rSm (8) | — |

**自动隐藏逻辑**：
- `visible` 由父组件控制：`_isScrollActive && !_atBottom`
  - `_isScrollActive`：用户滑动时 true，停止 2 秒后自动 false
  - `_atBottom`：位于底部 50px 容差内时 true（在底部时隐藏导航）

**滚动控制**（在 `IntermediateChatBody` 中实现）：
- `_jumpToTop()`：animateTo 到 offset 0（最旧消息）
- `_jumpToBottom()`：animateTo 到 maxScrollExtent（最新消息）
- `_jumpToPrevUserMessage()`：通过 `_findFirstVisibleIndex` 找到当前视口第一条可见消息，向前查找 role='user' 并 `_scrollToMessage`，找不到则跳顶

- `_scrollToMessage(messageId)`：通过 `KeyedSubtree` 的 GlobalKey + `getOffsetToReveal` 定位

- 滚动方向：故事模式 ListView 非 reverse（顶部=最旧，底部=最新），与 Simple 模式 reverse 列表相反
- i18n：复用 `chat.navigation.*` key，无独立翻译

### 6.17 RebuildEmbeddingsProgressDialog（重建向量索引进度对话框，v3.6 新增）

会话设置面板「记忆管理」区段（§6.8 区段 6）的「重建向量索引」按钮触发的进度对话框。通过 `showDialog<void>` 弹出，`barrierDismissible: false` + `PopScope(canPop: false)` 双重禁止关闭，用户必须等待重建完成（单条记忆的 embedding 调用通常很快，重建无法中途安全中断）。

**布局**：

```
┌─ AlertDialog(surfaceElevated 底, rXl 圆角) ─────────────────┐
│  重建向量索引                                                │
│  ─────────────────────────────                              │
│  [LinearProgressIndicator ━━━━━━━░░░░░░░░░░░]              │
│  已处理 12 / 30（失败 1）                                    │
│                                                              │
│  （无按钮：用户必须等待完成）                                │
└──────────────────────────────────────────────────────────────┘
```

| 元素 | 样式 | 说明 |
|------|------|------|
| 容器 | `AlertDialog`（默认主题）+ `PopScope(canPop: false)` | 阻止返回键关闭 |
| 标题 | `rebuildVectorIndexTitle`（"重建向量索引"） | i18n 文案 |
| 进度条 | `LinearProgressIndicator` + `divider` 底色 + `primary` 进度色 | value = `processed / total`（total > 0），无 bounce/elastic |
| 进度文案 | caption + muted 色 | `rebuildVectorIndexProgress(processed: N, total: M, failed: K)` |
| 按钮 | 无 | 重建完成后由 `_runRebuild` 调 `Navigator.pop()` 关闭 |

**状态更新机制**：通过 `ValueNotifier<(int, int, int)>`（processed, total, failed）+ `ValueListenableBuilder` 实时更新进度。Controller 的 `rebuildEmbeddings(onProgress: ...)` 回调每完成一条记忆触发一次更新。

**完成后行为**：
1. `_runRebuild` 调 `Navigator.of(context).pop()` 关闭本对话框
2. `setState(() => _isRebuilding = false)` 重置按钮状态
3. `_refreshPendingCount()` 刷新未向量化记忆数量（重建后应减少）
4. 显示 SnackBar 结果反馈：
   - 成功：`rebuildVectorIndexResultSuccess(succeeded: N, failed: K)`（success 底色，2 秒）
   - 失败原因 `busy`：`rebuildVectorIndexFailureBusy`（error 底色，3 秒）
   - 失败原因 `not_configured`：`rebuildVectorIndexFailureNotConfigured`（error 底色，3 秒）

**与 FailureBar E104 降级的关系**：重建向量索引是「事后补救」操作（用户已知降级，主动补全向量）；FailureBar 的"临时降级继续"是「事中决策」操作（用户遭遇失败，选择是否接受降级）。两者覆盖 embedding 失败的不同时间点。

### 6.20 ContextBudgetSlider（上下文预算百分比条，v0.2.2 新增 2026-07-30；v3.16 新增双阶段 token 预估 2026-08-03）

故事模式设置 → 工具与记忆子页（`IntermediateToolsMemorySettingsPage`）内 `IntermediateContextBudgetSection`（§6.22）以及会话级设置面板（§6.8 区段 5）使用的可视化百分比条组件，将抽象的 token 预算分配转化为可拖动的滑块组合。

> **设计动机**（2026-07-30）：v0.2.2 检索前置后，草稿生成阶段需同时注入「最近对话原文 + 检索记忆 + 压缩摘要 + 世界设定」，三者争抢有限的上下文窗口。用户需要直观控制各区域占比，避免某区域过大挤占其他区域。原 `IntermediateMemorySection` 仅控制宏摘要策略，无法精细调节 token 预算，故新增本组件。

> **v3.16 双阶段 token 预估**（2026-08-03）：故事模式分步骤模型允许 generating / reviewing 使用不同模型，两者 contextWindow 可能不同。新增 `secondaryWindow` 参数，当其与 `availableWindow` 不同时在可用窗口信息行和每个预算行下方追加"审查 X tokens"次行，让用户看到两阶段各自的 token 分配。同时全局/会话级设置页均改为从模型注册表动态解析 contextWindow（替代原硬编码 96000 兜底）。

**三区域结构**（从上到下）：

| 区域 | 控件 | 默认值 | 范围 | 说明 |
|------|------|--------|------|------|
| 原文区上限 | 固定标记线（`_FixedSliderMark`，不可拖动） | 50% | 固定 | `recentMaxRatio`，达到时触发压缩。灰色圆点 + 灰色轨道，视觉上明确"不可编辑" |
| 原文区下限 | 动态/自定义切换 + 滑块（可选） | 动态（null） | 10%-45% | `recentMinRatio`，null=动态（基于 32K token / availableWindow 反推并 clamp），非 null=用户自定义。`_DynamicCustomToggle` chip 切换两种模式 |
| 检索区比例 | 滑块（可拖动） | 15% | 0%-30% | `retrievalRatio`，控制注入检索记忆的 token 预算占比。v0.2.2 阶段 2-E 下限改为 0 允许完全关闭检索（=0 时显示 warning 色"已完全关闭检索"明确提示） |

**可用窗口信息行**（顶部）：caption + muted 标签 "可用窗口" + caption + ink 值（如 "96K"），让用户知道当前模型的上下文窗口大小。
- **单阶段**（`secondaryWindow` 为 null 或等于 `availableWindow`）：仅显示 generating 阶段窗口值。
- **双阶段**（`secondaryWindow` 与 `availableWindow` 不同）：显示 "生成 X" + "审查 Y" 两个值，分别用 ink 色（主）和 faint 色（次）形成视觉层次。

**预算行 `_BudgetRow`**：标签（caption + muted）+ 可选 trailing 控件 + 百分比文本（caption + ink/faint + w600）+ token 预估文本（caption + faint + 11px）。固定项用 faint 色，可编辑项用 ink 色，形成视觉层次。双阶段模式下，行下方追加 "审查 X tokens" 次行（caption + faint + 11px），让用户对比两阶段同一比例的实际 token 数。

**`_DynamicCustomToggle` 切换 chip**：surfaceVariant 底 + rXs 圆角 + InkWell，点击在"动态"（faint 色）与"自定义"（primary 色）间切换。切到动态时传 null（`onMinRatioChanged(null)`），切到自定义时传下限 floor 值 0.10。

**`_FixedSliderMark` 固定标记线**：Stack 布局——底部 4px 高 divider 色细线（模拟 Slider 轨道）+ FractionallySizedBox 按比例定位的 16×16 faint 色圆点（模拟不可拖动的滑块）。视觉上与可拖动 Slider 区分（无 primary 色、无阴影）。

**可用窗口来源**（v3.16 改造）：
- **全局设置页**（`IntermediateContextBudgetSection` §6.22）：通过 `intermediateGlobalContextWindowProvider` 解析 `intermediate.phaseModels` 配置的 generating/reviewing 模型，从 `cachedModels` 中读取 `contextWindow`。未配置或不在缓存中时回退到 `ConfigurationResolver.defaultContextWindow`（96000）。
- **会话级设置页**（§6.8 区段 5）：通过 `ConfigurationResolver.resolveContextWindowForPhase` 解析会话 `phaseModels` 字段（已快照全局值）的模型 contextWindow。会话未配置模型时回退到默认值。

**视觉规范**：
- 容器：由父组件 `IntermediateContextBudgetSection`（§6.22）或会话级设置面板提供 `Material(surface, rLg)` + sLg 内边距
- Slider：`activeColor: primary`（琥珀金）+ `inactiveColor: primaryDim`，与 `IntermediateSliderField` 一致
- hint 文案：caption + faint + 11px，2 行内说明各区域语义
- 所有 Text 在 Row 中均设置 `maxLines: 1` + `overflow: ellipsis`（遵守 DOC-06 溢出防护规范）

**持久化**：本组件仅展示与回调，持久化由父组件 `IntermediateContextBudgetSection`（全局）或 `_resetContextBudgetToGlobal` / `_onRecentMinRatioOverrideChanged` / `_onRetrievalRatioOverrideChanged`（会话级）承载。

**i18n key 命名空间**：`settings.intermediate.contextBudget*`（含 `availableWindow` / `recentMax` / `recentMin` / `retrieval` / `tokens` / `dynamic` / `custom` / `recentMinHint` / `retrievalHint` / `generating` / `reviewing` / `retrievalDisabledHint`）。

### 6.22 IntermediateContextBudgetSection（上下文预算全局配置，v0.2.2 新增 2026-07-30；v3.16 动态 contextWindow 2026-08-03）

> **v3.16 动态 contextWindow**（2026-08-03）：原实现使用硬编码 96000 作为可用窗口，导致用户切换模型后 token 预估仍按 96K 计算，与实际不符。现通过 `intermediateGlobalContextWindowProvider`（位于 `lib/core/di/providers.dart`）解析 `intermediate.phaseModels` 配置的 generating/reviewing 模型，从 `cachedModels` 读取 `contextWindow`，分别传入 `ContextBudgetSlider` 的 `availableWindow`（generating）和 `secondaryWindow`（reviewing）参数。若 reviewing 阶段未配置或与 generating 相同，则仅展示单阶段 token 预估。`effectiveContextLimit`（如配置）会取 min 值后作为实际窗口传入，与控制器运行时计算逻辑一致。

| 滑块组件 | `ContextBudgetSlider`（§6.20） | 传入当前配置值 + 动态解析的 generating/reviewing contextWindow + 回调 |

**可用窗口来源**（v3.16）：通过 `intermediateGlobalContextWindowProvider` 解析 `intermediate.phaseModels` 配置的 generating/reviewing 模型 contextWindow，并应用 `effectiveContextLimit`（取 min 值）。未配置模型或模型不在 `cachedModels` 中时回退到 `ConfigurationResolver.defaultContextWindow`（96000）。

**配置项与持久化**：

|--------|-----------|--------|------|

**i18n key 命名空间**：复用 §6.20 的 `settings.intermediate.contextBudget*` 系列 key（含 v3.16 新增的 `generating` / `reviewing`）。
