## 1. 文档说明

### 1.1 编写目的
本文档定义 LMStory 项目全部 Repository 接口的完整方法签名、参数定义、返回类型、异常规范。作为代码重构的决策依据，不迁就现有实现。

### 1.2 设计原则
- 单一职责：每个接口功能明确、职责单一
- 开闭原则：接口设计允许扩展无需修改现有实现
- 高内聚低耦合：接口内部功能紧密相关，接口间依赖最小化
- Domain 纯净性：接口定义在 Domain 层，不依赖 Flutter；Core 层不依赖 Domain 业务实体
- 单向依赖：Presentation → Domain ← Data，Core 不依赖 Domain；Domain 不依赖 Data
- 异步优先：所有 IO 方法返回 Future 或 Stream
- 错误不吞没：底层异常转换为 Domain 异常向上传播
- 接口不暴露实现细节：Repository 接口不暴露 drift 表类型、Dio 响应类型、数据库主键等 Data 层细节

### 1.3 版本标注
每个接口方法标注版本（v0.1 / v0.2），v0.1 为 Simple 模式基础设施，v0.2 为 Advanced 模式新增。

## 2. 共享类型定义

### 2.1 枚举

> **v0.1 实际实现差异**：v0.1 代码中 `ChatMode` 和 `MessageRole` 均未使用枚举，而是直接使用 `String` 类型。`ChatSession.mode` 为 `'chat'`/`'advanced'`，`ChatMessage.role` 为 `'system'`/`'user'`/`'assistant'`/`'tool'`。以下枚举定义为原始设计，v0.2 重构时可考虑引入以增强类型安全。

```dart
/// 会话模式（v0.2 新增 intermediate；v0.1 实际使用 String: 'chat' / 'advanced'）

enum ChatMode { chat, intermediate, advanced }

/// 消息角色（原始设计，v0.1 实际使用 String: 'system' / 'user' / 'assistant' / 'tool'）
```

### 2.5 辅助函数

```dart
/// 从 narrativeTime 提取 narrativePeriod
/// 规则：取 "·" 之前的部分
/// 示例："修炼第三天·清晨" → "修炼第三天"
/// 示例："第一章" → "第一章"（无分隔符则原样返回）
String extractNarrativePeriod(String? narrativeTime) {
  if (narrativeTime == null) return '';
  final dotIndex = narrativeTime.indexOf('·');
  return dotIndex >= 0 ? narrativeTime.substring(0, dotIndex) : narrativeTime;
}
```
