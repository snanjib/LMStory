## 0. 文档定位

本文档定义「实体强制注入开关」：一个与「评分等级 5 强制注入」解耦的、**开关形式**的、可在**记忆库批量操作**的实体级注入控制。它是 DOC-15（世界书）的后续增强，并**修订** DOC-15 §6.2 的 `constant=true → importance=5` 映射。

**适用范围**：仅故事模式（`intermediate`）。对话模式（`chat`）无记忆系统。

**只记录已确认结论；待补项明确标注。**

---

## 1. 背景与动机

DOC-15 中，世界书词条 `constant=true`（常驻）被映射为 `importance=5`，借「关键实体」机制实现强制注入。但：

1. 世界书大量词条**并非世界设定**（如「限制文风」「写作口吻」「禁止现代用语」等），把它们标成 `importance=5` 会让它们背负「关键实体」语义（UI 星标、`known_entities` 去重、属性修改高置信度），语义错位。
2. 用户需要一种**开关形式**的「强制注入」控制：手动指定某个实体「始终注入」，并可指定注入去向（世界设定 / 常驻指令），**独立于 1–5 评分**。

目标：在不退化记忆系统护城河的前提下，把「常驻注入」与「关键实体评分」两个概念拆开，并支持非世界设定类常驻内容的正确落位。

---

## 2. 概念定位（已确认）

### 2.1 三态开关

新增枚举 `ForceInjectTarget`：

| 值 | 语义 |
|---|---|
| `none`（默认） | 不强制注入，走原有 importance 评分 + 关键词命中逻辑 |
| `world` | 始终注入到【世界设定】区块 |
| `directive` | 始终注入到新的【常驻指令】区块（用于非世界设定类的常驻约束，如文风限制） |

### 2.2 与「评分等级 5 强制注入」的区别

| | 评分等级 5（`importance≥5`） | 强制注入开关（`forceInject`） |
|---|---|---|
| 控制形式 | 1–5 评分 | 三态开关 |
| 语义 | 关键实体（主角级） | 「这个实体始终要注入」 |
| 注入去向 | 固定【世界设定】 | 可指定 世界设定 / 常驻指令 |
| 附带效应 | 星标、`known_entities`、属性高置信度 | 无（纯检索偏好） |

### 2.3 只读关系（关键，已确认）

开关是**检索层偏好**，不改变实体内容：

- 不修改 `primaryName`/`aliases`/属性，**不破坏世界书/角色卡「完全冻结」只读承诺**。
- **不影响 FactApplier 的只读写入守卫**：世界书实体仍全跳过、角色卡基线仍只读。
- 开关只影响 retrieving 阶段「注不注入、注入到哪」，与 persisting 阶段无关。

## 3. 数据模型（已确认）

### 3.1 字段

`factual_entities` 加一列：

```
forceInject TEXT NOT NULL DEFAULT 'none'   -- none | world | directive
```

`FactualEntity` 加 `forceInject` 字段（`ForceInjectTarget`，默认 `none`）。

### 3.2 迁移 v37

（写作时点 `schemaVersion=36`；本设计实施后为 v37，当前 Schema 已演进至 43。）v37：

1. `ALTER TABLE factual_entities ADD COLUMN forceInject TEXT NOT NULL DEFAULT 'none'`
2. 回填：`UPDATE factual_entities SET forceInject='world' WHERE source='worldbook' AND importance=5`
3. 数据修正：`UPDATE factual_entities SET importance=2 WHERE source='worldbook' AND importance=5`（把已投影的 constant 词条从「评分 5」迁成「开关 world + 评分 2」，见 §3.3）

> 说明：v36 前世界书 constant 词条以 `importance=5` 区分，回填将其转为 `forceInject='world'`。

### 3.3 `constant` 映射变更（修订 DOC-15 §6.2）

`resource_projection_service.dart` 原 `importance: entry.constant ? 5 : 2` 改为：

- `forceInject: entry.constant ? ForceInjectTarget.world : ForceInjectTarget.none`
- `importance: 2`（constant 与非 constant 统一为 2，评分不再承载「常驻」语义）

### 3.4 开关存储决策（已确认）

采用**实体行加列**而非独立 override 表：实体行本就是会话级实例（投影时每会话一份），开关作为实体行上的「注入偏好」字段即可，`getEntities`/`getKeyEntities` 直接带出、管线侵入最小。开关仅检索层消费，不影响只读/写入语义。

---

## 4. 注入管线（已确认）

### 4.1 两桶两区块

`FactContextBuilder.buildFactBlock` 改为：

- **世界设定桶** = 关键实体（`importance≥keyEntityImportanceThreshold`）∪ 强制注入（`world`）∪ 关键词命中 / 世界书 FTS
- **常驻指令桶** = 强制注入（`directive`）

去重：按 `entityId` 去重，同一实体只出现一次（`forceInject` 优先级最高，其次关键实体，其次关键词命中）。

### 4.2 上限

- 关键实体 + 强制注入实体 = **保底始终注入**，不参与 `injectionMaxEntities`（20）截断。
- 关键词命中实体填充剩余配额至 20。
- 强制注入实体总数受**兜底上限** `forceInjectSafetyCap`（默认 50）约束，防大量开开关撑爆 prompt（超限记警告、按 importance 降序截断）。

### 4.3 归档优先

`isArchived=true` 的实体即使 `forceInject≠none` 也**不注入**（归档优先）。含世界书 `disabled`（映射为 `isArchived=true`）的词条。

### 4.4 输出

输出仍为**单个 `factBlock` 字符串**，内含两节：

1. 【世界设定】（现有格式，追加 `forceInject=world` 实体）
2. 【常驻指令】（新，仅当有 `forceInject=directive` 实体时输出）

沿用现有 `hasFactBlock` / token 计数 / 消息位置，管线侵入最小。

### 4.5 【常驻指令】格式

```
【常驻指令】
- 标题1：内容
- 标题2：内容
```

每实体一行，属性按 attrKey 聚合（基线在前、演变在后），风格对齐【世界设定】。标题可配置 `directiveInjectionTitle`，默认「常驻指令」。

## 5. `known_entities` 去重（修订，已确认）

constant 解耦后世界书实体 `importance=2`，将退出 `known_entities`（原 `importance≥4` 才进）。为保证世界书去重（DOC-15 §8.2），`buildKnownEntitiesBlock` 改为：**`source=worldbook` 的未归档实体无论 importance 都进 `known_entities`**（保留 `[只读设定]` 标记）。

---

## 6. Repository API

- 新增 `updateEntityForceInject(entityId, ForceInjectTarget)`：只改 `forceInject` 列，**豁免内容只读守卫**（世界书/角色卡实体可改开关）。
- 新增 `batchUpdateForceInject(List<String> entityIds, ForceInjectTarget)`：批量，事务内执行。
- `getEntities`/`getKeyEntities` 已带出 `forceInject` 字段（自动）。

---

## 7. 记忆库 UI（批量勾选，已确认）

- 顶部「多选」入口 → 进入勾选模式，每个实体卡带勾选框。
- 底部操作栏：「强制注入：关 / 世界设定 / 常驻指令」+「取消选择」。
- 归档实体在勾选模式中禁用（归档优先，不可被强制注入）。
- 开关操作不受实体 `source` 只读守卫限制（只改注入偏好）。

---

## 8. `deleteFactsByTurns` 回滚

`deleteFactsByTurns` 的回滚逻辑**不动 `forceInject` 列**（用户手动偏好，非故事 delta，不应被轮次回滚清除）。

---

## 9. 配置

`FactualConfig` 加 `forceInjectSafetyCap`（int，默认 50）。`PromptsConfig` 加 `directiveInjectionTitle`（String，默认「常驻指令」），与既有 `factInjectionTitle` 对齐。

---

## 10. 测试要点

- 迁移 v37 幂等、回填正确、不丢数据。
- `constant→forceInject=world` 解析正确，`importance=2`。
- `buildFactBlock` 两桶注入、去重、上限（保底 + 兜底 50）、归档优先。
- `known_entities` 世界书永远进。
- 批量 UI 开关 + 只读守卫豁免。
- `deleteFactsByTurns` 不动 `forceInject`。
