## 5. SettingsRepository（全局配置与 API Key 管理）

**所属模块**: Settings
**版本**: v0.1
**职责**: 全局配置读写、API Key 安全存取
**接口定义位置**: `features/settings/domain/repositories/settings_repository.dart`

### 5.1 接口定义

```dart
abstract class SettingsRepository {
  // ─── API Key 管理 ───

  /// 安全存储 API Key（flutter_secure_storage）
  /// 异常: QueryException (E301)
  Future<void> saveApiKey(String presetId, String apiKey);

  /// 读取 API Key（每次请求时动态读取，不缓存）
  /// 返回 null 表示未设置
  Future<String?> getApiKey(String presetId);

  /// 删除 API Key
  /// 异常: QueryException (E301)
  Future<void> deleteApiKey(String presetId);

  // ─── 全局配置 ───

  /// 获取用户覆盖配置（SharedPreferences）
  Future<Map<String, dynamic>> getUserOverrides();

  /// 设置用户覆盖项
  /// 异常: QueryException (E301)
  Future<void> setUserOverride(String key, dynamic value);

  /// 移除用户覆盖项（恢复默认）
  /// 异常: QueryException (E301)
  Future<void> removeUserOverride(String key);

  /// 获取合并后的完整配置（默认 + 用户覆盖）
  /// 实现委托给 Core 层 ConfigLoader.loadDefaultConfig() + Preferences
  Future<AppConfig> getResolvedConfig();

  /// 清空所有用户覆盖项（恢复全部默认值）
  ///
  /// 用于数据导入覆盖模式。
  /// 异常: QueryException (E301)
  Future<void> clearAllUserOverrides();

  /// 获取用户覆盖项数量
  Future<int> getUserOverrideCount();
}
```

> **v1.2 变更说明**：移除 `loadDefaultConfig()`（与 ConfigLoader 功能重叠），SettingsRepository 的 `getResolvedConfig()` 实现委托给 ConfigLoader + Preferences。

> **v1.3 变更说明**（提示词白盒化）：`setUserOverride` / `removeUserOverride` 新增一类覆盖 key 模式——`intermediate.prompts.{fieldKey}`（共 9 个 fieldKey：`default_role_prompt` / `draft_suffix` / `draft_suffix_json` / `revise_suffix` / `revise_suffix_json` / `compact_revise_suffix` / `compact_revise_suffix_json` / `draft_injection_prefix` / `memories_injection_title`）。
>
> **存储机制**：与现有扁平 key（如 `intermediate.system_prompt`）一致，通过 SharedPreferences 持久化。`ConfigLoader._expandFlatKeys` + `_deepMerge` 将扁平 key 展开为嵌套 JSON 后合并到 `intermediate.prompts` 子节点，最终由 `PromptsConfig.fromJson` 反序列化。字段值为空串或 key 被移除时，回落到 `intermediate_prompts.dart` 常量。
>
> **UI 入口**：「故事模式设置 → 提示词模板」页面（`IntermediatePromptsSection` + `IntermediatePromptEditorPage`）。详见 DOC-09B §10.4、DOC-06B §6.10。

> **v1.5 变更说明**（2026-07-21 配置架构重构）：`setUserOverride` / `removeUserOverride` 新增一类覆盖 key 模式——`common.title_model.preset_id` / `common.title_model.model_id`（共 2 个字段），用于会话标题生成的跨模式共享配置（Simple / Intermediate 模式共用），独立于会话级模型配置。
>
> **存储机制**：与其他扁平 key 一致，通过 SharedPreferences 持久化。`ConfigLoader._expandFlatKeys` + `_deepMerge` 将扁平 key 展开为嵌套 JSON 后合并到 `common.title_model` 子节点，最终由配置加载层反序列化为 `TitleModelConfig`（含 `presetId` / `modelId` 两字段）。字段值为空串或 key 被移除时，回落到 `default_config.json` 中 `common.title_model` 节点的默认值。
>
> **使用方**：`ConfigurationResolver.resolveTitleNamingConfig()` 无参方法读取此节点（替代已删除的 `resolveNamingConfig(ChatSession)` / `resolveIntermediateNamingConfig(ChatSession)`）。**2026-09-09 标题模型三级优先级**：本节点未配置时不再直接前缀截取，调用方依次回落——先取该会话生成正文的模型（Simple `resolveBroadcastGeneratingNamingConfig` / 故事 `resolveIntermediatePhaseNamingConfig` 'generating' / 导演 `resolveAdvancedGeneratingNamingConfig`），仍不可用才由 `SessionTitleGenerator.fallbackTitle` 前缀兜底。
>
> **UI 入口**：「设置 → 通用 → 标题生成模型」页面（跨模式共享设置项）。详见 DOC-02 §7.1、DOC-08 §3.1、DOC-09C §10.2。

> **v1.6 变更说明**（2026-07-22 配置快照语义）：`setUserOverride` / `removeUserOverride` 新增 4 个覆盖 key——`broadcast_chat.temperature` / `broadcast_chat.top_p` / `broadcast_chat.max_tokens` / `broadcast_chat.stream_enabled`，作为 Simple 模式新会话物化的"快照源"全局生成参数。由 `SettingsNotifier` 管理 4 个 `SettingsState` 字段（`globalTemperature` / `globalTopP` / `globalMaxTokens` / `globalStreamEnabled`）和对应 setters（`setGlobalTemperature` / `setGlobalTopP` / `setGlobalMaxTokens` / `setGlobalStreamEnabled`），持久化到上述 user_override key。setters 内含 clamp 逻辑（temperature ∈ [0.0, 2.0]，topP ∈ [0.0, 1.0]，maxTokens 为 nullable int）。
>
> **快照语义**：会话物化时（首条消息 OR 草稿期间首次配置变更），由 `ConfigurationResolver.snapshotSimpleDefaults()` / `snapshotIntermediateDefaults()` 读取当前全局配置生成 `GlobalDefaultsSnapshot`（含 15 字段：modelId/presetId/systemPrompt/temperature/topP/maxTokens/presencePenalty/frequencyPenalty/autoCompaction/compactionThreshold/streamEnabled/maxContextMessages/reasoningEffort/phaseModels/jsonMode），控制器将草稿值与快照值合并后写入 `chat_sessions` 表会话级字段。后续全局配置变更不影响已物化的会话——这是"值快照"而非"引用解析"。
>
> **字段说明**：
> - `streamEnabled`：流式输出开关，来自 `broadcastChat.stream_enabled`，Simple/Intermediate 共享。
> - `jsonMode`：工具调用开关，来自 `intermediate.stream.tool_calling_enabled`，仅 Intermediate 模式物化时填充（Simple 模式 snapshot 保持 null）。两者语义不同，不可混用——此前曾因混淆导致 `jsonModeOverride` 重置时误用 `streamEnabled`。
>
> **ConfigurationResolver snapshot 方法**：`snapshotSimpleDefaults()` 从 `broadcastChat` 全局配置读取（presetId 空时 fallback 到第一个可用 preset，jsonMode 保持 null）；`snapshotIntermediateDefaults()` 从 `intermediate.generation` + `broadcastChat` + `intermediate.phaseModels` + `intermediate.stream.tool_calling_enabled` 读取（空串转 null）。这两个方法已存在，v1.6 起用于完整快照（不只是 modelId/presetId），v1.7 新增 `jsonMode` 字段。
>
> **UI 入口**：「设置 → 对话模式 → 新对话默认生成参数」区段（`GlobalGenerationDefaultsSection` widget），暴露 4 个全局生成参数。详见 DOC-06 §3.6。

> **v1.9 变更说明**（2026-07-29 推荐回复功能）：`ConfigurationResolver` 新增 2 个推荐回复专用方法（接口注释详见 DOC-05-3 §3.4.3）：
>
> - `resolveSuggestReplyNamingConfig(ChatSession session) → Future<NamingConfig?>`：推荐回复模型解析。**优先级链**：(1) 会话级 `suggestReplyPresetId` / `suggestReplyModelId` → (2) 全局 `intermediate.suggest_reply.preset_id` / `model_id` → (3) drafting 阶段模型 fallback（复用 `resolveIntermediatePhaseNamingConfig(session, 'drafting')`）。返回 null 表示所有层级均未配置（含 drafting fallback 也失败），调用方应禁用推荐回复按钮。
> - `resolveSuggestReplyPrompt(ChatSession session) → Future<String>`：推荐回复提示词解析。**优先级链**：(1) 会话级 `suggestReplyPromptOverride` → (2) 全局 `intermediate.suggest_reply.prompt` → (3) 内置默认 `kSuggestReplyDefaultPrompt`（定义在 `core/config/intermediate_prompts_v2.dart`）。
>
> **存储机制**：会话级 3 字段（`suggestReplyPresetId` / `suggestReplyModelId` / `suggestReplyPromptOverride`）持久化到 `chat_sessions` 表（schemaVersion=30 新增）；全局配置通过 `intermediate.suggest_reply.*` user_override key 持久化到 SharedPreferences，由 `ConfigLoader._expandFlatKeys` + `_deepMerge` 展开合并到 `intermediate.suggest_reply` 子节点，`SuggestReplyConfig.fromJson` 反序列化。
>
> **使用方**：`IntermediateChatController.generateSuggestReplies()` 调用这两个方法解析模型与提示词后，委托 `SuggestReplyGenerator.generate()` 调用 LLM。详见 DOC-09D §7.2、DOC-06B §6.6A/§6.6B。

## 6. ApiPresetRepository（API 预设管理）

**所属模块**: Settings
**版本**: v0.1
**职责**: API 预设的完整管理（含内置供应商和自定义预设）
**接口定义位置**: `features/settings/domain/repositories/api_preset_repository.dart`

### 6.1 接口定义

```dart
abstract class ApiPresetRepository {
  // ─── 预设 CRUD ───

  /// 获取全部预设（含内置 + 自定义）
  Future<List<ApiPreset>> getAllPresets();

  /// 获取单个预设
  /// 异常: ModelNotFoundException (E007)
  Future<ApiPreset> getPreset(String presetId);

  /// 创建自定义预设
  /// 异常: QueryException (E301)
  Future<ApiPreset> createPreset({
    required String name,
    required String baseUrl,
  });

  /// 更新预设（内置预设触发 fork-on-write：自动复制为自定义预设）
  /// [updater] 接受当前 ApiPreset，返回修改后的 ApiPreset
  /// 返回更新后的预设（如果是内置预设，返回新创建的自定义副本）
  /// 异常: ModelNotFoundException (E007), InvalidConfigurationException (E002), QueryException (E301)
  Future<ApiPreset> updatePreset(
    String presetId,
    ApiPreset Function(ApiPreset current) updater,
  );

  /// 删除预设（内置预设不可删除，抛出 InvalidConfigurationException）
  ///
  /// 2026-07-17 修订：SettingsNotifier.deletePreset 在调用本方法后，
  /// 会级联清理 user_overrides 中所有引用该 presetId 的 key
  /// （broadcast_chat/intermediate 的 preset_id+model_id、
  /// intermediate.embedding_*、intermediate.phase_models.*_preset_id+model_id、
  /// common.title_model.preset_id+model_id【2026-07-21 配置架构重构新增】），
  /// 避免删除供应商后设置页因悬空引用飘红。会话级 chat_sessions.preset_id
  /// 由运行时 resolvePhaseNamingConfig 兜底降级，不在此清理范围。
  /// 异常: InvalidConfigurationException (E002), QueryException (E301)
  Future<void> deletePreset(String presetId);

  // ─── 模型列表 ───

  /// 从 API 获取可用模型列表（GET /v1/models）
  /// [presetId] 预设 ID
  /// 返回的 ModelInfo 列表已通过 models.dev registry enrich（填充 type/capabilities/contextWindow/maxOutput）
  /// 异常: ConnectionException (E102), ApiException (E103), InvalidApiKeyException (E201)
  Future<List<ModelInfo>> fetchModels(String presetId);

  /// 更新预设的模型列表（缓存到本地）
  /// 异常: QueryException (E301)
  Future<void> updateModelList(String presetId, List<ModelInfo> models);

  // ─── 内置供应商 ───

  /// 初始化内置供应商（应用启动时调用）
  /// 仅在首次启动时写入，已存在则跳过
  Future<void> ensureBuiltInPresets();

  /// 删除所有自定义供应商（保留内置供应商）
  ///
  /// 用于数据导入覆盖模式。同时清除关联的 API Key。
  /// 异常: QueryException (E301)
  Future<void> deleteAllCustomPresets();

  /// 获取自定义供应商数量（不含内置）
  Future<int> getCustomPresetCount();
}
```

### 6.3 Fork-on-Write 策略（v1.8 已废弃）

> **v1.8 变更**（DOC-12 v1.1 同步）：Fork-on-Write 机制已废弃，改为覆盖式更新策略（借鉴 ChatBox），详见下方"覆盖式策略"小节。本节保留历史描述供参考。

```
[已废弃] 用户修改内置预设 (isBuiltIn = true)
  │
  ├── 1. 复制内置预设为自定义预设（新 ID，isBuiltIn = false）
  ├── 2. 应用用户修改到自定义副本
  ├── 3. 返回自定义副本
  └── 4. 原内置预设保持不变
```

#### 6.3.1 覆盖式更新策略（v1.8+）

```
[当前实现] 用户修改内置预设 (isBuiltIn = true)
  │
  ├── 1. 直接 UPDATE 原内置预设行（不再复制副本）
  ├── 2. 应用用户修改到原行（覆盖 baseUrl/apiKey/cachedModels 等字段）
  └── 3. 提供"重置"功能：清空用户覆盖字段，从 ProviderTemplates 恢复默认值
```

- **触发条件**：所有 preset 的修改都走覆盖式（内置/自定义无差异）
- **重置**：仅内置 preset 支持重置（清空覆盖字段，恢复模板默认 baseUrl/protocol）
- **基于模板新建**：从 `ProviderTemplates` 复制 protocol/baseUrl 到新行（`isBuiltIn=false`），支持同一供应商多账号
- **协议锁定**：所有 preset 的 `protocol` 字段在创建后不可修改（内置 preset 代表模板协议，自定义 preset 在创建时选定后锁定），详见 §6.5 LlmProtocol

### 6.5 LlmProtocol 枚举（v1.8 新增，DOC-12 §3.1）

**所属模块**: Settings（Domain 层枚举）
**版本**: v1.8（DOC-12 v1.1 同步）
**职责**: 决定 LlmProtocolAdapter 的分发目标。每个 ApiPreset 持有一个协议类型，运行时按此字段选择对应的适配器构造请求 URL/Header/Body 并解析响应/SSE。
**接口定义位置**: `features/settings/domain/entities/llm_protocol.dart`

```dart
enum LlmProtocol {
  openaiCompatible,    // OpenAI Chat Completions 兼容协议（/v1/chat/completions）
  openaiResponses,     // OpenAI Responses API（/v1/responses，v0.3+ 适配，本期不实现）
  anthropic,           // Anthropic Messages API（/v1/messages，原生协议）
  geminiNative;        // Google Gemini generateContent（/v1beta/models/{model}:generateContent）

  String toJson() => name;  // 序列化为 JSON 字符串（存入 api_presets.protocol 列）

  /// 从 JSON 字符串反序列化
  /// 未知值回退到 [openaiCompatible]（兼容旧版本数据 + 用户手填协议场景）
  static LlmProtocol fromJson(String? value);

  /// 中文显示名（用于 UI 展示协议类型）
  String get displayName;  // 'OpenAI 兼容' / 'OpenAI Responses' / 'Anthropic Claude' / 'Google Gemini'
}
```

**4 值语义**：
- `openaiCompatible`：适用 OpenAI、DeepSeek、OpenRouter 及各类第三方兼容供应商（默认值）
- `openaiResponses`：适用 OpenAI 官方 Responses API（v0.3+ 适配，本期 LlmAdapterFactory 抛 UnimplementedError）
- `anthropic`：适用 Anthropic Claude 系列
- `geminiNative`：适用 Google Gemini 系列（AI Studio API Key 方式）

详见 DOC-12 §3.1。

### 6.6 ProviderTemplate 数据类（v1.8 新增，DOC-12 §4.1）

**所属模块**: Settings（Data 层静态注册表）
**版本**: v1.8（DOC-12 v1.1 同步）
**职责**: 静态注册的内置供应商配置模板。用户基于模板创建自定义 ApiPreset 时，自动继承 protocol 和 defaultBaseUrl，仅需填入 API Key 即可使用。不预填模型列表（符合"模型迭代快"要求，避免下架/更新导致的隐性问题）。
**接口定义位置**: `features/settings/data/provider_templates.dart`

```dart
class ProviderTemplate {
  const ProviderTemplate({
    required this.templateId,
    required this.name,
    required this.protocol,
    required this.defaultBaseUrl,
    this.websiteUrl,
    this.docsUrl,
    this.apiKeyUrl,
  });

  final String templateId;        // 模板唯一标识（'tpl-openai' / 'tpl-deepseek' 等）
  final String name;              // 显示名
  final LlmProtocol protocol;     // 协议类型（决定 LlmProtocolAdapter 分发目标）
  final String defaultBaseUrl;    // 默认 baseUrl（不含路径，路径由适配器拼接）
  final String? websiteUrl;       // 官网链接（详情页跳转）

  final String? apiKeyUrl;        // 获取 API Key 的链接（详情页引导用户申请）

  /// 从 templateId 推导内置 preset 的 presetId
  /// 约定：'tpl-openai' → 'builtin-openai'（DOC-12 §4.2）
  String get builtInPresetId => 'builtin-${templateId.substring(4)}';
}
```

**所属模块**: Settings（Domain 实体，完整定义见 DOC-05-2 §2.3）
**版本**: v1.8（DOC-12 v1.1 同步）
**职责**: 在原 ApiPreset 实体基础上新增 2 个字段，支持多协议适配与模板溯源。

> **ApiPreset 完整定义见 DOC-05-2 §2.3**，此处仅描述 v1.8 新增字段。

| 字段 | 类型 | 默认值 | 说明 |
|------|------|--------|------|

**字段持久化**（数据库 schema v24，dev 阶段覆盖式重建）：
- `api_presets.protocol`：TEXT 列，存储 `LlmProtocol.toJson()` 字符串（如 `'openaiCompatible'`），默认值 `'openaiCompatible'`
