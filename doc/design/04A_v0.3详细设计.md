## 1. 当前事实（2026-08-19 更新）

- 产品现有“对话”“故事”“导演”（`advanced`，实验性）三个可用入口；导演模式有独立页面（`AdvancedChatPage`）、控制器（`AdvancedChatController` + `DirectorRoundRunner`）与完整 Agent Loop（`lib/features/advanced/`）。
- 导演模式与故事模式共享运行时（`lib/features/story_runtime/`：压缩/持久化/失败分类/重试等），不另建平行存储；事实三表与经历记忆被两模式共同复用。
- 当前实现三类协议：OpenAI-compatible、Anthropic、Gemini；OpenAI Responses 尚未实现。
- 本文 §2 的八项启动门槛问题已在 `doc/design/v0.3.0/` 各文档中逐一决策并实施；§3 的清单可作为评审实现的对照参考，但不是实现的事实来源。

## 2. 详细设计启动门槛

只有在以下决策被记录并获确认后，本文才进入具体类、接口和表设计：

1. 产品入口与用户控制模型；
2. 循环状态机、停止条件、预算和取消语义；
3. 能力白名单、权限与确认策略；
4. 副作用幂等键、事务边界与审计模型；
5. 崩溃恢复、后台限制与跨平台策略；
6. 与现有 `IntermediateChatController` 阶段、轮次产物、事实提取和宏摘要的唯一集成点；
7. 协议能力矩阵和无工具调用协议的降级行为；
8. 威胁模型、敏感数据处理和资源上限。

## 3. 未来详细设计必须包含的内容

- 状态机：每一状态的输入、输出、可重试性和持久化点；
- 数据模型：只增补循环元数据，解释为何不能复用现有表的每个新增字段；
- 能力协议：JSON schema、验证、权限、幂等和回滚/补偿；
- 错误模型：区分规划失败、能力失败、协议不支持、预算耗尽、用户取消和恢复失败；
- UI 行为：步骤列表、确认、取消、恢复和无障碍；
- 测试矩阵：单步、多步、取消、崩溃恢复、重复事件、协议降级、数据迁移和 Web 限制。

## 5. 临时开发规则（已被取代）

> 2026-08-19 更新：本节规则写于 Agent Loop 未实现时。现在导演模式已作为实验性功能上线（设置页开关，默认关闭），"不向用户界面暴露"已被"功能开关 + 实验性标注"的正式机制取代。保留原文仅作历史记录。

在详细设计获批前：

- 不向用户界面暴露 Advanced 或未实现能力；
- 不以“为 Advanced 预留”为由新增数据库表、可选择协议或模板类型；
- 新的故事/记忆功能继续以当前代码和 DOC-10、DOC-11、DOC-13 为准；
- 若试验 Agent Loop，必须置于隔离实验分支，并明确标注不可发布与不可迁移。
