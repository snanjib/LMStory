# 故事模式 · 失败处理术语字典

> **用途**：统一故事模式（Intermediate mode）失败处理相关概念的命名与定义。
>
> **范围**：错误码、错误分类、失败上下文、重试策略、失败处理选项等失败处理范畴的概念。
>
> **状态**：初版。
>
> **维护原则**：记录曾用名、同步更新；当前可执行代码、数据库 Schema 和匹配当前 API 的测试优先，字典与实现冲突时修订字典。

## 一、错误码概念

| 术语 | 英文/代码名 | 定义 | 备注 |
|---|---|---|---|
| 生成失败 | E010 | 生成阶段（generating）的 LLM 请求失败 | 曾用名「草稿生成失败」 |
| 生成格式异常 | E011 | 生成阶段返回的内容格式不符合预期 | 旧版 JSON 解析失败的遗留码；v0.2.2 纯文本输出后较少触发 |
| 检索失败 | E012 | 检索阶段（retrieving）的数据库查询失败 | |
| 提取失败 | E013 | 关键词提取阶段（extracting）的 LLM 请求失败 | |
| **审查失败** | **E014** | 审查阶段（reviewing）的 LLM 请求失败 | **曾用名「修正生成失败」** |
| 审查格式异常 | E015 | 审查阶段返回的内容格式不符合预期 | 旧版 JSON 解析失败的遗留码 |
| 格式重试失败 | E016 | JSON 格式重试次数用尽 | extracting / summarizing 的工具调用降级链失败 |
| 摘要失败 | E017 | 摘要阶段（summarizing）的 LLM 请求失败 | |
| 压缩失败 | E018 | 压缩阶段（compacting）或持久化阶段失败 | 自动重试次数为 0；失败栏仍允许用户手动从中断处继续或整轮重试 |
| 检索降级失败 | E104 | 语义检索 embedding 服务失败 | 默认 `fallbackOnFailure=false`：进入统一三选项失败处理，不静默降级；仅用户显式启用 fallback 时退化为 FTS5-only |

| 术语 | 英文/代码名 | 定义 | 备注 |
|---|---|---|---|
| 错误分类 | ErrorCategory | 错误的类型分类 | 用于 UI 分层展示和统计 |
| 配置错误 | config | 未配置 API 供应商/模型/API Key | |
| 网络错误 | network | 连接失败、DNS 解析失败 | |
| 认证错误 | auth | 401/403、API Key 无效 | |
| 限流错误 | rateLimit | 429 Too Many Requests | |
| 服务器错误 | server | 500/502/503/504 | |
| 超时错误 | timeout | 请求超时 | 区别于网络中断 |
| 格式错误 | format | JSON 解析失败、响应结构异常 | |
| 持久化错误 | persist | 数据库写入失败 | |
| 未知错误 | unknown | 未归类的错误 | |

## 三、失败上下文与重试概念

| 术语 | 英文/代码名 | 定义 | 备注 |
|---|---|---|---|
| 失败上下文 | FailureContext | 携带错误码 + 失败阶段 + 错误分类的上下文对象 | 含 errorMessage / retryable / httpStatus / rawError |
| 重试调度器 | RetryScheduler | 纯决策逻辑：重试次数 / 阶段映射 / 延迟 | 不执行重试，只决策 |
| 自动重试 | *Retry | 各阶段的自动重试状态 | generatingRetry / reviewingRetry 等；按阶段分别计数 |
| 重试次数上限 | maxRetries | 每阶段最大自动重试次数 | 按阶段独立配置 |

## 四、失败处理选项概念

| 术语 | 英文/代码名 | 定义 | 备注 |
|---|---|---|---|
| 整轮取消 | cancel | 丢弃本轮所有中间产物（生成正文/关键词/检索结果/摘要） | 用户消息气泡移除，内容通过 userInput 回填到输入框（页面层检测回写机制） |
| 中断处重试 | continueFromFailed | 保留已完成阶段产出，从失败阶段继续 | 复用 _round 中的阶段产出 |
| 整轮重试 | retryFromStart | 保留用户消息，从头重新执行 | 等价于重新 sendMessage |
| 三选项失败处理 | - | 统一的失败处理选项 | v0.2.2 引入；三种选项适用于所有阶段失败 |

> 失败处理 UI 交互见 [交互与UI.md](交互与UI.md)。

## 五、状态恢复与消息操作概念

| 术语 | 英文/代码名 | 定义 | 备注 |
|---|---|---|---|
| clearUserInput | clearUserInput | 清空 State.userInput 字段 | 页面层把 userInput 回写到输入框后调用，避免重复触发回写逻辑 |
| 编辑消息内容 | editMessageContent | 仅更新数据库中消息文本，不清理记忆、不删除下游 | 适用于修正错别字等小修改，与编辑重发(editAndResend)的区别是不重新生成 |
| 更新临时消息文本 | updatePendingUserMessageContent | 仅更新内存中的 pendingUserMessage 文本 | 不持久化、不发送，用于用户编辑未发送消息后只保存修改 |
| 后台恢复检测 | recoverIfStuck | App 从后台恢复时检测流式阶段卡死状态 | 清空 pendingUserMessage + 保留 userInput，恢复到 idle |
