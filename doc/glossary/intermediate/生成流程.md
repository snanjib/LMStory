# 故事模式 · 生成流程术语字典

> **用途**：统一故事模式（Intermediate mode）生成流程相关概念的命名与定义，消除代码与文档中的术语歧义。
>
> **范围**：v0.2.2 故事模式生成流程涉及的阶段、产物、流程编排、Prompt 结构、流式显示、配置等概念。上下文空间分配见 [上下文工程术语字典](上下文工程.md)，检索算法见 [检索系统术语字典](检索系统.md)，记忆系统见 [记忆系统术语字典](记忆系统.md)。
>
> **状态**：v0.2.2 术语变更落地中。阶段名从「草稿/终稿」变更为「生成/审查」，代码枚举值及阶段专属代码名同步更改。
>
> **维护原则**：
> - **记录曾用名**：术语变更时在备注中记录旧称，避免代码/文档中的过时引用造成误解
> - **同步更新**：每次术语调整须同步更新代码、文档与用户可见文本，并在变更记录中登记
> - **权威顺序**：当前可执行代码、数据库 Schema 和匹配当前 API 的测试优先；本字典负责记录统一术语，若与代码事实冲突必须修订本字典

## 一、阶段术语

| 术语 | 英文/代码名 | 定义 | 备注 |
|---|---|---|---|
| 空闲 | idle | 无生成任务进行中 | |
| 压缩阶段 | compacting | 检查 token 阈值，超限时压缩旧对话为摘要前缀 | 可选，条件触发；七阶段事务最前置阶段 |
| 关键词提取阶段 | extracting | 从用户输入 + 近期对话提取 5 类关键词 | v0.2.2 前置到生成阶段之前 |
| 检索阶段 | retrieving | 用 5 类关键词驱动 5 路并行检索 | |
| **生成阶段** | **generating** | 注入记忆生成回复正文 | **曾用名「草稿阶段」(drafting)**；v0.2.2 改造：检索前置后注入记忆 |
| **审查阶段** | **reviewing** | 基于生成内容 + 记忆进行审查修正 | **曾用名「终稿阶段」(revising)**；可选，reviewEnabled 控制，默认关闭 |
| 摘要阶段 | summarizing | 提取事件摘要写入经历记忆 | |
| 持久化阶段 | persisting | 整轮事务写入数据库 | 7 步合一 |
| ~~独立宏摘要阶段~~ | ~~macroSummarizing~~ | **已废弃的旧阶段** | 当前没有独立 macroSummarizing 阶段；分段宏摘要由压缩服务在发生压缩时生成并在 persisting 阶段写入 |
| 失败 | failed | 生成流程失败 | |
| 生成重试 | generatingRetry | 生成阶段的自动重试状态 | **曾用名 draftingRetry** |
| 审查重试 | reviewingRetry | 审查阶段的自动重试状态 | **曾用名 revisingRetry** |

> **七阶段事务**（v0.2.2 架构调整）：
> `compacting? -> extracting -> retrieving -> generating -> reviewing? -> summarizing -> persisting -> idle`
> 其中 compacting 与 reviewing 为可选阶段。未触发压缩时默认 3 次 LLM 调用（extracting + generating + summarizing），开启审查后 4 次；触发压缩时，首次压缩增加 1 次摘要调用，后续压缩并行增加压缩摘要与分段宏摘要 2 次调用。

## 二、阶段产物术语

| 术语 | 英文/代码名 | 定义 | 备注 |
|---|---|---|---|
| **生成正文** | **generatedText** | 生成阶段产出的回复正文 | **曾用名「草稿正文」(draftText)** |
| 回复正文 | replyText | 最终回复给用户的正文 | 审查关闭时 = 生成正文；代码名不变（reply 为中性词） |
| 关键词 | classifiedKeywords | 提取阶段产出的 5 类关键词 | characters/items/locations/actions/plots |
| 检索结果 | scoredMemories | 检索阶段产出的记忆列表 | 含综合评分 |
| 检索事实 | retrievedFacts | 检索阶段产出的事实层命中 | DOC-11 §6.1 |
| 事件摘要 | eventSummary | 摘要阶段产出的事件摘要（5W1E） | 写入 experiential_memories |
| 事实变更 | factsDeltas | 摘要阶段产出的事实变更列表 | 工具调用返回 |
| 压缩摘要 | compactionSummary | 压缩阶段产出的累积式旧对话骨架摘要，用作稳定上下文前缀 | token 上限 8000；与写入经历记忆并参与检索的分段宏摘要职责分离 |
| **审查执行标记** | **reviewExecuted** | 记录本轮是否执行了审查阶段 | **曾用名 reviseExecuted**；artifacts 字段 |
| 轮次产物 | IntermediateRoundArtifacts | 持久化后的轮次快照 | 含生成正文/关键词/检索结果/回复正文/摘要 |

## 三、流程编排术语

| 术语 | 英文/代码名 | 定义 | 备注 |
|---|---|---|---|
| 轮次 | round / turn | 一次完整的生成流程 | |
| 轮次上下文 | RoundContext | 承载各阶段输入参数与产出的对象 | 各阶段产出随推进填充 |
| 整轮事务性 | - | 生成阶段的中间产物在最终持久化成功前不形成半成品最终状态；持久化事务中的非事实层错误会整体回滚 | compacting -> extracting -> retrieving -> generating -> reviewing? -> summarizing -> persisting；FactsDelta 单项失败由 FactApplier 捕获并跳过，不回滚整轮 |
| **生成即最终** | - | 审查关闭时，生成正文直接作为最终回复 | **曾用名「草稿即终稿」** |
| 重新生成 | regenerate | 丢弃原回复重新执行生成流程 | |
| **降级跳过** | **skipReview** | 旧版降级标记（检索为空时跳过审查） | **曾用名 skipRevise**；v0.2.2 废弃，恒为 false；代码残留待清理 |

## 四、Prompt 结构术语

| 术语 | 英文/代码名 | 定义 | 备注 |
|---|---|---|---|
| 系统提示词 | systemPrompt | 全局或会话级的角色设定 | 用户可配置 |
| 角色提示词 | rolePrompt | 故事模式叙述者视角的生成规则 | generating 与 reviewing 均为第一条 system，用于复用最稳定的缓存前缀 |
| **审查后缀** | **reviewSuffix** | 审查阶段的审查修正指令 | **曾用名「修订后缀」(reviseSuffix)** |
| **生成内容注入** | **generatedInjection** | 审查阶段把生成正文喂给 LLM 的前缀标注 | **曾用名「草稿注入」(draftInjection)** |
| ~~旧审查提示词标记~~ | ~~--审查提示词--~~ | 旧版单消息 Prompt 的分隔文字 | 当前 V2 不使用该标记：审查提示词是第二条独立 system 消息；更早曾用「--终稿提示词--」 |
| 待审查内容标记 | 【需要审查的生成内容】 | reviewing 末尾 user 消息中分隔用户输入与生成正文的当前标记 | 当前结构为 `【用户消息】...【需要审查的生成内容】...`；旧版曾用「--草稿内容--」「--生成内容--」 |
| **生成版后缀** | **generatingSuffixV2** | 生成阶段的差异后缀（纯文本生成指令） | **曾用名「草稿版后缀」(draftSuffixV2)** |
| **审查版后缀** | **reviewSuffixV2** | 审查阶段的差异后缀（纯文本审查指令） | **曾用名「修正版后缀」(reviseSuffixV2)** |
| 稳定前缀 | stablePrefix | 跨请求不变的前置消息，提升缓存命中率 | generating/extracting 可复用角色提示词 + 压缩摘要 + 未变化的旧历史；reviewing 方案D不带压缩摘要或历史，仅复用第一条角色提示词 |
| 双 system 结构 | - | 审查阶段开头的 prompt 结构 | 第一条 system = 角色提示词，第二条 system = 审查提示词；之后按需加入世界设定/相关往事，末尾 user 合并用户消息与待审查生成内容 |
| 事实层注入 | factBlock | 【世界设定】块 | system 角色注入；详见 [检索系统.md](检索系统.md) |
| 往事注入 | memoriesInjection | 【相关往事】块 | system 角色注入；详见 [检索系统.md](检索系统.md) |

> 生成阶段消息结构和缓存命中设计见 `doc/design/13_故事模式上下文机制设计.md` §4。
> 审查阶段消息结构见同文档 §5。

## 五、流式显示术语

| 术语 | 英文/代码名 | 定义 | 备注 |
|---|---|---|---|
| **生成流式内容** | **streamingGenerated** | 生成阶段实时输出的文本 | **曾用名 streamingDraft** |
| **生成思考内容** | **streamingGeneratedThinking** | 生成阶段的 reasoning tokens | **曾用名 streamingDraftThinking** |
| 回复流式内容 | streamingReply | 审查阶段实时输出的文本 | 代码名不变（reply 为中性词） |
| 冻结前缀渲染 | frozen-prefix chunked rendering | 流式正文按「已定稿前缀 + 活动增量块」分块渲染：滚动视口外的已完成块不随流式追加重建，仅活动块逐帧更新（StreamingMarkdownBody 共享组件，chat/故事气泡与导演稿件卡共用，2026-09-04 引入） | 上滚阅读时冻结跟随、增量 32ms 合帧、jumpTo 直贴配套 |
| 增量合帧 | delta coalescing | 流式增量按 32ms 窗口合并成一帧再送渲染，避免逐 token 触发布局 | 导演直播稿件/故事与导演手动压缩摘要打字机共用（AgentLiveDeltaCoalescer） |

> 审查开启时：生成流式内容显示在生成面板，回复流式内容显示在回复气泡。
> 审查关闭时：不显示生成面板，生成流式内容直接显示在回复气泡（生成即最终）。
