# 故事模式 · 上下文工程术语字典

> **用途**：统一故事模式（Intermediate mode）上下文工程相关概念的命名与定义，消除代码与文档中的术语歧义。本字典仅覆盖上下文工程范畴，不是整个项目的通用术语字典。
>
> **范围**：v0.2.2 故事模式上下文工程涉及的概念，包括空间分层、内容分区、近期对话区管理、压缩、上下文预算配置等。阶段与生成流程见 [生成流程术语字典](生成流程.md)，检索算法见 [检索系统术语字典](检索系统.md)，记忆系统见 [记忆系统术语字典](记忆系统.md)。
>
> **状态**：v0.2.2 术语调整：阶段术语已移至 [生成流程.md](生成流程.md)，检索术语已移至 [检索系统.md](检索系统.md)，注入内容术语已分配至两者。
>
> **维护原则**：
> - **记录曾用名**：术语变更时，在备注中记录旧称，避免代码/文档中的过时引用造成误解
> - **同步更新**：每次术语调整须同步更新本字典并在变更记录中登记
> - **权威顺序**：当前可执行代码、数据库 Schema 和匹配当前 API 的测试优先；本字典负责记录统一术语，若与代码事实冲突必须修订本字典

## 一、空间分层概念

| 术语 | 英文/代码名 | 定义 | 备注 |
|---|---|---|---|
| 模型上下文上限 | contextWindow | 模型规格决定的上下文 token 总上限，输入与输出共享 | 压缩触发线以此为基准；曾用名「上下文窗口」「模型上下文窗口」 |
| 输出上限 | maxTokens | 用户配置的单次生成输出限制；0 表示不设置应用层输出上限 | 正数会在模型最大输出元数据已知时取较小值；OpenAI/Gemini 的 0 映射为省略协议字段，Anthropic 的 0 映射为模型 maxOutput |
| 输出预留 | outputTokenReserve | 上下文组装为模型输出保留的空间 | 与 API 输出上限分开计算：maxTokens>0 时取配置值与模型 maxOutput 的较小值；maxTokens=0 时固定为 8192 |
| 可用窗口 | availableWindow | 模型上下文上限扣除输出预留后的空间，即 `contextWindow - outputTokenReserve` | ContextBuilder 的检索区与历史组装运行时计算基准；近期对话下限也以此计算 |
| 上下文组装空间 | assemblySpace | 可用窗口扣除固定开销和检索区预留后，可分配给对话历史的空间 | 曾用名「剩余空间」/ `remaining`；V2 代码已使用 `assemblySpace` |
| ~~预算~~ | ~~budget~~ | **已废弃作为空间术语** | 原歧义：局部变量=可用窗口、dialogueBudget=对话空间、ContextBudget=配置类三者同名 |

> 详细设计见 `doc/design/13_故事模式上下文机制设计.md`；当前公式以 `IntermediateContextBuilder` 与 `IntermediateCompactionService` 的可执行实现为准。

## 二、内容分区概念

| 术语 | 英文/代码名 | 定义 | 备注 |
|---|---|---|---|
| 基础上下文部分 | systemTokens + compactionTokens + userTokens | 角色提示词、压缩摘要、用户输入等不可截断内容所占的空间 | 曾用名「固定部分」「固定开销」；"基础"指不可截断，非内容不变 |
| 固定开销上限 | fixedBudgetCap | 基础上下文部分各组件的 token 硬上限之和 | v0.2.2 修订引入，防止固定开销膨胀挤压历史空间 |
| 检索注入区 | memoriesTokens + factBlockTokens | 事实层注入块 + 经历记忆注入块所占的空间 | 曾用名「检索区」 |
| 近期对话区 | dialogueBudget / reducedHistory | 最近 n 轮对话原文（user + assistant 消息）所占的空间 | 曾用名「原文区」 |
| 对话历史 | history / dialogueMessages | 全部历史消息（含已压缩的旧消息） | 数据库层概念 |
| 近期对话 | recentMessages | 压缩后保留的最近 n 轮原文 | 与"近期对话区"是数据视角 vs 空间视角 |

> 固定开销上限明细见 `doc/design/13_故事模式上下文机制设计.md` §3。

## 三、近期对话区相关概念

| 术语 | 英文/代码名 | 定义 | 备注 |
|---|---|---|---|
| 近期对话区下限 | recentMinRatio | 压缩后保留的近期对话量，确保压缩后仍有足够历史对话携带 | null 时基于 recentMinTokenTarget 反推；曾用名「原文区下限」 |
| 近期对话区下限目标 | recentMinTokenTarget | 动态计算下限时的目标 token 数 | 默认 32000；曾用名「原文区下限目标」 |
| 历史极限裁剪 | _reduceHistory | 组装请求时按 assemblySpace 保留可容纳的近期原文 | 自动压缩是主要机制；该方法仍作为超出模型窗口时的硬性兜底，并非待清理残留 |
| ~~安全余量~~ | ~~dialogueBudgetRatio~~ | **v0.2.2 修订废弃**：原为上下文组装空间中预留的安全缓冲比例 | 曾用名「对话预算比例」；generating 不再使用，由压缩触发线统一控制 |
| ~~近期对话区上限~~ | ~~recentMaxRatio~~ | **v0.2.2 修订移除**：原为近期对话区的容量上限 | 压缩时机改为基于总占用后，"对话区上限"概念无意义；已重新定义为「压缩触发线」（compactionTriggerRatio），移至第四章 |

> 压缩触发条件见 `doc/design/13_故事模式上下文机制设计.md` §5.1。

## 四、压缩相关概念

| 术语 | 英文/代码名 | 定义 | 备注 |
|---|---|---|---|
| 压缩点 | CompactionPoint | 一次压缩操作的持久化标记 | 记录边界、摘要、时间 |
| 压缩摘要 | compactionSummary | LLM 生成的旧对话累积骨架摘要，替代被压缩的原文并作为稳定上下文前缀 | 有 token 上限（8000），防止无限膨胀；与分段宏摘要职责分离 |
| 压缩边界 | boundary / boundaryIndex | 分隔"被压缩"和"保留"的消息索引 | |
| 压缩触发线 | compactionTriggerRatio | 本次请求总占用（固定+检索+历史）达到模型上下文上限的此比例时触发压缩 | 默认 0.5；曾用名 recentMaxRatio；从第三章「近期对话区上限」重新归位至此 |
| 压缩触发判定 | shouldCompact | 阈值检查，基于压缩触发线决定是否压缩 | 仅判断，不执行；v0.2.2 修订为基于总占用 |
| 压缩执行 | compact | LLM 压缩 + 历史替换 | 产出 CompactionResult |
| 分段宏摘要 | segmentMacroSummary / memoryLevel=macro | 对本次新进入压缩区的连续事件生成高密度概览，写入经历记忆并参与长期检索 | 与累积压缩摘要分离；首次压缩可直接以压缩摘要建立 macro 记录 |
| 单轮摘要 | eventSummary | 每轮生成的事件摘要（5W1E），写入经历记忆 | 曾用名「微摘要」；写入 experiential_memories |

## 六、歧义点状态

### 已解决

1. ~~**「原文区」是否包含压缩摘要？**~~ -> **已解决**：近期对话区 = 最近 n 轮对话原文，压缩摘要单独归类为基础上下文部分

2. ~~**「对话历史」和「原文区」的关系？**~~ -> **已解决**：近期对话区是对话历史的子集（压缩后保留的最近 n 轮）

3. ~~**「recentMaxRatio 的分母」是 availableWindow 还是 remaining？**~~ -> **已解决**：该字段已改名为 compactionTriggerRatio，压缩阈值为 `contextWindow × compactionTriggerRatio`；它不等同于检索区或近期对话区的比例基准

4. ~~**「压缩」和「截断」的区别？**~~ -> **已解决**：压缩会调用 LLM 生成可持久化摘要，是主要历史管理机制；_reduceHistory 不生成摘要，仍保留为单次请求的极限空间兜底

5. ~~**「稳定前缀」包含哪些内容？**~~ -> **已解决**：稳定前缀 = 角色提示词 + 压缩摘要。历史紧接稳定前缀后，旧消息部分也能命中缓存。世界设定、相关往事为动态内容，不属于稳定前缀

6. ~~**「预算」（budget）的分母到底是什么？**~~ -> **按配置项分别定义**：compactionTriggerRatio 使用 contextWindow；ContextBuilder 的 retrievalRatio 与 recentMinRatio 使用 availableWindow。当前 CompactionService 对 retrievalRatio 的压缩预估仍使用 contextWindow，与 ContextBuilder 存在待统一差异

### 已解决（续）

7. ~~**「压缩摘要」与「宏摘要」是否是同一份内容？**~~ -> **已解决**：两者职责分离
   - 压缩摘要：累积式，写入 `chat_messages` / `compaction_points`，用于后续请求的稳定上下文前缀
   - 分段宏摘要：仅总结本次新进入压缩区的对话，写入 `experiential_memories`（`memory_level=macro`），参与长期检索
   - 首次压缩没有旧摘要时，可以复用本次压缩摘要文本建立第一条 macro 记录；这不改变两种摘要的长期职责边界

8. ~~**reviewing 阶段的消息结构和预算分配**~~ -> **已确认**：方案D（不注入压缩摘要和历史；角色提示词、审查提示词分别作为前两条 system，用户消息与生成内容合并为末尾 user）；无需 dialogueBudget 计算，仅校验检索区；三维度 prompt 约束（事实审查+去AI味+易读性）

9. ~~**固定开销上限的具体值确认**~~ -> **已确认**：角色提示词 2000 / 压缩摘要 8000（项目主打长期记忆，给更大空间）/ 用户输入 2000，合计 12000 token

## 上下文用量指示器（2026-09-02 起；2026-09-04 起三模式共用）

- **圆环**：输入区工具栏末端的环形 chip，满刻度 = 压缩触发线（不是模型窗口）。≥70% warning 色、≥100% error 色、无数据空轨道。点击开详情面板（窗口用量/缓存命中率/最近请求 token）。触发线口径分模式：故事/导演 = contextWindow × compactionTriggerRatio；对话 = availableWindow × compactionThreshold（availableWindow = max(窗口−32000, 窗口×0.5)，与对话自动压缩判定同公式同值，2026-09-04 接入）。对话模式数字与旧 token 文本徽章同源（最近落库 tokensUsed + 草稿输入），无缓存命中的行显示「—」。
- **手动压缩**：详情面板内「立即压缩」——不等触发线提前压缩，摘要流式生成（输入历史经信封化打包为单条 user 消息+收尾指令锚点，2026-09-04），完成后旧对话被一条前情摘要替代。四态反馈：busy（生成/压缩中互斥）、insufficient（对话不足）、success、failed（可重试）。
- **撤销压缩**（2026-09-04）：压缩从不删除旧消息（过滤是视图效果），摘要卡展开态「撤销压缩」单事务回剥最新压缩点+摘要行+宏摘要记忆（FTS 同步），旧对话自然全量恢复；多次压缩逐次回剥。仅 idle 可用；撤销只还原上下文前缀，不动后续轮次/记忆/叙事时间。
- **「已归档第 X–Y 轮」**：故事模式压缩摘要卡标签行标注本次压缩覆盖的轮次区间（from=压缩前累计基数+1，to=压缩后基数）。
