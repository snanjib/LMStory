# LMStory 术语字典

> 术语字典体系的目的：保证项目沟通精准、代码实现精准、用户可见内容无歧义且不过时。

## 为什么需要术语字典

项目多次出现因术语不明确或过时导致的问题：

- 功能缺乏确切命名，造成理解偏差
- 改名后旧称残留（如 中级模式 -> 故事模式、草稿/终稿阶段 -> 生成/审查阶段），导致文档与代码"过时"
- 沟通中同一概念用不同名称，增加对齐成本

本体系通过维护权威术语字典，记录每个术语的标准命名、曾用名与精确定义，作为沟通与实现的统一参照。

## 命名规则

- **目录名**：用模式英文代号（`intermediate` / `simple` / `advanced`）
- **文件名**：用中文功能模块名（如 `上下文工程.md`）
- **模式命名**：项目内统一使用「故事模式」指代 Intermediate mode，「对话模式」指代 Simple mode，「导演模式」指代 advanced mode

## 维护原则

1. **记录曾用名**：术语变更时，在对应术语条目备注旧称，避免过时引用造成误解
2. **同步更新**：术语调整后同步更新代码、文档与用户可见文本，并在对应字典的变更记录中登记
3. **权威顺序**：当代码、术语字典与设计文档不一致时，以当前可执行代码、数据库 Schema 和匹配当前 API 的测试为准；术语字典必须随实现同步更新，不能反向覆盖代码事实
