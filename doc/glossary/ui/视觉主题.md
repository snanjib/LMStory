# 前端 · 视觉主题术语字典

> **用途**：统一前端视觉主题（设计系统层、外观装配、语义色槽、材质与布局尺度）相关概念的命名与定义。
>
> **范围**：`lib/core/theme/` 下的系统层与垫片层、外观装配两条轴（结构 × 配色族）、明暗档、语义色槽、LmTokens、琉璃材质、阅读限宽与移动断点。跨模式通用，不属于任何单一模式。
>
> **状态**：初版（2026-09-20）。
>
> **维护原则**：记录曾用名、同步更新；当前可执行代码、数据库 Schema 和匹配当前 API 的测试优先，字典与实现冲突时修订字典。
>
> **术语纪律**：全文统一使用「结构 / 配色族 / 明暗档 / 外观 / 预设 / 系统层 / 垫片层 / 语义色槽 / 阅读限宽」。「皮肤」「主题包」「样式集」等一律视为曾用名，仅在「曾用名」字段出现。

## 一、系统层与垫片层

### 1.1 系统层（system layer）

- **标准命名**：系统层
- **定义**：v0.4.0 设计系统重构后收敛出的新设计系统层，位于 `lib/core/theme/system/` 。把「界面长什么样」（结构）与「用什么配色」（配色族）拆成两条独立轴，由 `ThemeCatalog` 装配出最终 `ThemeData`。
- **代码位置**：`lib/core/theme/system/`，核心文件：
  - `lm_palette.dart` — `LmPalette` 语义色槽载体、`LmPaletteFamily` 配色族接口
  - `lm_structure.dart` — `LmStructure` 结构接口、`LmReadingConstraints`
  - `lm_tokens.dart` — `LmTokens` ThemeExtension 与 `context.lm` 扩展
  - `theme_catalog.dart` — `ThemeCatalog` 装配与登记入口（`LmAppearance` / `LmPreset` / `LmCatalogEntry`）
  - `palettes/classic/classic_palette.dart`、`palettes/bordeaux/bordeaux_palette.dart`
  - `structures/classic/classic_structure.dart`、`structures/glass/glass_structure.dart`、`structures/brutal/brutal_structure.dart`、`structures/wonder/wonder_structure.dart`
  - `lib/core/theme/api/lm_component_kit.dart` — 界面职责接口；各结构目录的 `*_components.dart` 实现组件外观
- **曾用名**：无（重构前该层不存在）
- **易混淆点**：系统层不是「某一个主题」，而是所有外观共享的装配机制层。Classic / Bordeaux 是外观名，不是目录名。

### 1.2 垫片层（shim layer）

- **标准命名**：垫片层
- **定义**：重构前的旧主题路径 `lib/core/theme/simple/`、`lib/core/theme/intermediate/`、`lib/core/theme/shared/`，重构后保留为兼容垫片，指向系统层。
- **代码位置**：`lib/core/theme/simple/`（4 文件 / 19 行）、`lib/core/theme/intermediate/`（3 文件 / 22 行）、`lib/core/theme/shared/`（8 文件 / 1151 行）
  - `simple/components/` 与 `intermediate/components/` 两个重定向目录**已退役删除**（2026-10-05，见保留决策附注）：每个文件原为单行 `export` 重定向，指向 `lib/core/theme/system/structures/classic/{conversation,narrative}/` 下的同名实现
  - `simple/simple_theme.dart`：`SimpleTheme.lightTheme` / `darkTheme` 直接委托 `ThemeCatalog.assemble(ThemeCatalog.defaults, ...)`，自身不含色值
  - `intermediate/intermediate_spacing.dart`：`IntermediateSpacing.readingWidth` 桥接 `LmReadingConstraints.width`
- **保留决策（主控评估，记录不重新评估）**：垫片目录运行时零成本；640 处调用点迁移会产生巨大 diff，与「打磨双主题」目标无关且引入回归风险；Classic 为长期默认，垫片指向的正是 `system/structures/classic/`，语义正确。
  - **附注（2026-10-05）**：消费面收编完成后，`components/` 重定向目录的 lib 消费清零（残余 6 个 domain 实参个案与全部镜像测试改引 `system/structures` 实现路径），两个目录 53 个垫片文件整体删除；token 垫片（spacing/text_styles/radius/theme）消费面仍广，保留决策不变。
- **纪律**：**新代码必须直接引用 `lib/core/theme/system/` 路径，不得再新增垫片引用。**
- **曾用名**：
  - `Simple mode` / 对话模式（在主题代码语境下）→ 现名垫片层 `simple/`
  - `Intermediate` / 故事模式（在主题代码语境下）→ 现名垫片层 `intermediate/`
- **易混淆点**：
  1. `shared/` 与另两个目录性质不同：它含实际逻辑实现（流式 Markdown 块切分器 `streaming_markdown_blocks.dart`、搜索高亮 `search_highlight.dart`、呼吸点 `components/breathing_dot.dart`、品牌 Logo `components/brand_logo.dart` 等），**不是**纯 `export` 重定向。
  2. 「垫片层 = Simple/故事模式主题实现」是错误理解；垫片不定义任何色值。
  3. 注释残留：`shared/components/breathing_dot.dart:7,14-16` 仍引用 `SimpleColors` / `IntermediateColors`，这两个类在当前代码中已无定义（该组件实际取色方式为 `context.lm.palette`）。属注释过时，非代码事实。

## 二、外观装配轴

外观由三条正交输入装配而成：**结构**（形态）× **配色族**（色值）× **明暗档**（light/dark）。

### 2.1 结构（structure）

- **标准命名**：结构
- **定义**：决定「界面长什么样」的一条装配轴，即组件形态、材质语言与几何。实现类为 `LmStructure`，通过 `buildComponents()` 提供 `LmComponentKit`。业务组件只请求界面职责，结构实现由 `ThemeCatalog` 注入。
- **代码位置**：接口 `lib/core/theme/system/lm_structure.dart:9-12`（`String get id` + `ThemeData assemble(LmPalette palette, Brightness brightness)`）；登记 `lib/core/theme/system/theme_catalog.dart:56-67`
- **值域**：`classic`（经典）、`glass`（琉璃）、`brutal`（印刻）、`wonder`（漫游）。后两个 id 保持稳定，不随显示名变化。
- **曾用名**：无
- **易混淆点**：结构不含色值。结构配方只消费配色槽位与 white-alpha 台阶（解耦保证，`structures/glass/glass_materials.dart:5-6`）。结构与配色族 id 允许重名（`classic` 既是结构 id 也是配色族 id），但语义不同。

### 2.2 配色族（palette family）

- **标准命名**：配色族
- **定义**：决定「用什么配色」的一条装配轴，即一族按明暗档取值的语义色槽集合。实现类为 `LmPaletteFamily`。
- **代码位置**：接口 `lib/core/theme/system/lm_palette.dart:74-77`（`String get id` + `LmPalette of(Brightness brightness)`）；登记 `lib/core/theme/system/theme_catalog.dart:68-79`
- **值域**：`classic`（`ClassicPaletteFamily`）、`bordeaux`（`BordeauxPaletteFamily`）
- **曾用名**：`Daylight`（仅指 Classic 日间档，见 `classic_palette.dart:14`）、夜航（仅指 Classic 夜间档，见 4.4）
- **易混淆点**：配色族不是单一 `ColorScheme`，而是「日间档 + 夜间档」两组成品 `LmPalette`。

### 2.3 明暗档（brightness）

- **标准命名**：明暗档；两个取值中文写作**日间**（light）、**夜间**（dark）
- **定义**：Flutter `Brightness` 的两档取值，决定配色族取哪一组色槽、结构走哪条装配分支。
- **代码位置**：消费点 `lib/core/theme/system/theme_catalog.dart:102-121`（`ThemeCatalog.assemble(appearance, brightness)`）；配色族取档 `ClassicPaletteValues.of`（`classic_palette.dart:67-69`）、`BordeauxPaletteFamily.of`（`bordeaux_palette.dart:119-121`）；结构分支 `ClassicStructure.assemble`（`classic_structure.dart:13-14`）、`GlassStructure.assemble`（`glass_structure.dart:25`）
- **曾用名**：`daylight`（日间）、`twilight`（夜间）—— 出处 `DESIGN.md:5-36` 前置 YAML 的 `daylight-*` / `twilight-*` 键
- **与设计文档 DESIGN.md 的差异（以代码为准）**：`DESIGN.md` 中 `twilight-*` 是独立一组深色值（`twilight-bg #1A1A22`、`twilight-primary #5C5CE8`），该组值在当前代码中**无对应实现**；代码夜间档取的是 `night-voyage-*` 值（Classic 夜间 `bg #0E1018` / `primary #D4A042`，与 `DESIGN.md:37-51` 一致）。按权威顺序，字典记录的夜间锚值以代码为准。
- **易混淆点**：明暗档是全局维度，不是「某个模式的局部暗色」。把夜间档称为「故事模式的暗色」是收编前的旧理解（见 4.4 夜航）。

### 2.4 外观（appearance）

- **标准命名**：外观
- **定义**：**结构 × 配色族** 的二元组，即一次可装配的完整视觉身份。
- **代码位置**：`lib/core/theme/system/theme_catalog.dart:20-40`（`LmAppearance`，字段 `structureId` / `paletteId`，`copyWith` / `==` / `hashCode` 均按二元组）
- **装配链**：`AppearanceNotifier` → `appearanceThemesProvider`（`lib/core/theme/appearance_controller.dart:12-20`）→ `ThemeCatalog.assemble` → `MaterialApp.theme` / `darkTheme`（`lib/main.dart:166,171-172`）
- **曾用名**：**皮肤 / skin**（历史设计文档用词，历史讨论中的「配色皮肤系统」「可插拔配色皮肤架构」；代码现用 `LmAppearance`）
- **易混淆点**：
  1. 外观不等于明暗档。同一个外观在日间/夜间下是两套色值。
  2. 外观不等于结构，也不等于配色族；它是两者的组合。
  3. 持久化与切换以二元组为单位：`Preferences` 键 `appearance_structure` / `appearance_palette`（`appearance_controller.dart:28-29`），非法组合由 `ThemeCatalog.resolve` 回落到 `defaults`。

### 2.5 预设（preset）

- **标准命名**：预设
- **定义**：~~`ThemeCatalog` 中登记过的、有名字的外观组合~~ **已删除（2026-09-21，`f6b2cd33`）**：`ThemeCatalog.presets` 与 `LmPreset` 经生产零消费实锤后移除，`appearance.presets.*` i18n 死键同步删除。本条目保留作曾用名登记，防止旧文档误导。
- **代码位置**：删除前为 `lib/core/theme/system/theme_catalog.dart`（`LmPreset` 类型 + presets 登记表）；现均不存在
- **删除理由**：唯一消费是测试自身；结构轴与配色轴各自的选择入口已由 catalog 注册表驱动（新增结构/配色零 UI 改动），具名预设层无产品语义。**双轴不得合并**的拍板不受影响——删除预设恰恰消除了「预设=第三条选择轴」的误解源。
- **曾用名**：预设 / `LmPreset`
- **易混淆点**：`ThemeCatalog.resolve`（`theme_catalog.dart`）只校验 structureId / paletteId 各自是否存在于 catalog；结构与配色族的笛卡尔积 4 种组合**全部是正式支持组合**（v0.4.0 拍板），不存在「未被设计的组合」。

## 三、LmTokens 与语义色槽

### 3.1 LmTokens

- **标准命名**：LmTokens
- **定义**：`ThemeExtension<LmTokens>` 载体，携带当前外观的身份与色槽快照，供组件经 `context.lm` 取用；`structureId` / `paletteId` 兼作 markdown 缓存失效键。
- **代码位置**：`lib/core/theme/system/lm_tokens.dart:11-49`；`context.lm` 扩展 `lm_tokens.dart:51-58`；注入点 `theme_catalog.dart:110-120`
- **四个字段**：`structureId`（String）、`paletteId`（String）、`palette`（`LmPalette`）、`material`（`ColorScheme`）
- **取用与回退**：`context.lm` 先取 `theme.extension<LmTokens>()`，为空时回退 `ThemeCatalog.fallbackTokens(theme.brightness)` 并覆盖 `material` 为当前 `theme.colorScheme`
- **曾用名**：无
- **易混淆点**：
  1. `GlassStructure.assemble` 自身也注入一个 `LmTokens`（`glass_structure.dart:202-217`），其 `paletteId` 为**空串**；随后 `ThemeCatalog.assemble` 用 `copyWith(extensions: [...values, LmTokens(...)])` 再注入一个带真实 `paletteId` 的 `LmTokens`（`theme_catalog.dart:110-120`）。`ThemeData.extensions` 按 type 覆盖、后者生效，因此运行期 `context.lm.paletteId` 为真实配色族 id，不是空串。
  2. `LmTokens.material` 是 Material 层 `ColorScheme`，与 `LmPalette` 语义色槽是两套坐标；组件取色应走 `context.lm.palette`。

### 3.2 语义色槽（semantic color slots）

- **标准命名**：语义色槽
- **定义**：`LmPalette` 上按「语义角色」而非「具体色值」定义的取色位，共 **19 槽**，是所有外观共享的稳定契约。
- **代码位置**：`lib/core/theme/system/lm_palette.dart:5-72`（声明与 `lerp`）；Classic 取值 `palettes/classic/classic_palette.dart`；Bordeaux 取值 `palettes/bordeaux/bordeaux_palette.dart`
- **全部 19 槽与语义分工**：

  | # | 槽名 | 语义分工（依当前代码的消费方式） |
  |---|---|---|
  | 1 | `bg` | 页面/脚手架底色（`scaffoldBackgroundColor`） |
  | 2 | `surface` | 卡片底、导航条底（一级承载面） |
  | 3 | `surfaceElevated` | 弹窗 / 底栏 / SnackBar 底（抬升面） |
  | 4 | `surfaceVariant` | 输入框底、Chip 底（次级承载面） |
  | 5 | `ink` | 主文本与图标前景（最高对比档） |
  | 6 | `muted` | 次级文本（如对话框正文） |
  | 7 | `faint` | 三级文本 / 未选中态 / 输入提示 |
  | 8 | `primary` | 主操作填充、选中态、焦点边、强调 |
  | 9 | `primaryDim` | `primary` 的低透明度底（选中指示、选中底） |
  | 10 | `onPrimary` | `primary` 填充上的文字/图标前景 |
  | 11 | `accent` | 第二强调（映射 `ColorScheme.secondary`；琉璃焦点环边） |
  | 12 | `accentDim` | `accent` 的低透明度底（横幅底） |
  | 13 | `divider` | 内容分隔线（1px 装饰性，低对比） |
| 14 | `dividerStrong` | 结构分隔线（侧栏边界等导航结构，对 bg ≥3:1；Q5 语义拆分自 `divider`） |
  | 14 | `success` | 语义状态色：成功 |
  | 15 | `warning` | 语义状态色：警告 |
  | 16 | `error` | 语义状态色：错误 |
  | 17 | `scrim` | 遮罩 |
  | 18 | `bgGlow` | **可选**槽：场地渐变端点。**唯一消费点 = `GlassBackdrop` 工厂**（`structures/glass/glass_factories.dart:25,40`）。未赋值时 `LmPalette.bgGlow` 回退为 `bg`（`lm_palette.dart:47`），保留纯平背景。T05 起 Classic 两档亦已赋值（克制中性端点） |

- **曾用名**：无
- **易混淆点**：
  1. 语义色槽 ≠ 具体色值。同一槽在 Classic / Bordeaux、日间 / 夜间下取值不同。
  2. `bgGlow` 是唯一的**可选**槽（构造函数为 `Color?`，`lm_palette.dart:24`）。T05 起两族四档均已赋值；「缺省回退 bg」仅是未赋值场景的兜底语义。
  3. `success` / `warning` / `error` 三槽不受配色族色相纪律约束（Bordeaux 色相纪律明确排除语义色，`bordeaux_palette.dart:6-7`）。
  4. 白玻璃阶梯（见 5.2）是**结构常量，不是语义色槽**，不占这 19 槽。

## 三点五、配置显示模式（跨外观的展示层开关）

> 严格说这是配置域概念，因与「简单/进阶」外观心智同源，暂记于本册，待配置域分册建立后迁移。

- **配置显示模式（ConfigLevel）**：设置 → 通用页底的「简单/进阶」开关（键 `ui_config_level`，默认简单）。只过滤设置页与会话面板的**展示层**，不改存储语义；被隐藏项已有值继续生效；切换即时生效。15 面键集合由 `config_visibility.dart` 声明并有守卫对账；未登记键 release 下 fail-open（可见）。
- 深链落地：会话内「未配置嵌入模型」横幅的「去配置」直达配置区。D-C13（2026-09-24）嵌入模型划入简化后：故事侧嵌入区双模式恒显（原 revealEmbedding 豁免参数已删）；导演侧记忆区壳恒显（focusSection 保留展开定位职责）——「提示去配置但无物可配」死路由分级本身消除。

## 四、外观实例

### 4.1 Classic（经典）

- **标准命名**：Classic（经典）
- **定义**：由「`classic` 结构 + `classic` 配色族」组成的外观，即预设 `classic`，也是 `ThemeCatalog.defaults`。
- **代码位置**：结构 `lib/core/theme/system/structures/classic/classic_structure.dart`；配色 `lib/core/theme/system/palettes/classic/classic_palette.dart`
- **锚值（代码实测）**：

  | 槽 | 日间 | 夜间 |
  |---|---|---|
  | `bg` | `#F4F5F7` | `#0E1018` |
  | `bgGlow` | `#DDE3EE`（T05） | `#202A40`（T05） |
  | `surface` | `#FFFFFF` | `#141722` |
  | `surfaceElevated` | `#EEF0F3` | `#1B1E2C` |
  | `surfaceVariant` | `#E7E9ED` | `#171A26` |
  | `ink` | `#22222E` | `#EFEDE6` |
  | `primary` | `#4338CA`（靛蓝） | `#D4A042`（琥珀金） |
  | `onPrimary` | `#FFFFFF` | `#14100A` |
  | `accent` | `#9E7520` | `#B8862E` |
  | `divider` | `#DDE0E5` | `#2A2D3A` |

  （Classic 两档 `bgGlow` 于 T05 赋值：日 `#DDE3EE` / 夜 `#202A40`，本族冷灰自身色相低彩度端点，判定口径「场地可辨但不抢内容」。）
- **产品定位**：**Classic 是长期默认外观**，已在多个版本真机使用，整体无重大问题，是**后续打磨重点**；**与 Bordeaux 并列为「双主题」**，是当前打磨的两条主线之一。
- **曾用名**：`Daylight`（日间档名，`classic_palette.dart:14`）；夜航（夜间档，见 4.4）
- **易混淆点**：「Classic」同时是结构 id 与配色族 id；说「Classic 结构」指形态，说「Classic 配色族」指色值，说「Classic 外观」指两者组合。

### 4.2 Bordeaux（波尔多）

- **标准命名**：Bordeaux（波尔多）
- **定义**：由「**琉璃（`glass`）结构 + 波尔多（`bordeaux`）配色族**」组合而成的第二套外观，即预设 `bordeaux`。
- **代码位置**：配色 `lib/core/theme/system/palettes/bordeaux/bordeaux_palette.dart`；结构 `lib/core/theme/system/structures/glass/glass_structure.dart`
- **锚值（代码实测）**：

  | 槽 | 夜间 | 日间 |
  |---|---|---|
  | `bg` | `#150C13` | `#F5F2F3` |
  | `bgGlow` | `#5C1F38` | `#E9D9DE` |
  | `surface` | `#221420` | `#FFFFFF` |

### 5.2 白玻璃阶梯（双轴：层级面恒提亮 / 状态台阶方向派生）

- **标准命名**：白玻璃阶梯
- **定义**：一组白/黑 alpha 台阶常量，**属结构常量，不是语义色槽**。T10-2 起按**两条语义轴**切分（此前为单向「只叠白、按明暗取不同 alpha」的一条轴，见「曾用名」）：
  - **A 轴 · 层级面 / 结构面**（`fill6` 静息面、`fill22` 结构档）：**恒提亮**（只叠白），alpha 仍由**底面亮度**派生（暗底 6% / 22%，亮底 30% / 70%）。它们回答「构件从场地里浮起来了吗」，不回答「指针在上面吗」；方向不翻转，故所有构件静息面观感与 T10-2 前逐像素一致。
  - **B 轴 · 状态台阶**（`fill10` hover、`fill16` pressed/selected）：**方向由底面色亮度派生** —— `directionOf(base)`：`base.computeLuminance() ≥ stepFlipLuminance(0.5)` → **压暗**（叠黑），否则 **提亮**（叠白）。这是 T10-2 真正修的东西（与 Apple 材质「highlight/shadow 极性随环境翻转」同构）。
- **代码位置**：`lib/core/theme/system/structures/glass/glass_materials.dart`（常量 + `directionOf` + 四个取档函数）；消费见 `structures/glass/glass_factories.dart`（`GlassPillButton` 的 `fillOf` 等）
- **常量与取档**：

  | 取档函数 | 轴 | 亮底（`luminance ≥ 0.5`） | 暗底（`< 0.5`） |
  |---|---|---|---|
  | `fill6(base)` | A 静息面 | `restLiftLight` `0x4DFFFFFF`（白30%） | `restLiftDark` `0x0FFFFFFF`（白6%） |
  | `fill22(base)` | A 结构档 | `structLiftLight` `0xB3FFFFFF`（白70%） | `structLiftDark` `0x38FFFFFF`（白22%） |
  | `fill10(base)` | B hover | `sinkHover` `0x12000000`（**黑**7%） | `liftHover` `0x21FFFFFF`（白13%） |
  | `fill16(base)` | B pressed | `sinkPressed` `0x1B000000`（**黑**10.5%） | `liftPressed` `0x30FFFFFF`（白19%） |

  - 方向阈值 `stepFlipLuminance = 0.5`（sRGB 中灰 `#BCBCBC` 的相对亮度）。亮底叠白的增量 `255−B` 已不足以产生可感知台阶（实测 Δ≤8），故必须转为压暗。
  - **T2 模态任务面台阶 `t2LiftLight` / `t2LiftDark` = 结构档**，**恒提亮**、不参与状态递进（scrim 恒为暗色叠加，场地侧永远被压暗，提亮永远正确）；`modalSurface(b, baseElevated)` 沿用按 `Brightness` 取档。
  - 合成助手 `stepped(base, fill)` = `Color.alphaBlend(fill, base)`，供「以合成面为新底面继续叠档」与对比度核算（半透明台阶的 `computeLuminance()` 只看 rgb，直接判方向会错）。
  - **验收线（T10-2 拍板）**：四组合 × 明暗下，静息→悬停、静息→按压 **Δ ≥ 15**（与 classic 按钮已达水位对齐），悬停→按压额外增量 **Δ ≥ 8**；暗向档三态文字对比度 **≥ 4.5:1**。实测 hover Δ16–31 / pressed Δ24–46 / 额外 Δ8–15，见 `test_screenshots/night-2026-09-21/t10_step_direction_report.md`；守卫 `test/core/theme/glass/t10_step_direction_guard_test.dart`。
- **辅助常量**：`topInnerHighlight` 白@18%（`0x2EFFFFFF`，单侧 `boxShadow(0,-1)`，不占布局宽度）；`floatShadow(b)` 日间取 `dayShadow`（黑@12%，blur 20，offset(0,6)），夜间取 `t1FloatShadow`；焦点环辉光 = `focusGlow(accent)` **按当前配色族 accent 运行时派生**（accent@30%，blur 16；品牌时刻 `brandGlow(accent)` = accent@35%；T05 前曾写死波尔多 accent 值 `0x4DFF4F6E`，该写法已被红线守卫禁绝）/ `focusRingWidth` 2；`pressedScale` 0.98（按压回弹禁用，无弹跳无弹性）；T2 模态任务面阴影 `t2ShadowColor`（黑@25%）+ `t2Elevation` 6（T05）。
- **曾用名**：~~单向白玻璃阶梯（只叠白、按明暗硬分档 `fill6/10/16/22`，日间为 30/50/70 三档）~~ **已废（T10-2）**：白叠白必然无变化（波尔多夜间白药丸 hover Δ0），且日间 `fill10 == fill16 == fillDay50` 使 chip「hover +1 / pressed +2」塌掉一档。现改为双轴 + 方向派生。
- **易混淆点**：
  1. **两条轴别混成一条**：`fill6`/`fill22` 是**层级面**（恒提亮，方向不翻转），`fill10`/`fill16` 是**状态台阶**（方向派生）。把静息面也改成「亮底压暗」会在数学上无解 —— `muted` 文字在 `#F4F5F7` 上仅 5.13:1，压暗 ≤11% 就必须停手，塞不进「Δ≥15 + 额外 Δ≥8」两档；让静息面留在提亮侧才能把全部对比度预算让给状态台阶。
  2. 档位序号沿用 `fill6/10/16/22` 的**历史 alpha 编号，只作序号用**，与当前实际 alpha 无对应关系。
  3. 「亮底 / 暗底」判据是 `base.computeLuminance()`，不是 `Brightness`；同一 `Brightness`（如 `dark`）下波尔多夜间**白药丸**（面 `#ffffff`）与**暗底**会得到**相反**方向（正是修复目标）。

- **版心语义槽**（内容列最大宽度，消费面负责居中）：
  | 槽 | 值 | 用途 |
  |---|---|---|
  | `readingMeasure` | 720 | 正文阅读列（= `LmReadingConstraints.width`，**不放宽**） |

  | `listMeasure` | 1120 | 列表 / 卡片类页（资源库、记忆库、模板管理、帮助中心） |
  | `dialogMaxWidth` | 560 | 模态对话框（M3 规格上限，Flutter 默认不施加，本项目补上） |
  | `dialogNarrowWidth` | 480 | 表单 / 编辑型对话框（更紧凑阅读宽） |
  | `sheetMaxWidth` | 640 | 底部浮层（宽屏不得通铺整窗） |
  | `panelWidth` / `panelNarrowWidth` | 560 / 440 | 页面内嵌侧面板（AI 建卡会话面板等） |
  | `sidebarWidth` | 240 | 桌面侧栏宽（= `main_layout` 既有 240） |
- **施加机制 `LmMeasure`**：`usesMeasure(width)`（`width ≥ mediumMax` 即 1280）为真才 `Align(topCenter) + ConstrainedBox(maxWidth:)` 收敛；**`<1280` 一律 `child` 原样返回**——因此 600–1279 区间（含全部历史 golden）**逐像素零变化**，这是「Classic 默认观感不变」由构造保证的关键。
- **代码位置**：`lib/core/theme/system/lm_layout.dart`；守卫 `test/core/theme/t07_layout_guard_test.dart`（常量锚值 / `tierOf`·`usesMeasure` 边界 / 断点字面量只许在 `lm_layout.dart` 出现 / `LmMeasure` 行为 / **布局类宽度字面量白名单**）。
- **红线**：布局类宽度（影响版心 / 面板 / 浮层 / 输入区）必须取本类语义槽；**内容固有尺寸**（缩略图、图标位、封面等局部固定尺寸）不算布局类，登记在守卫白名单里，新增自由字面量即失败。
- **曾用名**：无
- **易混淆点**：①「移动断点 600」与「版心启用阈值 1280」是两个不同语义的阈值——前者分单栏/双栏壳，后者分「全幅 / 收敛」；②`readingMeasure`（720，正文列）不随窗口变宽而放宽（可读性红线），大屏修正做的是「把输入区/工具栏/空态对齐到同一版心」，不是拉长正文；③`LmMeasure` 的 `<1280` 直通行为是**刻意设计**，不是漏写收敛。

## 七、交互状态与动效

### 7.1 动效单源 `LmMotion`

- **标准命名**：动效单源（`LmMotion`）
- **定义**：结构无关的动效常量单源，位于 `lib/core/theme/system/lm_motion.dart`。与 `LmButtonMetrics`（按钮度量单源）、`GlassMaterials`（材质单源）、`GlassRadii`（几何单源）同一范式：**结构轴与业务面都从这里取，禁止就地写时长/曲线字面量**。T06 把 `lib/features/` 里散落的 84 处时长字面量与曲线收编入表，**只换来源、不改数值**（数值即 Classic 现值，故 Classic 组合零视觉零行为变化）。
- **代码位置**：`lib/core/theme/system/lm_motion.dart`；守卫 `test/core/theme/lm_motion_guard_test.dart`（扫 `lib/` 全域 `Duration(milliseconds: <数字>)` / `Curves.<名>` / `Cubic(<数字>…)`，等值锚定各槽）。
- **豁免通道**：确属**非过渡动效**（网络超时、定时器、流式引擎节奏）的时长，在该语句**上方一行**写 `// lm-motion-exempt: <理由>`；守卫按此豁免，白名单即注释本身，不另存表。

  **时长语义槽**（档位关系，按语义选档，不按"看起来差不多"）：

  | 槽 | 值 | 语义 |
  |---|---|---|
  | `instant` | 0ms | 终态：减弱动态下的直接落点（不做补间） |
  | `micro` | 120ms | 微反馈：悬停/聚焦环淡入、进度环、搜索高亮 |
  | `fast` | 150ms | 快档：按压反馈、状态切换、跳转药丸 |
  | `base` | 200ms | 常规档：绝大多数过渡默认（模态、条目淡入、面板切换） |
  | `slow` | 250ms | 慢档：显著过渡与出场（crossfade、收起） |
  | `emphasis` | 300ms | 强调档：强调/布局形变（抽屉、导航、面板展开） |
  | `enter` | 400ms | 进场档：列表条目/消息入场 |
  | `transition` | 500ms | 整场转场：模式切换级画面过渡 |
  | `unfold` / `fold` / `step` / `sweep` | 160 / 180 / 220 / 240ms | 元素专属刻度（展开、折叠、分页步进、幕线扫过）——不是新档位，是经实测锚定的具体元素节奏 |
  | `blink` / `pulse` / `pulseSoft` / `loop` / `breathe` | 540 / 800 / 900 / 1200 / 1500ms | **循环节奏**（流式光标、呼吸点、打字点、微光扫掠）；减弱动态下**不得启动** |

  语义别名（与刻度同值，只为调用点自解释，**不是新档位**）：`press`=`fast`、`hover`=`fast`、`focus`=`micro`、`exit`=`slow`。

  **曲线语义槽**（全部减速或对称，**禁 bounce / elastic / 任何带回弹的 spring**）：

  | 槽 | 值 | 语义 |
  |---|---|---|
  | `easeStandard` | `Curves.easeOut` | 标准减速：位移、状态过渡默认 |
  | `easeBoth` | `Curves.easeInOut` | 双向缓入缓出：尺寸/颜色开合、循环呼吸 |
  | `easeEmphasis` | `Curves.easeOutCubic` | 强调减速：跳转、步进等较大位移 |
  | `easeSnap` | `Curves.easeOutQuart` | 强减速：短距离快速收束（T06 与旧 `GlassMotion.easeMove` 合一） |
  | `easeColor` | `Cubic(0.33, 1, 0.68, 1)` | 颜色/透明度专用减速（波尔多夜间白药丸按压在用） |
  | `easeRecede` | `Curves.easeIn` | 加速段，仅用于对称往返的后半程，与 `easeStandard` 成对 |
  | `linear` | `Curves.linear` | 无补间 |

  几何过程量：`modalScaleFrom` 0.97（模态入场 fade + scale → 1）。

- **红线**：① 禁 bounce/elastic；② 数值即 Classic 现值，改值须单独 commit 并出前后对比；③ 尊重减弱动态。
- **曾用名**：无
- **易混淆点**：「语义别名」与「元素专属刻度」都**不是新增档位** —— 别名只是同值自解释名，专属刻度是单个元素的实测节奏；判断有没有"多出档位"要看数值集合，不是看常量条数。

### 7.2 交互五态

- **标准命名**：交互五态 —— **静息 / 悬停（hover）/ 焦点（focus-visible）/ 按压（pressed）/ 禁用（disabled）**，另加**载入（loading）**贯穿态。
- **定义**：T06 给 18 个琉璃工厂与 classic 对应件统一补齐的交互状态集。焦点态与其余四态**不同屏**（primary focus 全局唯一），故五态矩阵截图分两次快门（见 `t06_states_matrix_review.md`）。
- **代码位置**：`lib/core/theme/system/structures/glass/glass_factories.dart`（`_GlassStates` / `_PressedScale` / `_glassFocusRing` / `_glassFocusGlow`）；守卫 `test/core/theme/glass/t06_interaction_states_guard_test.dart`（四组合 × 双亮度）。
- **口径**：
  - **焦点环必须可见**：`focusRingWidth` 2px 的环 + 按配色族 accent 运行时派生的 `focusGlow(accent)` 辉光，四组合都成立。
  - **禁用不隐形**：禁用面 = 不透明语义槽底（`alpha == 1.0`）+ 可辨描边（`disabledBorderAlpha` 0.4），内容降 `faint`，且**不回调**（`onPressed == null`）。
  - **载入不回调**：loading 期间点按计数恒 0；进度环保留（WCAG 2.3.3：进度指示不属于"装饰性动效"，减弱动态下不撤）。
  - **按压**：`pressedScale` 0.98，减弱动态下 `_PressedScale` 直接返回 child。
- **实测取证**：八组合（四组合 × 明暗）*焦点件像素差分*均检出 ≥2 个独立簇（主按钮 + 输入件），证明两个焦点件都拿到了焦点形态；数据见 `test_screenshots/night-2026-09-21/t06_states_focus_diff.txt`。
- **曾用名**：无
- **易混淆点**：focus-visible（键盘焦点，需 `FocusHighlightStrategy.alwaysTraditional` 才在测试环境亮起）≠ 一般的获焦；五态矩阵的「悬停/按压」是**真实指针驱动**逼出来的，不是假样式。

### 7.3 减弱动态降级

- **标准命名**：减弱动态（reduced motion）降级
- **定义**：无障碍偏好下的动效退化策略。判据取全仓历史最严**并集**：`MediaQuery.disableAnimations` **或** `accessibleNavigation` 任一为真（此前 21 处消费点判据不一致，T06 统一到 `LmMotion.reducedMotion(context)`）。
- **代码位置**：`lib/core/theme/system/lm_motion.dart`（`reducedMotion` / `shouldAnimate` / `durationFor` / `fadeFor`）；守卫 `test/core/theme/t06_reduced_motion_guard_test.dart`。
- **降级口径**：
  - **一次性过渡**：`durationFor` → `instant`（直接终态）；"骤然消失会被当成渲染故障"的场景用 `fadeFor` → `micro`（保留最小可感淡入）。
  - **循环动效**：**不得把时长压到 0**（`repeat()` 会空转），须用 `shouldAnimate` 判断后**不启动**，直接落静态终态。
  - 源码审计：每个 `repeat()` 站点上方必须有守卫，站点数被守卫钉死（当前 10 处）。
- **曾用名**：无
- **易混淆点**：`durationFor` 只适用于一次性过渡；拿它去压循环动效的时长是错的（会产生空转的重复动画）。

### 7.4 可达性语义口径

- **标准命名**：语义缺口（空名按钮 / 可点无角色）
- **定义**：T06 以 `SemanticsTree` 快照为准审查可达性的两类硬缺口：
  - **空名按钮**：带 button 角色但 `label` 与 `tooltip` 双空 → 读屏器只能播报「button N」；
  - **可点无角色**：`hasAction(tap)` 且有可读名字，却没有任何交互角色（button / 选项态）→ 读屏器当静态文本，用户不知道"能点"。
- **代码位置**：守卫 `test/core/theme/t06_semantics_audit_test.dart`（哨兵断言 + dump 到 `t06_semantics_audit.txt`）；清单 `t06_semantics_gap_list.md`；补充普查脚本 `.tools/t06_semantics_scan.py`。
- **口径**：**先出清单再动手**，只修清单上真有问题项，不为好看乱包 `Semantics`。补名字**优先复用既有文案**（`MaterialLocalizations` 框架本地化 或 `t.common.*`），无既有键可用时登记待主控（红线禁新增 i18n key）。
- **曾用名**：无
- **易混淆点**：`Tooltip` 只写语义节点的 `tooltip` 属性；读屏器播报按钮名读的是 `label`——两者不等价，外层 `Tooltip(message:)` 包裹常被误判为"已有名字"。

### 7.5 classic 键盘焦点环 `LmFocusRing`

- **标准命名**：classic 键盘焦点环（`LmFocusRing`）
- **定义**：classic 结构四类按钮（filled / elevated / text / outlined）的**键盘焦点**指示单源，位于 `lib/core/theme/system/lm_focus_ring.dart`。补的是 T06 登记项「经典侧焦点指示强度不对称」——此前 classic 只吃 Material 默认焦点 overlay。
- **先量后改（T07-4 实测）**：逐像素测「聚焦态 vs 未聚焦态**同一像素**」的对比度变化（正确口径 = 有/无焦点指示的亮度差，**不是**指示对背景的对比度）。修复前四组合 × 四类按钮共 16 组，峰值变化仅 **1.14–1.39:1**，远低于 WCAG 2.2 SC 2.4.11（焦点外观）的 **3:1** 门槛——键盘用户实际看不出焦点落点。T06 观察的「均Δ≈20」正是这一低对比度的低分辨率代理。
- **环色按控件类型分化**（单色无法同时达标）：
  | 控件 | 环像素原本是 | 环色 | 环宽 | 四组合实测变化 |
  |---|---|---|---|---|
  | filled / elevated（填充 = `primary`） | `primary` | `onPrimary` | 2px（内绘） | 8.09–16.8:1 |
  | text（透明底） | 页面底 | `ink` | 2px（内绘） | ≥12:1 |
  | outlined（既有 1.5px 描边） | 描边 + 页面底 | `ink` | **4px**（见下） | ≥12:1 |
  - **为什么 outlined 要 4px**：其默认描边占住最外 1.5px，焦点环若只有 2px，则「**新增变化**且达 3:1 的像素带」仅 2−1.5 = 0.5px 厚，不满足 SC 2.4.11「指示区域至少 2px 厚」——取 4px 使新增变化带 = 4−1.5 = **2.5px ≥ 2px**。
  - **为什么必须分化环色**：浅色主题下 `bg` 亮度 0.896、`primary` 亮度 0.076，单个颜色要同时对二者 3:1 需亮度既 ≥0.329 又 ≤0.265，**区间为空**。
- **只在键盘焦点态生效（构造保证，非自律）**：全部消费点走 `WidgetState.focused`；Material `ButtonStyleButton` **只在 `FocusHighlightMode.traditional`（键盘 / 焦点遍历）下**才上报 `focused`——指针交互拿到 `hovered` / `pressed`。故默认观感（含 golden 基线）**零变化**，落实派发红线「不许把 classic 的默认观感改掉」。
- **与玻璃侧关系**：`LmFocusRing.width`（2px）与玻璃工厂 `GlassMaterials.focusRingWidth` **同值**——两结构焦点环粗细必须一致，否则同一键盘用户在 classic / glass 间切换会有「一会儿粗一会儿细」的观感。
- **代码位置**：`lib/core/theme/system/lm_focus_ring.dart`；消费 8 处（`classic_structure.dart` 的 `_light`/`_dark` × filled/elevated/text/outlined）；报告 + 守卫 `test/core/theme/t07_focus_contrast_report_test.dart`。
- **实测报告**：修复后环带变化 **6.08–16.40:1**、峰值 **7.90–18.11:1**，16 组全过；报告落 `test_screenshots/night-2026-09-21/t07_focus_contrast_report.md`（gitignore）。
- **曾用名**：无
- **易混淆点**：①焦点环（`side`，像素变化 ≥40 的环带）≠ Material `focusColor` 12% overlay（覆盖整个按钮面，变化仅 ~1.2:1）——测对比度必须把环带与 overlay 分离，否则被稀释；②「键盘焦点」是 `FocusHighlightMode.traditional` 下的 `focused`，不是「获焦」的泛称。

### 7.6 按钮度量单源 `LmButtonMetrics` 与扁平口径

- **标准命名**：按钮度量单源（`LmButtonMetrics`）；其扁平口径（`flatElevation` / `flatElevationProperty`）
- **定义**：四类按钮（filled / elevated / outlined / text）的**共享度量**单源，位于 `lib/core/theme/system/lm_button_metrics.dart`。Classic 与 Glass 两结构只允许在「形状」（rMd 圆角 vs stadium）与「配色」上分化；触控目标、内边距、标签字重、**elevation 口径**全外观统一，禁止两个结构各自复制一份（Q4 度量统一 + T10-3 扁平口径）。
- **代码位置**：`lib/core/theme/system/lm_button_metrics.dart`；消费 `structures/classic/classic_structure.dart`（**单一骨架 `_theme`** × 四类 buttonTheme，含 2 处 `elevatedButtonTheme` 的 `copyWith`；T11 前该文件是 `_light`/`_dark` 两份复制体）、`structures/glass/glass_structure.dart`（`filledButtonTheme` / `elevatedButtonTheme`）；守卫 `test/core/theme/t10_flat_button_guard_test.dart`。
- **度量槽**：`minInteractiveHeight` **44**（WCAG 2.5.5 红线）/ `minimumSize` `Size(0, 44)` / `solidPadding`（`sLg`×`sMd`）/ `textPadding`（`sLg`×`sSm`）/ `label(base)` = bodySm + w500。
- **扁平口径（T10-3 拍板）**：**四类按钮全态 elevation = 0**（静息 / hover / pressed / focused / disabled）。
  - M3 默认给 `FilledButton` 的 hover 抬 1、给 `ElevatedButton` 静止就抬 1（hover 3），阴影色一律取 `colorScheme.shadow`（纯黑）。Classic 语言刻意扁平：实测 classic 夜间 `FilledButton` 圆角外侧像素从页面底 `244,245,247` 变 `0,0,0`（**Δ247** 凭空黑阴影），而同结构 `ElevatedButton` 仅 Δ15 —— 同结构内两类按钮 hover 观感割裂（T08 P2-4）。
  - 全态钉 0 后 hover 反馈回到**面色**（Material 状态层，实测 Δ15–20，仍可感知）——钉 0 不得让 hover 反馈消失。
  - **两个常量，别混用**：`flatElevation`（普通 `double` 0）用于 `Filled/Outlined/TextButton.styleFrom(elevation:)`（`allOrNull` 直接口径）；`flatElevationProperty`（`WidgetStatePropertyAll<double>(0)`）用于 `ElevatedButton.styleFrom` —— 后者的 `elevation` 参数是**基数**，把 hover 算成 `e + 2`、pressed 算成 `e + 6`，故必须用 `copyWith(elevation: flatElevationProperty)` 覆盖，否则 `elevation: 0` 实际得 hover=2 / pressed=6（T10-3 被逐态 resolve 守卫抓住的坑）。
  - **例外（留痕，未一刀切）**：`FloatingActionButton` 仍保留 elevation —— 浮起是 FAB 的成立条件（见 `classic_structure.dart` 的 `floatingActionButtonTheme` 注释）。
  - **玻璃结构牵连**：`glass_structure.dart` 的 `filledButtonTheme` 早已有 `flatElevation`；`elevatedButtonTheme` 于 T10-3 补 `copyWith(elevation: flatElevationProperty)` 对齐同一口径。
- **曾用名**：无
- **易混淆点**：①`flatElevation`（plain double）与 `flatElevationProperty`（`WidgetStateProperty`）**不是等价写法**，前者喂给 `ElevatedButton.styleFrom` 会被当基数放大；②「扁平口径」只钉 elevation，hover 的可感知能力由**面色台阶**承担（玻璃侧走 §5.2 的 B 轴状态台阶，classic 侧走 Material 状态层）——把 elevation 与 hover 反馈当成同一件事会误判「钉 0 = 取消反馈」。

### 7.7 桌面键盘交互层 `LmShortcuts` 与焦点遍历声明

- **标准命名**：键盘交互层（`LmShortcuts`）；其注册项（shortcut）、作用域（scope）、主修饰键（primary modifier）、消费包装件（`LmShortcutHost`）；焦点遍历声明（`LmFocusTraversal` / `LmFocusOrder` / `LmFocusRegion`）
- **定义**：把「有哪些键位、按键干什么、在哪个作用域生效」收成一份**可枚举**的表，页面只通过包装件消费，不再裸写 `CallbackShortcuts`。位于 `lib/core/theme/system/lm_shortcuts.dart` 与 `lm_focus_order.dart`（同属系统层，与视觉令牌并列的**交互单源**）。
- **代码位置**：`lib/core/theme/system/lm_shortcuts.dart`、`lib/core/theme/system/lm_focus_order.dart`；消费点 `main_layout.dart`（app）、`chat_mode_page.dart` + `intermediate_chat_page.dart`（session）、`global_search_dialog.dart` + `lm_overlays.dart`（overlay）、`glass_factories.dart`（control）；守卫 `t11_shortcuts_guard_test.dart` + `t11_keyboard_reachability_test.dart`。
- **作用域（`LmShortcutScope`）**：`app`（桌面壳，与会话无关的导航）/ `session`（会话页页体，随页面进出生效）/ `overlay`（浮层，只覆盖其下方作用域）/ `control`（单一可聚焦控件自身的激活键）。**越靠内层在运行时优先级越高**——键事件从主焦点沿焦点链向上冒泡，先命中者消费。
- **主修饰键（`primary`）**：`LmKeyCombo(primary: true)` = Windows/Linux 的 `control` ∨ macOS 的 `meta`，在注册表里**只写一遍**。Flutter 的 `SingleActivator` **不做平台映射**（`control: true` 在 macOS 上同样要求物理 Control 键），所以历史形态是每个键位在调用点手写「control 一支 + meta 一支」两遍——这是本层存在的主要动机。
- **消费包装件（`LmShortcutHost`）**：以 `Focus.onKeyEvent` 自行裁定，键事件匹配复用 `SingleActivator.accepts`（含 `includeRepeats` 与平台修饰键口径），**绑定里没有的键返回 `KeyEventResult.ignored` 继续上浮**。
- **焦点遍历声明**：`LmFocusTraversal` 装 `OrderedTraversalPolicy`，`LmFocusOrder(region:)` 用 `NumericFocusOrder` 给区域排序，`LmFocusRegion` = 侧栏 → 会话区 → 内容页。只有装了 `OrderedTraversalPolicy` 的分组，其子树里的 `FocusTraversalOrder` 才真正接管 Tab 顺序。
- **曾用名**：无（T11 新建）
- **易混淆点**：
  - **不能用 `Shortcuts` + `Actions` 实现包装件**。`Actions.maybeFind` 按 Intent 的**运行时类型**在最近祖先里命中，且 `_castAction` **不看 `isEnabled`**、命中即止；注册表共用一个 Intent 类型时，**内层 host 会替外层 host 接收全部 intent**，`handlers[id]` 取不到就静默 no-op 并返回 `handled`，外层再也收不到。实测后果：会话页一打开壳层的 `Ctrl/Cmd+N` 全哑；全局搜索浮层让统一浮层入口的 Esc 失效（对话框关不掉）。守卫「嵌套不吞键」两条用例锁死。
  - **不是所有键盘交互都进这张表**：文本编辑与焦点局部键（聊天输入框的 Enter/Shift+Enter、会话内搜索框的 Enter/Esc、滑杆的方向键）刻意留在组件内——它们是输入框/滑杆**自身的编辑语义**，且发送键用户可配置。
  - **焦点遍历 ≠ 快捷键**：前者决定 Tab 走哪里（可达性），后者决定组合键触发什么（效率），两者都在系统层，但互不替代。
