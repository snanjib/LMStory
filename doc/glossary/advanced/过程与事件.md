# 导演模式 · 过程与事件术语字典

> **用途**：统一导演模式过程展示（剧场语言）与事件日志相关概念的命名与定义。
>
> **范围**：L1/L2 过程分层、舞台动词、durable 事件日志、重启恢复等。运行机制见 [运行机制](运行机制.md)，协作控制见 [人机协作](人机协作.md)。
>
> **状态**：初版（2026-08-19 建立）。
>
> **维护原则**：记录曾用名、同步更新；代码与 Schema 优先。

## 一、过程分层概念（剧场语言）

| 术语 | 英文/代码名 | 定义 | 备注 |
|---|---|---|---|
| L1 台前 / L1 过程行 | director_process_row | 用户默认只看的一行式过程汇总（「正在翻阅前情… · 第 3 步」/「幕后 12 步 · 翻阅前情、查证设定 · 36s」） | 可「展开幕后过程」进入 L2 |
| L2 幕后 / 步骤卡 | director_tool_card | 逐步骤的审计展开层：舞台动词 + 工具名（等宽字体只出现在此层）+ 时长；失败步骤卡可一键复制 | 默认折叠 |
| 舞台动词 | advanced.stage.* | 工具调用的人话动词映射体系（体验重构 §4.1） | 见下表 |
| 心跳行 | advanced.heartbeat | 发送后首字前的等待提示（「导演正在构思…」） | 体验重构 §4.3.2 |
| 缓存命中提示 | advanced.workProcess.cache | 「缓存命中：N tokens（输入约 1 折）」 | 让用户感知长前缀的成本优势 |
| 会话成本 | advanced.workProcess.sessionCost | 「本会话累计 · N 轮 · ~M tokens」 | 让用户感知长会话的累计消耗 |

## 二、事件与恢复概念

| 术语 | 英文/代码名 | 定义 | 备注 |
|---|---|---|---|
| 事件日志 | agent_events 表（schema v38 引入） | 导演执行全过程的 append-only durable 事件记录，是导演会话的真相源 | 与轮次产物（intermediate_round_artifacts 的 agent_steps/agent_summary/story_anchor 列）并存 |
| 事件日志仓库 | AgentEventLogRepository | 事件日志的读写仓库 | advanced/data/repositories/ |
| 重启恢复 | AgentLogRecoveryService.recover | 应用重启后依据事件日志恢复导演会话状态（含崩溃前未落库的进行轮） | loadHistory 时对 advanced 会话触发 |
| durable 事件 | AgentDurableEvent | 落库的事件对象 | 经 AgentDurableEventSink 写入 |
| 轮次产物 | agent_steps / agent_summary / story_anchor | 每轮导演执行的步骤记录、总结与剧情锚持久化列 | 供 UI 回放与恢复 |
| 失败真续跑 | DirectorResumeContext | 失败后「从中断处继续」（含 E104 临时降级继续）经事件日志投影（deriveAgentSurface）重建失败时刻的模型可见消息序列续跑，不重发已完成的 LLM 请求；步数/token 预算计入前次尝试消耗，停止保留的半截正文合成进续跑上下文 | 与「整轮重试」（删同 turn 事件重放式重跑）并存；不可续跑（换模型端点/无日志仓库等）自动回退整轮重跑 |

## 三、诊断概念（开发者）

|---|---|---|---|
| Agent Loop 诊断页 | agent_loop_diagnostics_page | 开发者自检页（设置 → 诊断入口），用 echo/get_current_time/finish_demo 三个演示工具走通最小循环 | 标注「非产品 UI」 |
