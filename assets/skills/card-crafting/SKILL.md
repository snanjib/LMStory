# 角色卡写作规范

## 字段写法标准（V2 spec）

### description——卡的脊柱

两种社区公认结构，按角色气质二选一：

1. **段落结构**（叙事型角色首选）：外表 → 性格 → 背景 → 说话方式。
   每个维度一段，用「关键词：一句话事实」的密度写，不写散文。
2. **Ali:Chat 结构**（对话感强的角色）：`[Character("名字")]` 头部 +
   问答式条目（`Question: 外表如何？ Answer: ...`），模型对这种格式的
   人设遵从度在社区实测中更稳。

硬性要求：

- 写**可验证的事实**，不写评价。「他的剑术是全镇最好的」是评价；
  「他十五岁起在镖局走镖，惯用短刀反手」是事实。
- 人设不进对话素材堆砌：动机、矛盾、秘密各至少一条——没有内在矛盾
  的角色卡对话两轮就平。
- token 预算意识：description 建议控制在 300-600 token。写不下的设定
  分流到世界书（见 worldbook-crafting），不要把 description 写成百科。

### personality——行为锚点

不是性格形容词罗列，是**可执行的行为倾向**。「善良温柔」不可执行；
「会替醉酒的陌生人垫账，但事后会念叨三天」可执行。3-6 条，每条一个
具体行为模式。

### scenario——舞台，不是剧情

交代场景前提（时间/地点/关系），一段话。不写故事走向——走向是用户
与角色共同决定的。

### first_mes——开场白（质量红线）

- 必须**正在发生**：以一个具体时刻切入（动作/对话/环境），不用
  「你好，我是 XX」自我介绍式开场。
- 展示而非声明人设：性格从角色的言行细节里透出来，不复述 description。
- 角色说话声线与 mes_example 一致；{{char}}/{{user}} 宏原样书写，
  禁止展开成具体名字。
- 长度 2-5 段；结尾留一个用户可以接的口子（提问/递物/凝视均可）。

### mes_example——示例对话（声线的标尺）

- 以 `<START>` 分隔多组示例；每组展示一种典型情境下的反应。
- 必须体现**语言指纹**：口头禅、句长习惯、标点习惯、动作描写密度。
- {{user}} 的示例台词保持中性简短，把篇幅留给 {{char}}。
- 3-5 组为宜；示例对话是给模型「校准声线」的，不是给用户看的剧情。

### tags 与 creator_notes

- tags 用 SillyTavern 社区通行分类词（fantasy、male、oc 等），5-10 个。
- creator_notes 写给**卡的使用者**：这张卡的适用场景、推荐搭配、
  已知坑。不写给模型。

## 硬约束（优先级最高）

1. `{{char}}`/`{{user}}` 宏在所有字段中**原样存储**，渲染期才替换。
2. 字段内容自足：description/first_mes 不引用「见上文」——每个字段
   都可能被单独注入。
3. 中文写作时避免在关键词性质的内容上依赖整词匹配语义。

## 工作流建议

概念定位（一句话人设 + 一句话矛盾）→ description 骨架 → personality/
scenario → first_mes → mes_example → tags → 缺口盘点。每完成一个字段
用 update_draft 落盘，最后 finalize_draft。
